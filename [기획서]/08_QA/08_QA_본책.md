# OMENWARD QA 본책

## 목표

문서와 실제 Godot 수직 슬라이스의 차이를 조기에 찾고, 자동·수동 검증 상태를 명확히 남긴다.

## 배경과 의도

테스트는 반복 횟수가 아니라 승인된 규칙·보존·사용자 흐름의 증거다.

## 범위

`docs/PHASE_0_VALIDATION.md`, `docs/VERTICAL_SLICE_VALIDATION.md`, `tests/README.md`, `tests/`를 등록 부록과 실제 증거로 승계한다.

## 규칙과 제약

올바른 실행 순서: Godot editor import → 기존 headless 6종 → runtime smoke → 문서·발행 검증. import 전 headless 실패는 전역 클래스 캐시 조건을 구분해 기록한다.

## 현재 상태와 다음 작업

1920×1080·1280×720 수동 플레이 QA는 `[미검증]`이다.

## 검증과 완료 기준

각 명령의 exit code·로그, runtime smoke, 두 해상도 수동 점검과 회귀 위험을 통합검수에 연결한다.
