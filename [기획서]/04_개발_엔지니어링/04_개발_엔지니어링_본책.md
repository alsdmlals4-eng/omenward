# OMENWARD 개발·엔지니어링 본책

## 목표

Godot Scene·GDScript·Resource·데이터가 공용 병종 규칙과 단일 상태 소유를 유지하며, 검증 가능한 수직 슬라이스를 제공한다.

## 배경과 의도

공용 `UnitArchetypeProfile`과 진영 `FactionVisualProfile`을 분리해 진영별 중복 전투 데이터와 모션 계약을 만들지 않는다.

## 범위

`등록_부록/GODOT_PROJECT_STRUCTURE.md`, `APPROVED_PERFORMANCE_DATA_TEST_READINESS_POC_V1.md`, 공용 아키타입·웨이브 승인 문서를 등록 부록으로 승계한다.

## 규칙과 제약

- 이 문서 마이그레이션은 코드·Scene·데이터·저장 형식·`project.godot`을 변경하지 않는다.
- 새 GDScript는 첫 줄 한국어 역할 헤더를 사용한다.
- AutoLoad와 Scene이 같은 상태의 책임 원본을 중복 소유하지 않는다.

## 현재 상태와 다음 작업

실제 main의 구현·테스트를 재확인하고, 다음 변경은 승인된 Issue·Plan Mode에서만 정한다.

## 검증과 완료 기준

Godot editor import 후 기존 headless 6종과 runtime smoke를 순서대로 실행한다.
