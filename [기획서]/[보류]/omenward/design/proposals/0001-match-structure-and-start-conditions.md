# 제안서 0001 — 한 판 구조와 시작 조건

> 상태: **사용자 조정안 대기 / 확정 전 구현 금지**  
> 대상: 디자인 프리즈 A — 제품 범위와 한 판 구조

## 1. 목적

플레이어가 게임 시작 직후 무엇을 보고 무엇을 선택해야 하는지, 전투가 언제 본격적으로 시작되는지, 한 판이 어떤 단계로 발전하고 어떤 조건에서 끝나는지를 구현 전에 확정한다.

이 제안서는 비용·체력·공격력 같은 최종 밸런스 수치를 고정하지 않는다. 대신 Codex가 임의로 해석하면 재작업이 커지는 흐름, 상태, 입력과 종료 계약을 잠그는 것을 목표로 한다.

## 2. 추천안 요약

| 항목 | 추천안 |
|---|---|
| 기본 모드 | 싱글플레이 PvE 전용 MVP |
| 우선 플랫폼 | Windows PC, 마우스·키보드 |
| 정식 한 판 목표 | 25~35분 |
| 수직 슬라이스 목표 | 10~15분 |
| 시작 건물 | 본진 핵심 건물만 존재, 전용 건설 노드는 모두 비어 있음 |
| 시작 룰렛 | 실제 토큰 0개, 각 릴 X 토큰 3개 |
| 시작 경제 | 본진 기본 금화 수입과 기본 보급 한도 제공 |
| 시작 금화 기준 | `Tier 1 경제시설 1개 + 기본 훈련소 1개 + 룰렛 2회`가 가능한 예산 |
| 첫 웨이브 | 게임 시작 시 즉시 전조 공개, 60초 후 한 라인으로 출격 |
| 접전지 활성화 | 첫 웨이브 출격 시점에 활성화 |
| 기본 속도 | 1배속 |
| 일시정지 | 허용. 정지 중 계획·선택·명령 예약 가능 |
| 가속 | 2배속만 허용, 위험 상황에서 자동 1배속 복귀 |
| 승리·패배 | 상대 또는 플레이어 본진 핵심 건물 파괴 |
| 동시 파괴 | `상호 파괴` 별도 결과, 클리어로 처리하지 않음 |
| 장기전 방지 | 정식 목표 시간을 넘으면 결전 단계로 자연스럽게 압박 강화. 즉시 시간패는 사용하지 않음 |

## 3. 제품 범위

### 3.1 MVP 모드

- 싱글플레이 PvE만 제공한다.
- 적은 플레이어 룰렛을 복제하지 않고 기존 기획대로 건물·티어 기반 웨이브를 사용한다.
- 멀티플레이, 협동, 랭크, 영구 메타 성장은 제외한다.
- 첫 MVP는 난이도 `일반` 하나만 제공한다.

### 3.2 입력과 플랫폼

- Windows PC를 첫 실행·검증 플랫폼으로 한다.
- 마우스를 주 입력으로 사용한다.
- 키보드는 화면 이동, 일시정지, 속도, 라인 선택과 주요 패널 단축키를 보조한다.
- 게임패드와 터치 입력은 MVP에서 제외한다.

## 4. 한 판 시간 구조

### 4.1 정식 목표

- 평균 목표 시간: 25~35분
- 20분 이전 종료: 빠른 승리 또는 빌드 붕괴로 간주
- 35분 이후: 결전 단계 진입
- 45분 이상: 밸런스 실패 신호로 기록

45분에 즉시 승패를 판정하는 하드 타임아웃은 추천하지 않는다. 본진 파괴가 핵심 목표인데 시간 점수로 끝나면 플레이어의 전장 판단과 결과가 분리되기 때문이다.

### 4.2 수직 슬라이스

첫 구현 검증용 수직 슬라이스는 10~15분을 목표로 한다.

- 기본 병종 4종을 모두 완성할 필요는 없다.
- 제한된 웨이브 수와 단순한 적 건물 구성을 사용한다.
- 적 본진 파괴 또는 최종 검증 웨이브 방어로 종료할 수 있다.
- 정식 25~35분 밸런스를 수직 슬라이스 코드에 하드코딩하지 않는다.

## 5. 게임 시작 상태

### 5.1 시작 시 존재하는 것

- 플레이어 본진 핵심 건물
- 적 본진 핵심 건물
- 플레이어 후방 건설 노드 6개
- 플레이어 상·중·하 전방 건설 노드 각 3개
- 적 건물과 노드
- 비활성 상태의 중앙 접전지 3개
- 첫 웨이브 전조 UI

### 5.2 시작 시 존재하지 않는 것

- 플레이어 시장, 농장, 훈련소, 포탑
- 룰렛 실제 토큰
- 출전 유닛
- 점령 중인 접전지
- 런 전용 장비·스킬북

본진 자체는 전용 건설 노드를 사용하지 않는다.

### 5.3 본진 기본 기능

본진은 플레이어가 아무것도 짓지 않아도 게임이 완전히 멈추지 않도록 최소 기능을 제공한다.

- 낮은 기본 금화 수입
- 소수 기본 유닛을 출전시킬 수 있는 기본 보급 한도
- 가까이 접근한 적을 지연시키는 약한 최후 방어

본진 방어만으로 정상 웨이브를 계속 막을 수는 없어야 한다. 목적은 초반 실수 한 번으로 즉시 패배하는 것을 방지하는 것이다.

## 6. 시작 자원 계약

정확한 수치는 데이터에서 조정하되 시작 예산의 의미를 다음처럼 고정한다.

```text
시작 금화 목표
= Tier 1 경제시설 1개
+ 기본 병종 훈련소 1개
+ 기본 룰렛 2회
```

플레이어는 다음과 같은 선택을 할 수 있어야 한다.

- 시장 + 훈련소 + 룰렛: 경제와 병력의 균형
- 농장 + 훈련소 + 룰렛: 빠른 병력 확장 준비
- 훈련소 2개 + 적은 룰렛: 병종 특화와 높은 초반 압박
- 전방 포탑 + 훈련소: 안전한 첫 방어

시작 예산으로 주요 시설 3개와 다수 회전을 동시에 확보할 수는 없어야 한다.

기본 보급 한도는 Tier 1 병사 약 4~6기를 운용할 수 있는 수준을 목표로 한다. 농장이 없어도 첫 웨이브 대응은 가능하지만 중반 확장은 막히도록 한다.

## 7. 시작 룰렛 상태

- 실제 토큰은 0개로 시작한다.
- 각 릴은 X 토큰 3개로 채워진다.
- 실제 토큰이 없는 상태에서도 룰렛 버튼은 보이지만, 회전 시 보상이 없다는 사실을 명확히 표시한다.
- 기본 권장안은 실제 토큰이 0개일 때 유료 회전을 차단하는 것이다.
- 첫 건물이 완공된 순간 토큰 장부와 확률 미리보기가 갱신된다.

`실제 토큰 0개인데 금화를 소비해 X만 뽑는 경험`은 실수 유도 외에 전략 가치가 없으므로 차단을 추천한다.

## 8. 첫 60초 흐름

### T=0

- 게임 시작
- 첫 적 웨이브의 라인·병종·정확한 수량 공개
- 중앙 접전지는 비활성
- 모든 플레이어 건설 노드는 사용 가능
- 전투 시간, 건설시간, 생산시간과 기본 수입이 진행됨

### T=0~30

- 플레이어가 첫 건물을 선택
- 건설 전 룰렛 확률 변화를 확인
- 첫 훈련소 또는 시장·농장 건설
- 건물이 완공되면 룰렛과 자동 생산 사용 가능

### T=30

- 일반 웨이브의 기본 전조 길이인 30초 구간 진입
- 라인 경고와 적 집결 표현 강화

### T=45

- 첫 웨이브 위험 안내 강화
- 대응 병종, 현재 대기 병력과 식량 부족 여부 표시

### T=55

- 자동 1배속 복귀
- 출격 라인 강조와 카운트다운

### T=60

- 첫 웨이브 출격
- 중앙 접전지 3개 활성화
- 첫 웨이브는 한 라인만 공격
- 기본 근접 병종 중심이며 특수 효과·후방 침투·영웅은 없음

첫 웨이브만 게임 시작부터 60초 전체 구성을 공개하는 튜토리얼 예외로 둔다. 이후 일반 웨이브는 기존 기획대로 T-30부터 공개한다.

## 9. 진행 단계

시간만으로 단계를 나누기보다 웨이브 번호와 적 건물 티어를 함께 사용한다.

### 개전 단계

- 대략 웨이브 1~2
- 한 라인 중심 공격
- Tier 1 유닛과 건물
- 플레이어가 건설→토큰→룰렛→배치를 학습

### 중반 단계

- 대략 웨이브 3~6
- 두 개 이상의 라인 동시 압박
- 접전지 경제가 본격적으로 작동
- Tier 2 건물과 병종 상성 요구
- 전방 시설 파괴가 웨이브에 영향을 주기 시작

### 결전 단계

- 대략 웨이브 7 이후 또는 35분 이후
- 세 라인 압박과 특수 웨이브
- Tier 3 건물
- 적 본진을 공격하지 않고 방어만 하면 점차 버티기 어려워짐

정확한 웨이브 번호와 시간은 데이터로 조정한다. 단계 진입 시점은 UI에 명시적으로 알린다.

## 10. 일시정지와 속도

### 10.1 일시정지

- `Space`로 일시정지·재개
- 일시정지 중 카메라 이동, 정보 확인, 건물·유닛 선택 가능
- 건설, 업그레이드, 출전, 룰렛 기준 줄 선택 같은 명령은 예약 가능
- 예약 명령의 자원은 즉시 차감하거나 명확하게 예약 표시
- 게임 시간, 건설, 생산, 이동, 공격, 점령과 웨이브 타이머는 정지

전술적 판단을 위한 일시정지는 싱글플레이의 기본 접근성 기능으로 본다.

### 10.2 가속

- 1배속과 2배속만 제공
- 3배속 이상은 MVP에서 제외
- 다음 상황에서는 자동으로 1배속 복귀
  - 적 웨이브 출격 10초 전
  - 플레이어 시설이 공격받기 시작함
  - 중앙 접전지가 새로 접전 상태가 됨
  - 본진이 피해를 받음
  - 대기칸 가득 참 또는 식량 초과로 출전이 막힘

자동 복귀가 발생하면 화면과 짧은 효과음으로 이유를 표시한다.

### 10.3 패널 동작

- 룰렛, 건설, 업그레이드와 웨이브 정보는 전장을 덮는 전체화면 모달이 아니라 패널로 표시
- 패널을 연다고 자동으로 시간이 멈추지 않음
- 플레이어가 원하면 직접 일시정지
- 확인 대화상자와 결과 화면만 자동 정지

## 11. 승리·패배와 종료 상태

### 11.1 승리

적 본진 핵심 건물의 체력이 0이 되면 승리한다.

- 해당 시뮬레이션 틱의 피해 처리를 마친 뒤 전투 정지
- 추가 투사체·회복·점령 처리는 중단
- 승리 연출 후 결과 화면

### 11.2 패배

플레이어 본진 핵심 건물의 체력이 0이 되면 패배한다.

### 11.3 동시 파괴

같은 고정 시뮬레이션 틱에 양측 본진이 모두 파괴되면 `상호 파괴`로 판정한다.

- 승리로 처리하지 않음
- 패배와 구분되는 결과 문구 사용
- 재도전 가능

### 11.4 포기

- 일시정지 메뉴에서 `전투 포기`
- 확인을 한 번 요구
- 포기는 패배 결과로 기록하되 플레이 밸런스 통계에서는 별도 구분

### 11.5 장기전 처리

시간이 지났다는 이유로 즉시 패배시키지 않는다.

35분 이후 결전 단계에서 다음 중 최소한의 압박만 사용한다.

- 적 웨이브 간격이 점진적으로 짧아짐
- 적 특수 웨이브 출현 빈도가 증가
- 양측 본진을 향한 전선 압박이 강해짐

본진 체력을 자동으로 깎거나 점수 비교로 승패를 결정하는 규칙은 초기 MVP에서 제외한다.

## 12. 결과 화면

항상 제공:

- 승리 / 패배 / 상호 파괴 / 포기
- 플레이 시간
- 도달 웨이브
- 파괴한 적 건물과 잃은 아군 건물
- 가장 많이 사용한 토큰과 주력 병종
- 라인별 점령 시간
- 가장 큰 패배 원인 또는 승리 기여 요인 2~3개

버튼:

- 같은 시나리오 재도전
- 새 시드로 재도전
- 메인 메뉴

같은 시나리오 재도전은 적 웨이브 일정과 맵 구성을 유지한다. 룰렛 난수까지 같은 시드로 재현하는 기능은 디버그 옵션에서 제공하고 일반 플레이에서는 새 룰렛 결과를 기본으로 한다.

## 13. 튜토리얼 첫 판 예외

첫 튜토리얼에서는 다음을 순차적으로 개방한다.

1. 후방 시장 또는 훈련소 건설
2. 건설 전 룰렛 확률 변화 확인
3. 룰렛 회전
4. 대기 유닛을 첫 웨이브 라인에 배치
5. 첫 웨이브 방어
6. 중앙 접전지 활성화와 점령
7. 두 번째 라인과 전방 노드 개방

정식 일반 게임에서는 모든 기본 노드와 4개 기본 훈련소를 시작부터 사용할 수 있다.

## 14. 경계 상황 계약

| 상황 | 추천 처리 |
|---|---|
| 시작 후 아무 건물도 짓지 않음 | 첫 웨이브 전조는 계속 진행. 본진 약한 방어만 존재하며 패배 가능 |
| 실제 룰렛 토큰 0개 | 회전 차단, 이유와 첫 건물 추천 표시 |
| 첫 웨이브 전에 2배속 사용 | 허용하되 T-10에 자동 1배속 |
| 일시정지 중 명령 예약 후 자원 부족 | 예약 시점에 자원 검증·차감하여 재개 시 실패하지 않게 함 |
| 승패 판정 직전에 일시정지 | 승패 조건이 충족된 틱이면 결과 판정 우선 |
| 결과 직전 진행 중인 건설·생산 | 결과 통계에는 현재 진행률을 포함하지 않고 완공·생산 완료분만 집계 |
| 45분 이상 장기전 | 게임은 지속하되 장기전 로그를 남겨 밸런스 실패로 분석 |

## 15. 확정할 선택 항목

사용자 조정이 필요한 핵심 선택은 다음 5개다.

1. **정식 한 판 목표 시간**
   - 추천: 25~35분
   - 대안: 15~25분의 더 빠른 런

2. **시작 건물**
   - 추천: 본진만 존재하고 모든 전용 노드는 빈 상태
   - 대안: 농장 1개를 기본 제공

3. **첫 웨이브 시점**
   - 추천: 시작부터 정확히 공개, T=60 출격
   - 대안: T=45 출격

4. **일시정지 명령 예약**
   - 추천: 정보 확인과 명령 예약 모두 허용
   - 대안: 정보 확인만 허용하고 명령은 재개 후 실행

5. **장기전 종료 방식**
   - 추천: 하드 타임아웃 없이 35분 이후 압박 강화
   - 대안: 45분에 본진 체력·전장 우세로 판정

## 16. 승인 게이트

현재 상태는 `사용자 조정안 대기`다.

사용자 조정 후 확정된 항목만 `GAME_DESIGN.md`, `DECISIONS_PENDING.md`, `DESIGN_FREEZE_CHECKLIST.md`에 반영한다. 이 문서가 확정돼도 Godot 구현은 별도 Codex Plan Mode 제안서 승인 후 시작한다.
