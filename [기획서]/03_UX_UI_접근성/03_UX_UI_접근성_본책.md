# OMENWARD UX·UI·접근성 본책

## 목표

플레이어가 세 라인의 위협, 성문·거점·접전지, 다음 웨이브와 룰렛 상태를 같은 전략 화면에서 빠르게 이해한다.

## 배경과 의도

벨루의 단일 안내와 첫 10분 흐름은 선택의 이유를 보강하되 전장 시야를 침범하지 않는다.

## 범위

이 폴더의 UI·벨루·첫 10분 승인 부록과 `../06_아트/증거/VISUAL_REFERENCE_INDEX.md`를 승계한다.

## 규칙과 제약

- 기본 전략 줌에서 전장 전체를 보고 미니맵은 사용하지 않는다.
- 1920×1080과 1280×720에서 정보 계층을 수동 확인한다.
- 이미지의 임시 수치·UI 배치를 확정 규칙으로 복사하지 않는다.
- 전장은 상단·중단·하단의 독립 3레인이다. 각 레인은 루멘 성문 → 루멘 전초기지(전방 2·후방 1 노드) → 중앙 교전권 → 베일 전초기지 → 베일 성문 순서이며, 레인 간 연결선·교차로는 표시하지 않는다.
- 고정 하단 도크의 순서는 `룰렛 / 전술 스킬 / 상점 / 벨루 안내`다. 건물은 하단의 즉시 구매 버튼으로 두지 않는다.
- 건설 흐름은 전장 노드 선택 → 해당 노드의 소유·잠금·비어 있음 상태 확인 → 설치 가능한 건물 목록 표시 → 건물 선택 → 설치 결과의 순서다. 선택되지 않은 노드에는 건물 버튼을 노출하지 않는다.
- 룰렛은 20 Gold를 소비해 3×3 보드를 확정한다. 기본 판정줄은 가운데 가로줄이며, 세 칸이 같은 비-X 심벌일 때만 보상한다. 적중한 심벌로 가로 3·세로 3·대각 2, 총 8줄을 계산해 1/2/3~7/8줄을 일반/엘리트/영웅/전설로 정한다.
- 가운데 가로줄이 실패하면 다른 위치의 완성 줄은 보상하지 않는다. 보관함이 비기 전에는 재회전하지 않으며, 라인 배치는 가장 앞의 보상 한 장만 소비한다.

## 현재 상태와 다음 작업

Issue #44 Slice는 친선 전초기지의 노드 선택·건설 패널과 중앙 판정줄 기반 룰렛 피드백을 구현한다. 전술 스킬·상점의 실제 전투 서비스는 데이터·규칙 Slice가 선행되어야 하며, 그 전까지는 비어 있는 상태와 해금 조건만 플레이어에게 명확히 표시한다. UI는 존재하지 않는 효과를 실행한 것처럼 표시하지 않는다.

## 검증과 완료 기준

두 해상도 수동 플레이 QA, 텍스트·색상·입력 피드백 확인, 승인 이미지 해석 대조가 필요하다.
