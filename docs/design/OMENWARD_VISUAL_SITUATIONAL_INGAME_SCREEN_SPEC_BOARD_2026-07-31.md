# 2. 프로젝트 비주얼 기준 보드

## 2.1 비주얼 핵심 문장

> **클린 전술 픽셀** 위에 **2.5~3등신 미니어처 치비 유닛**, 절제된 금속 HUD와 제한적 조명을 사용한다. 귀엽게 읽히되 판단 정보가 장식보다 먼저 보여야 한다.

## 2.2 형태 언어

```text
아군 루메른·실베른
수직선 / 아치 / 방패 / 종 / 천 배너
남색 / 상아색 / 회청색 / 제한된 따뜻한 금속
정돈된 대칭과 훈련된 배열

적군 베일런·베일종
비대칭 균열 / 갑각 / 가시 / 공허 구멍
흑자색 / 암적색 / 갑각 회색 / 제한된 균열 발광
기능을 생물 구조로 번역한 불안정한 실루엣
```

## 2.4 정보 3계층

```text
L0 즉시 위험
- 본진 위험
- 현재 치명 행동
- 다음 공세 시간·라인

L1 현재 선택
- 보관 병력
- 건설·수리·룰렛·배치 가능 여부
- 비용과 조건 부족

L2 분석·복기
- TokenSource 출처
- 기대 변화
- 전투 원인 로그
```

L0가 가장 크고 강해야 하며, L2가 전장을 가리면 실패다.

## 2.5 금지 시각 요소

- 모바일 양산형 성채 게임의 과도한 금장·붉은 알림 점.
- 모든 유닛과 버튼의 상시 발광.
- 일반 등급부터 영웅처럼 보이는 장식량.
- 실제 전장보다 큰 미니맵·도감·로그 패널.
- 세 라인을 한눈에 볼 수 없게 만드는 과도한 확대.
- 아군과 적군을 색상만 바꿔 구분.
- 일반 판타지 인벤토리·장비창의 임의 추가.
- 문서 수치와 설명을 작은 글씨로 전부 노출하는 기술 대시보드.

## 2.6 확정·미정·제안

### 확정

- 클린 전술 픽셀과 미니어처 치비 비율.
- 아군·적군 형태 언어.
- 960×540 내부 기준, 1920×1080 출력, 1280×720 축소 검증.
- 세 전선 전체 표시, 미니맵 없음.
- 현재 위험과 다음 공세 우선.
- 실제 전장 삽입형 공용 10병종 Visual Set.

### 확인 필요

- 최종 UI 팔레트 색상값.
- 한글 제품 폰트와 숫자 폰트.
- 벨루 최종 초상화·마스코트 표현.
- 메인 화면 로고와 배경 아트.
- 실제 스프라이트·건물·전장 타일 세트.

### 신규 제안

- 메인 화면에서 세 전선과 세 원형 릴을 상징적으로 연결하는 배경.
- 준비 화면의 `공세 브리핑 → 릴 설계 → 보관·배치` 좌우 흐름.
- 결과 화면의 인과 사슬 카드.
- 위험 보스 화면의 `현재 위협 / 다음 위협` 2단 전조 스트립.


UI는 Threat·피해·확률·배치 가능성을 직접 계산하지 않는다.

## 6.5 예외 처리

- 저장 데이터 손상: 이어하기 비활성, 복구 가능한 프로필과 오류 원인 표시.
- 영구재화 부족: 재시도 버튼 비활성 + 부족량 표시.
- checkpoint 불일치: 재화 차감 금지, 런 종료 선택 유지.
- 긴 한국어: 1280×720에서 두 줄 제한과 툴팁 폴백.
- 게임패드: 모달 종료 후 이전 선택으로 포커스 복귀.
- 위험 전조 중 연출 감소: 위치·형태·텍스트·시간 정보 유지.

## 6.6 화면별 테스트 체크리스트

### SCREEN-01

- 저장 없음/있음/손상 상태.
- 이어하기 checkpoint 정보 정확성.
- 키보드·마우스·게임패드 포커스.

### SCREEN-02

- 현재 위협과 다음 위협 혼동 없음.
- 1280×720에서 HUD가 전장을 가리지 않음.
- 색각 폴백과 연출 감소.

### SCREEN-03

- TokenSource 변경 전후 비교.
- 가로 이동 비가역 경고.
- 골드·식량·노드 부족 원인.
- 보관·판매·배치 포커스 흐름.

### SCREEN-04

- 승리·부분 성공·패배 인과 정확성.
- 유료 재시도 비용·잔액·남은 횟수.
- 원자 거래 실패 시 차감 없음.
- 다음 Stage 또는 메인 복귀 경로.

# 7. 적대적 검토 결과

## 1차 — 화면 중심 산출물

초안 문제: 현재 구현과 기술 경계가 화면보다 길어질 위험이 있었다.

수정:

- 모든 기술 내용은 PART D로 이동.
- 각 필수 화면에 대형 와이어프레임을 먼저 배치.
- CURRENT 비교는 화면 아래 3개 묶음으로 제한.

## 2차 — 필수 화면과 시퀀스

초안 문제: 자원 관리 화면이 일반 인벤토리처럼 읽힐 가능성이 있었다.

수정:

- 화면명을 `Stage 준비·룰렛·보관 자원 관리`로 고정.
- 장비·소비 아이템·가방 슬롯 상태를 명시적으로 제외.
- TokenSource·릴·보관·건물·배치를 중심으로 재구성.

## 3차 — 근거 수준 분리

초안 문제: 최신 정본 기반 목표 화면이 구현된 화면처럼 보일 수 있었다.

수정:

- 각 SCREEN에 근거 수준과 구현 상태를 별도 표시.
- CURRENT legacy와 목표 화면을 분리.
- 실제 이미지·최종 에셋·정확 수치는 미승인으로 유지.

## 4차 — 프로젝트 고유성

초안 문제: 일반적인 전략 게임 HUD로 보일 위험이 있었다.

수정:

- 세 원형 릴, TokenSource, 비가역 가로 이동, 세 전선, 벨루를 필수 화면에 반복 연결.
- 결과 화면에 오멘워드 고유 인과 사슬을 배치.
- 전통 인벤토리·미니맵·generic 판타지 UI를 제외.

## 5차 — 판독성·가독성

초안 문제: 전투 HUD에 분석 정보를 상시 노출하면 현재 legacy 기술 대시보드가 반복될 수 있었다.

수정:

- L0/L1/L2 정보 계층을 고정.
- 현재 위험·다음 공세를 상단 스트립으로 제한.
- 상세 원인·TokenSource는 선택 확장 또는 결과 화면으로 이동.

## 6차 — 비교·재사용

초안 문제: 오멘워드 고유 내용과 Base 공통 템플릿이 섞일 수 있었다.

수정:

- 공통 SCREEN/SIT/근거 태그/검토 표는 Base 후보로 분리.
- 세 전선·릴·TokenSource·벨루·보스 패턴은 프로젝트 전용으로 유지.

# 9. Base 승격 후보

- 프로젝트 비주얼 기준 보드 공통 템플릿.
- 메인·핵심 플레이·자원 관리·결과 필수 화면 4종 기준.
- `CURRENT / INFERRED / PROPOSED / PLACEHOLDER` 태그 규칙.
- 목표 화면 70~80% + CURRENT 비교 20~30% 보드 구성.
- SCREEN ID·SIT ID·Image ID 연결 규칙.
- 상태 변형 검토표.
- 전체 화면 전환도 표기 규칙.
- 6단계 적대적 검토루프.
- 1920×1080 작성 후 1280×720 축소 검증 규칙.
- 이미지 승인이 구현·제품 에셋 승인을 의미하지 않는 상태 경계.
