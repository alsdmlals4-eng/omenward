명시적 대체 대상:

- 엘리트·영웅·전설을 계열별 고정 상위 등급 템플릿으로 교체하는 규칙.
- 아군을 주기적 3기 묶음으로 출격시키는 규칙.

유지 대상:

- 같은 기본 병종 계열은 Tier와 세부 병종이 달라도 같은 계열 심벌을 공유한다.
- 동일 심벌 당첨 시 `SpinSnapshot` 전체 릴의 동일 심벌 출처 풀에서 세부 출처를 결정한다.
- 출처 건물 완성 Tier가 출처 가중치와 패시브 성장 단계를 결정한다.

## 2. 제품 기준선

제품 약속:

> 예고된 세 전선의 공세를 읽고, 제한된 건물로 세 원형 릴의 토큰 구조를 설계·영구 편집한 뒤, 당첨 병력을 어느 전선에 커밋할지 결정해 전황을 뒤집는 실시간 전략 오토배틀 게임.

시장 구분:

> 3×3 슬롯으로 병력을 뽑는 게임이 아니라, 건물과 가로 이동으로 미래 룰렛 자체를 다시 쓰는 3전선 지휘 게임.

핵심 문구:

> 건물로 룰렛을 만들고, 룰렛으로 전선을 지휘한다.

기존 V2 계약:

1. 가로 이동은 노출 인덱스의 `TokenInstance`만 순환 교환하며 릴 길이와 cursor를 유지한다.
2. 새 토큰은 가장 낮은 안정 인덱스의 `NORMAL_X`를 교체하고, 없을 때만 append한다.
3. 정지 시 릴·cursor·보드·비용·출처 후보·reward payload를 immutable `SpinSnapshot`으로 동결한다.
4. 세부 출처는 snapshot 전체 릴의 동일 심벌 출처 풀에서 결정한다.
5. 럭키 확률은 숨김 `15/25/35/45/55/100%`다.
6. 전술 아이템 룰렛 심벌은 보류하며 `TokenSource` 건물만 토큰을 공급한다.
7. 코어 PoC와 첫 수직 슬라이스는 mid-run save를 지원하지 않는다.

전체 프로젝트 최적화 범위에는 코어 재미, 시스템·UX·경제, PoC·수직 슬라이스, 스코프 절감, 문서·스킬·GitHub 운영이 포함된다.

## 3. 룰렛·이동·결과 거래

- **GM-01:** 핵심 재미는 미래 릴 구조를 설계하는 것이다.
- **GM-02:** 좋은 설계는 약 3회 회전 안에 이점이 관찰되어야 한다.
- **GM-03:** 3회 평가 창당 의미 있는 이동 약 1회를 기준 감각으로 삼되 하드 상한은 두지 않는다. 이동원은 럭키 무료 이동, 상점 보관형 이동 아이템, 확정 무보상 누적 2회 보상이다.
- **GM-04:** `BlankMoveCounter`는 럭키 실패 카운터와 분리한다. 확정 무보상마다 +1, 성공은 유지, 2에서 이동 아이템 지급 후 0. 성공·무보상·보상·출처는 `[확정]`에서만 최종화한다.

거래 경계:

```text
정지 → immutable SpinSnapshot → 이동·preview → [확정]
→ 성공/무보상/보상/카운터 원자적 1회 처리
```

- **GM-05:** 미확정 `SpinSession`은 닫고 재개할 수 있다. snapshot과 이동 상태를 보존하고 새 회전·보상·카운터 처리를 금지한다. 위험 전투 시간은 계속 흐른다.
- **GM-06:** 미확정 중 전장 관찰, 상점, 이동 아이템 구매·사용은 허용한다. 건설·업그레이드·철거·새 회전은 금지한다.
- **GM-07:** 세로와 가로 이동은 같은 공용 이동 아이템 1개를 소비한다.
- **GM-08:** 보관형 이동 아이템 상한 3. 럭키 무료 이동은 별도이며 현재 세션에서만 유효하고 확정 시 소멸한다.
- **GM-09:** 상한에서는 상점 구매 비활성·무과금. 무보상 보상은 `PendingMoveReward` 1개로 보류한다. pending 중 blank counter는 정지한다. 이후 회전 확정 뒤 공간이 생기면 지급하며 촉발 회전에서는 사용하지 못한다.
- **GM-10:** 럭키 무료 이동을 보관형 이동 아이템보다 먼저 소비한다.
- **GM-11:** `SpinSession`당 이동 횟수 하드 상한은 없다. 사용→공간 생성→구매→사용 반복을 허용한다.
- **GM-12:** 같은 세션의 반복 이동 아이템 구매 가격은 상승하고 확정 후 초기화한다.
- **GM-13:** n번째 가격 `nP`, k개 총비용 `P*k(k+1)/2`.
- **GM-14:** `P`는 가장 저렴한 의미 있는 건설 또는 핵심 업그레이드 비용의 50%를 기준으로 하며 40~60%를 검증한다.
- **GM-15:** 유닛 결과는 `[확정] → PendingReward → 보관/판매/라인 배치`로 원자 처리하며 미처리 중 새 회전을 차단한다.
- **GM-16:** 금화 결과는 확정 거래에서 즉시 글로벌 금화 장부에 적립하며 pending을 만들지 않는다.
- **GM-17:** 과거의 다음 3기 배치 묶음 규칙은 폐기한다.

## 4. 라인 명령·점령·전방 건설

- **GM-18:** 유닛은 배치 즉시 출격한다. 주기적 아군 배치 묶음은 없다.
- **GM-19:** 대기는 라인별이며 작성된 대기 앵커를 선택한다. 유닛은 즉시 이동 후 대기한다.
- **GM-20:** 대기 유닛은 방어·자동전투·제한 추격 후 복귀한다.
- **GM-21:** 대기 지점은 임의 좌표가 아니라 작성된 전술 앵커다.
- **GM-22:** 도달 가능한 앵커는 소유권과 무관하게 선택할 수 있다. 적대 앵커는 전투하며 접근하고 생존자가 대기한다. 접근 불가한 깊은 적 앵커는 선택할 수 없다.
- **GM-23:** 라인당 활성 대기 앵커는 1개다. 변경 시 이동·대기 유닛 전체를 재지정하고 교전 중 유닛은 현재 전투 후 최신 명령을 수행한다.
- **GM-24:** 공격은 적 본진까지 지속 전진하며 능력치 보너스가 없다. 공격과 대기는 상호 배타적이고 최신 명령이 승리한다.
- **GM-25:** 현재·이동 중·미래 배치 유닛은 최신 라인 명령을 상속한다.
- **GM-26:** 명령 상태는 즉시 갱신한다. 비교전 유닛은 즉시, 교전 유닛은 현재 전투 후 최신 명령만 수행한다. 중간 명령은 폐기한다.
- **GM-27:** 대기 추격은 앵커별 `HoldRadius` 안으로 제한하며 밖에서는 복귀한다.
- **GM-28:** 점령은 8초 비교전. 적 진입 시 일시정지, 적 제거 후 점령측 유닛이 남으면 재개, 점령측 0명이면 0으로 초기화, 완료 즉시 소유권 변경.
- **GM-29:** 주둔이 없어도 소유권은 유지되며 상대가 점령 완료해야 변경된다.
- **GM-30:** 중점·접전지 점령은 전술 앵커와 연결된 전방 건설 권리를 준다. 전방 `TokenSource`는 미래 릴에 반영한다. 치유·무료 병력·전방 spawn 보너스는 코어에서 제외한다.

## 5. 일반 건물·TokenSource 차단과 교체

- **GM-31:** 적 점령 시 일반 건물은 파괴 대신 `BLOCKED`. 효과와 live 토큰을 비활성화하되 현재 snapshot은 유지한다. 원소유자 재점령 시 무료 복구, 적 교체 완료 시 영구 삭제.
- **GM-32:** blocked TokenSource 토큰은 위치·길이·cursor를 보존한 `SOURCE_BOUND_X`로 변환한다. 가로 이동 가능하며 binding이 따라간다. 재점령 시 현재 위치에서 복원, 적 교체 완료 시 `NORMAL_X`.
- **GM-33:** `SOURCE_BOUND_X`는 새 토큰의 일반 X 교체 대상이 아니다. 최저 `NORMAL_X`를 교체하고 없을 때 append한다.
- **GM-34:** 두 X를 시각적으로 구분하고 원래 토큰·출처·앵커·복구 조건·이동 목적지를 공개한다. 판정에서는 둘 다 blank다.
- **GM-35:** 자기 TokenSource 철거·교체 완료 시 linked token을 위치 그대로 `NORMAL_X`로 바꾸고 binding을 제거한다. 활성 snapshot은 유지한다.
- **GM-36:** TokenSource 업그레이드는 토큰 ID·위치·개수·릴 길이·cursor를 유지하고 출처 Tier·세부 병종·reward payload만 완료 시 갱신한다. 활성 snapshot에는 영향 없음.
- **GM-37:** blocked 건물의 완성 레벨·업그레이드를 보존한다. 재점령 시 정확 복구, 적 교체 완료 시 영구 삭제.
- **GM-38:** 원소유자는 blocked 건물 검사만 가능하고 사용·판매·철거·업그레이드 불가. 점령자는 검사·교체만 가능.
- **GM-39:** 기존 blocked 건물은 적 교체 완료 시 삭제한다. 공사 중 기존 blocked와 source-bound X를 유지하고 신규 효과는 비활성. 완료 시 기존 삭제→binding 제거→normal X→신규 활성→신규 토큰 삽입.
- **GM-40:** 적 교체 중 원소유자 재점령 시 공사 취소·진행 폐기·건설자 50% 환불·기존 정확 복구·현재 위치 토큰 복원.
- **GM-41:** 건설·교체·업그레이드는 시간 기반이며 비용은 시작 시 지불한다. 신규 효과는 완료 후, 업그레이드 중에는 마지막 완성 레벨 유지. snapshot 불변.
- **GM-42:** 결정론적 시뮬레이션 시계 사용. 준비 기본 정지와 `[시간 진행]`; 일반 전술 일시정지는 공사 포함 정지; 위험은 정지 불가·공사 지속; 벽시계 사용 금지.
- **GM-43:** 신규 건설·업그레이드 중 적 점령 시 취소·진행 폐기·50% 환불. 신규는 제거, 업그레이드 건물은 마지막 완성 레벨 blocked, linked token은 source-bound X, snapshot 불변.
- **GM-44:** 자발적 건설·업그레이드 취소는 50% 환불. 신규 제거, 업그레이드는 마지막 완성 상태 유지.
- **GM-45:** 글로벌 공사 슬롯 상한 없음. 노드당 건물 1·활성 공사 1, 서로 다른 노드는 병렬 가능.
- **GM-46:** 자기 완성 건물 철거는 시간 기반. 철거 중 효과·토큰 유지, 완료 시 제거·normal X·노드 비움, 완료 전 취소 가능.
- **GM-47:** 철거 완료 환급은 실제 지불한 최초 건설비와 완료 업그레이드 합계의 50%. 취소·미완성·기환불·명목 비용 제외.
- **GM-48:** 철거 중 적 점령 시 철거 취소·진행 폐기·철거 환급 없음·마지막 완성 blocked·source-bound X. 재점령 후 자동 재개 없음.

## 6. 방어탑·수리·글로벌 금화 장부

- **GM-49:** 일반 건물은 직접 공격 불가. 통제 상실은 점령, 적 영구 제거는 교체 완료. 방어탑만 공성 예외.
- **GM-50:** 방어탑 HP 0은 앵커 소유권을 변경하지 않으며 별도 8초 점령이 필요하다.
- **GM-51:** 방어탑 HP 0은 즉시 영구 삭제, 폐허·수리 상태 없음, 노드 비움·소유권 유지.
- **GM-52:** 방어탑은 비-TokenSource 전투 건물이며 릴을 변경하지 않는다.
- **GM-53:** 살아 있는 탑은 점령을 직접 차단하거나 contesting unit으로 계산하지 않지만 점령자를 공격할 수 있다.
- **GM-54:** 탑이 살아 있는 채 앵커 점령 완료 시 소유권을 즉시 점령자에게 이전하고 진영·표적을 반전한다. blocked 없음.
- **GM-55:** 이전된 탑은 현재 HP·최대 HP·완성 레벨·업그레이드를 보존하고 무료 치유 없음.
- **GM-56:** 탑 신규 건설 중 점령은 취소·50% 환불·미완성 제거. 업그레이드 중 점령은 취소·50% 환불·마지막 완성 상태와 현재 HP로 이전.
- **GM-57/58:** 초기 수리 제안은 GM-59 이후 계약으로 대체한다.
- **GM-59:** HP>0인 현재 소유 구조물은 전투·contested 중에도 유료 수리 가능. 최대 HP, HP 0, 지불 불가, 소유권 변경, 플레이어 중지 시 종료. 삭제·이전 규칙 적용, 환불 없음.
- **GM-60:** 작업자 하드캡 없음. 치유 `nH`, n번째 임금 `nC`, 총임금 `C*n(n+1)/2`. 수리 중 탑 전투 기능 유지.
- **GM-61:** 다음 정산 전체 임금을 못 내면 가장 높은 한계 임금 작업자부터 자동 해제해 최대 지불 가능 수만 유지한다. 자동 재고용 없음.
- **GM-62:** 모든 수리 구조물은 글로벌 수리 예산을 공유하며 전역 최고 한계 임금 작업자부터 제거한다. 플레이어 우선순위 없음.
- **GM-63:** 동률 제거 순서는 실제 한계 임금→현재 HP 비율 높은 구조물→`StableStructureId`.
- **GM-64:** 작업자 변경은 다음 1초 정산 경계 적용. 경계 순서는 요청 수 적용→글로벌 부족 해소→금화 차감→치유. HP 0은 즉시.
- **GM-65:** 마지막 tick은 실제 치유량 비례 임금만 부과하고 overheal 비용 없음. 최대 HP에서 작업자 해제·요청 수 0.
- **GM-66:** 1 금화=내부 1000. 정확 계산, HUD 기본 1자리·상세 최대 3자리.
- **GM-67:** 보상·구매·건설·업그레이드·환불·판매·수리는 하나의 고정소수점 글로벌 금화 장부 사용.
- **GM-68:** 정밀도 0.001 금화. 계산 debit 올림, 계산 credit/refund/reward 내림, 작성 정확 금액은 추가 반올림 없음.
- **GM-69:** 수리 작업자는 임시 유료 서비스다. 영구 풀·선불 고용·이동·전장 개체·해제 비용 없음.
- **GM-70:** 수리는 별도 유지보수 채널로 방어탑 업그레이드와 병행 가능, 철거·파괴·적 교체 중 불가. 탑·성문·본진에 같은 메커니즘 적용.
- **GM-71:** 탑·성문·본진은 같은 글로벌 수리 예산을 공유하고 구조물 종류 우선순위·자동 재고용 없음.
- **GM-72:** 구조물별 `RepairProfile`: 탑 `H_tower/C_tower`, 성문 `H_gate/C_gate`, 본진 `H_base/C_base`; 공통식은 `nH_s`, `C_s*n(n+1)/2`, `nC_s`.

## 7. 성문 재건

- **GM-73:** 성문 HP 0은 `BREACHED`, 차단·방어·작업자 수리 종료, 유료 시간 재건 필요. 본진 HP 0은 즉시 스테이지 패배, 재건 불가.
- **GM-74:** 적 존재 시 재건 정지 규칙 폐기.
- **GM-75:** 재건 성문은 이전 레벨·업그레이드를 잃고 기본 레벨로 복구하며 손실 환불 없음.
- **GM-76:** 완료 HP 50% 규칙 폐기. 50%는 시작 HP다.
- **GM-77:** 재건 시작 시 기본 최대 HP 50%의 공격 가능 구조물. 진행도 0→100%가 나머지 50%를 선형 치유. 공격 피해를 받을 수 있고 완료 시 현재 HP를 유지한다.
- **GM-78:** 적 존재는 재건 진행·진행 치유를 정지하지 않는다. 적은 공격 가능하며 footprint 규칙을 제외하면 적 존재 중 완료 가능.
- **GM-79:** 재건 중 HP 0은 실패·진행 0·환불 없음·`BREACHED`; 새 비용으로 50% HP에서 재시작.
- **GM-80:** 재건 중 일반 작업자 수리 불가, 진행 치유만 사용. 활성화 후 작업자 수리 허용.
- **GM-81:** 재건 중 통로 비차단. 100%에서 footprint 비어야 활성화. 점유 중 `READY_TO_ACTIVATE`: 비차단·진행 고정·진행 치유 종료·공격 가능. 비면 현재 HP로 즉시 활성화. HP 0은 실패.
- **GM-82:** footprint blocker는 살아 있는 아군·적 지상 유닛 collider 실제 교차. 시체·투사체·AOE·전리품·장식·비충돌 비행 제외.
- **GM-83:** 시작 50%, 총 진행 치유 예산 50%, 진행 delta 가산 치유·최대 HP clamp. 피해를 진행 목표치까지 보충하지 않고 100% 이후 진행 치유 없음.
- **GM-84:** 동일 timestamp: 진행 증가→delta 치유→`StableAttackEventId` 공격→각 피해 후 HP 0. HP 0 즉시 실패·후속 공격 무효 대상.
- **GM-85:** 재건 시작 후 자발적 취소 불가. 활성화·HP 0 실패·스테이지 종료로만 종료.
- **GM-86:** 비용은 기본 레벨 성문 최초 건설비의 50%, 시작 시 지불, 실패 환불 없음, 이전 업그레이드 미반영, 글로벌 debit 반올림 적용.
- **GM-87:** 초기 성문은 최초 건설 없이 제공. 재건은 고정 30 시뮬레이션 초, 실행·적 존재 중 진행, 전술 일시정지에서 정지, 30초 선형 치유.
- **GM-88:** 게임 시작 성문은 `ACTIVE`, 기본 레벨, 기본 최대 HP 100%, 업그레이드 없음.

## 8. Map·Stage·Wave와 런 상태

```yaml
CONTENT_HIERARCHY:
  MAP:
    contains: MULTIPLE_STAGES
  STAGE:
    belongs_to: ONE_MAP
    contains: MULTIPLE_WAVES
  WAVE:
    belongs_to: ONE_STAGE
```

Map은 공간 전장, Stage는 목표·규칙·적 구성·wave set을 가진 임무 구간, Wave는 병종·수량·라인·시간·예고·완료를 가진 개별 적 공세다.

- **GM-89R:** 같은 스테이지의 wave 전환은 모든 런타임 상태를 보존한다.
- **GM-89:** 같은 맵의 stage 전환도 자동 초기화 없이 모든 런타임 상태를 보존한다. 생존 유닛·HP·상태·라인 명령·앵커·소유권·건물·공사·blocked·성문·본진·탑 HP·수리·금화·이동 아이템·카운터·릴·토큰·cursor·binding·미확정 SpinSession·PendingReward를 유지한다. stage/wave ID·목표·modifier·forecast·spawn schedule만 변경한다.
- **GM-90:** 맵 하나가 독립 game/run이다. 다른 맵은 NEW GAME이며 런타임 상태 이월 없음. 작성된 기본 전장·구조물·경제·룰렛으로 초기화하고 성문은 기본 레벨·최대 HP다.

## 9. 메타 진행

- **GM-91:** 맵·난이도 해금, clear/best 기록, codex/tutorial 기록과 제한된 영구 전력 진행을 보존한다. 런타임 자산은 이월하지 않는다.
- **GM-92:** 주축은 전략 해금(건물, TokenSource, 병종 후보, 상점, 시작 구성 선택지), 보조는 상한형 수치 강화(시작 금화, 이동 아이템, 제한된 초기 릴 개선). 이산 레벨·하드캡·제한 효과. 무한 스탯·전역 피해·적 약화·무한 비용 감소·직접 자산 이월 금지.
- **GM-93:** 주요 메타 재화는 최초 맵·난이도·도전·캠페인 milestone, 보조는 소량 반복 clear. 반복 보상은 최초보다 현저히 낮고 최적 farming이 아니어야 한다.
- **GM-94:** 같은 맵 반복 clear는 점감하되 완전 중단하지 않는다.
- **GM-95:** 맵별 생애 반복 횟수. 최초 제외. 1회 100%, 2회 50%, 3회 이후 25%. 현실 시간·세션·런으로 초기화하지 않는다.
- **GM-96:** 계정 공용 메타 재화 1종이 전략 해금과 수치형 시작 강화에 사용되며 인런 금화와 분리된다.
- **GM-97:** 전략 해금은 영구·환불/재잠금 불가. 수치 강화는 활성 맵 밖에서 무료 respec·100% 환불, 활성 게임 중 잠금.
- **GM-98:** 현재 구매한 모든 수치형 시작 강화는 새 맵에 자동 적용. 활성 예산·슬롯·로드아웃 없음.
- **GM-99:** 전략 해금은 이후 적합한 맵의 카탈로그에서 자동 사용 가능. 활성화 로드아웃 없음. 단, 해금만으로 릴 토큰을 삽입하지 않으며 실제 완공 TokenSource만 릴을 구성한다.
- **GM-100:** 해금 콘텐츠가 자동 룰렛 풀을 희석한다는 질문은 잘못된 전제로 철회. weighted shuffle bag은 적용하지 않는다.

## 10. 병종 계열·출처·능력 성장

- **GM-100R:** 세부 병종마다 별도 심벌을 쓴다는 해석은 철회한다. 같은 기본 병종 계열은 Tier와 세부 병종이 달라도 동일 심벌을 공유한다.
- **GM-100C:** Tier 1은 계열 기본 병사, Tier 2 이상은 계열 내부 전문 병종이다. 계열 심벌은 Tier 1부터 유지된다.
- **GM-100D:** Tier 1 기본 병사 건물부터 계열 심벌 토큰을 각 릴에 1개씩 공급한다. Tier 2+ 업그레이드에서도 토큰 ID·위치·개수·심벌을 유지하고 출처 병종·Tier·payload만 완료 시 갱신한다.
- **GM-101:** Tier 2 세부 병종 분기는 건물별 배타적 선택이다. 한 건물이 여러 분기를 동시에 제공하지 않는다.
- **GM-102:** 동일 계열 당첨 시 활성 출처 건물 단위 후보를 만들고 3개 릴 토큰은 `source_building_instance_id`로 중복 제거한다. 건물 가중치는 마지막 완성 Tier, 병종 총가중치는 해당 건물 Tier 합이다.
- **GM-103:** 일반·엘리트·영웅·전설 모두 같은 Tier×건물 수 출처 가중치를 사용하며 등급별 추가 보정은 없다.
- **GM-104:** 상위 등급의 계열 공용 템플릿 교체 방향은 GM-104R로 대체한다.
- **GM-104R:** 모든 등급에서 선택된 출처의 실제 세부 병종 정체성을 유지한다. `Tier 3 철벽병 + 영웅 → 영웅 철벽병`.
- **GM-105:** 공통 등급 스탯 프로필을 주축으로 삼는 질문은 기존 패시브·액티브 성장 계약을 누락한 전제로 철회한다.

Tier와 등급은 독립 축이다.

출처 Tier가 결정:

- 실제 세부 병종.
- 패시브 생성.
- 기존 패시브 강화.

룰렛 등급이 결정:

- 액티브 기술 생성.
- 기존 액티브 기술 강화.

Tier별 패시브:

| Tier | 구성 |
|---:|---|
| 1 | 패시브 1 기본형 |
| 2 | 패시브 1 1차 강화 + 패시브 2 생성 |
| 3 | 패시브 1 2차 강화 + 패시브 2 1차 강화 + 패시브 3 생성 |

등급별 액티브:

| 등급 | 구성 |
|---|---|
| 일반 | 기술 1 기본형 생성 |
| 엘리트 | 기술 1 강화 |
| 영웅 | 강화된 기술 1 + 기술 2 생성 |
| 전설 | 강화된 기술 1 + 기술 2 강화 + 기술 3 생성 |

- **GM-105R:** 액티브 기술은 유닛 AI가 자동 발동한다. 해금·cooldown·작성 trigger·유효 대상·target layer·행동 가능 조건을 검사하며 플레이어 수동 클릭은 없다.
- **GM-106:** 여러 액티브가 동시에 가능하면 병종별 작성 우선순위 목록을 사용한다. 높은 우선순위부터 조건 검사하고 불충족 시 다음으로 이동한다. 무작위·고번호 단순 우선은 없다.

```yaml
ACTIVE_SKILL_PRIORITY:
  method: AUTHORED_PRIORITY_LIST
  example:
    1: EMERGENCY_DEFENSE
    2: CROWD_CONTROL
    3: DAMAGE_SKILL
```

## 11. 최종 유닛 생성 순서

```text
1. 최종 SpinSession 보드 확정
2. 완성선 수로 일반/엘리트/영웅/전설 확정
3. snapshot 전체 릴에서 동일 계열 출처 건물을 source ID로 중복 제거
4. 각 출처 건물에 마지막 완성 Tier 가중치 부여
5. 가중 추첨으로 출처 건물과 세부 병종 결정
6. 모든 등급에서 선택 세부 병종 정체성 유지
7. 출처 Tier로 패시브 생성·강화
8. 룰렛 등급으로 액티브 생성·강화
9. AI 작성 우선순위와 발동 조건 적용
10. PendingReward로 보관·판매·라인 배치 처리
```

결정론 계약:

- snapshot은 후보 건물, Tier, 세부 병종, 가중치, 패시브·액티브 payload를 동결한다.
- 같은 seed, snapshot과 최종 보드는 같은 결과를 만든다.
- 확정 뒤 live 건물 상태를 재조회해 결과를 변경하지 않는다.

데이터 마이그레이션:

- `fixed_grade_unit_template_id`, 계열별 `fixed_unit_template_id`는 제거 또는 세부 병종+grade composition 데이터로 대체한다.
- 문서·UI의 `일반 스킬` 명칭은 의미가 명확하도록 `액티브 기술`로 정리한다.
- 필요한 데이터: `family_symbol_id`, `source_building_instance_id`, `source_completed_tier`, `selected_unit_variant_id`, `source_weight`, `passive_unlock_ids`, `passive_upgrade_ids`, `reward_grade`, `active_skill_unlock_ids`, `active_skill_upgrade_ids`, `active_skill_priority`, `active_skill_trigger_conditions`.
