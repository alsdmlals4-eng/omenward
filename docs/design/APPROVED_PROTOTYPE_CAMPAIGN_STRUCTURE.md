# 승인된 프로토타입 캠페인 구조

- 상태: **승인됨**
- 대상: 첫 공개 프로토타입
- 목표 총 플레이 분량: 약 3시간
- 관련 문서: `APPROVED_MATCH_STRUCTURE.md`, `proposals/0002-prototype-campaign-and-stage-generator.md`

## 1. 핵심 결정

첫 공개 프로토타입은 다음 구조를 사용한다.

```text
짧은 수동 설계 튜토리얼 스테이지 1개
→ 절차적으로 변형되는 정규 스테이지 여러 개
→ 점차 증가하는 기본 난이도
→ 새로운 맵 변형과 특수 적 등장
→ 플레이어 선택형 제약으로 추가 난이도 설정
```

튜토리얼은 하나의 짧은 스테이지 안에서 핵심 기능을 순서대로 소개한다. 완전한 숙련을 요구하지 않고, 플레이어가 정규 스테이지를 시작할 수 있을 정도의 기본 조작과 시스템 연결만 이해시키는 것이 목적이다.

정규 스테이지에서는 필요한 순간에 짧은 툴팁과 첫 등장 안내를 제공하지만, 긴 튜토리얼 구간을 반복하지 않는다.

## 2. 추천 분량

| 구간 | 목표 시간 | 역할 |
|---|---:|---|
| 튜토리얼 | 10~15분 | 핵심 조작과 시스템 연결을 빠르게 소개 |
| 정규 스테이지 1~5 | 각 25~35분 | 난이도·맵·특수 적의 단계적 확장 |
| 결과·재정비·재시도 | 총 10~20분 | 빌드 확인, 제약 선택, 재도전 |

총 목표는 약 160~195분이다. 정규 후반 스테이지의 길이와 재도전 시간을 조정해 약 3시간 분량을 맞춘다.

## 3. 튜토리얼 스테이지

튜토리얼은 절차적으로 생성하지 않는 고정 스테이지다. 하나의 장으로 구성하고, 시드와 난이도 변형 없이 항상 같은 흐름을 제공한다.

### 3.1 진행 방식

튜토리얼은 기능을 개별 장으로 분리하지 않고 한 전투 흐름 안에서 짧게 소개한다.

```text
기본 조작 안내
→ 첫 건물 건설
→ 건물로 룰렛 토큰 추가
→ 첫 룰렛 회전
→ 유닛을 지정 라인에 배치
→ 적 웨이브 전조 확인
→ 상성에 맞춘 추가 배치
→ 접전지 점령
→ 건물 Tier 또는 포탑 업그레이드
→ 짧은 종합 웨이브 방어
→ 튜토리얼 완료
```

### 3.2 반드시 소개할 기능

- 카메라 이동, 선택, 일시정지와 1배속·2배속
- 후방·전방 건설 노드의 차이
- 시장·농장·훈련소·포탑의 기본 역할
- 건물 완공에 따른 룰렛 토큰과 확률 변화
- X 토큰, 기준 줄과 기본 룰렛 보상
- 대기칸과 상·중·하 라인 출전
- 검사·기병·창병·궁병의 핵심 상성
- T-30·T-15·T-5 웨이브 전조
- 중앙 접전지와 금화 수입
- 건물 Tier 상승과 포탑 사거리 확인

### 3.3 간략화 원칙

- 설명문은 한 번에 1~2문장으로 제한한다.
- 가능한 기능은 말로 설명하기보다 직접 한 번 실행하게 한다.
- 필수 행동만 잠시 강조하며, 나머지 UI는 정상적으로 사용할 수 있다.
- 튜토리얼 전용 복잡한 퍼즐이나 실패 판정은 만들지 않는다.
- 치명적인 실수는 즉시 패배시키지 않고 짧은 안내와 보충 자원으로 복구한다.
- 마지막 종합 웨이브는 2~3분 내로 끝나는 기본 병종 조합으로 구성한다.
- 특수 적, 복잡한 제약과 고급 빌드 최적화는 정규 스테이지에서 소개한다.
- 튜토리얼 완료 후 제약 시스템을 해금한다.
- 옵션에서 튜토리얼 안내를 빠르게 넘기거나 다시 볼 수 있다.

## 4. 정규 스테이지 진행

튜토리얼 이후에는 기본 시스템을 긴 설명으로 다시 가르치지 않는다. 대신 다음 세 축으로 난이도를 높인다.

### 4.1 난이도 증가

- 적 Threat Budget 증가
- 웨이브 간격 감소
- 적 건물 Tier 상승 속도 증가
- 동시 압박 라인 증가
- 경제 회복 여유 감소

### 4.2 맵 변경

- 본진과 전방 거점 사이 거리 변화
- 전방 거점과 접전지 사이 거리 변화
- 라인별 이동거리의 제한적 차이
- 노드의 시각적 배치와 환경 테마 변화

고정 계약인 3라인, 후방 6노드, 라인별 전방 3노드, 중앙 접전지, 기본 포탑 사거리 제한은 유지한다.

### 4.3 특수 적 등장

정규 스테이지가 진행될수록 특수 적을 순차적으로 해금한다.

- 공성병: 포탑과 시설을 우선 공격
- 돌격병 또는 강화 기병: 짧은 시간에 전열 돌파
- 지원병: 주변 적을 강화하거나 회복
- 침투병: 후방 시설을 노림
- 지휘관·영웅형 적: 명확한 전조와 고유 패턴 보유

특수 적은 처음 등장할 때 전투 전 카드와 첫 전조에서 아이콘, 역할, 공격 대상과 대응 수단을 공개한다. 이후에는 짧은 아이콘과 툴팁으로만 반복 안내한다.

## 5. 스테이지 구성 예시

| 구간 | 주된 변화 |
|---|---|
| 튜토리얼 | 핵심 기능을 한 전투에서 빠르게 소개, 고정 맵·고정 웨이브 |
| 정규 1 | 기본 규칙 종합, 소규모 맵 변형 |
| 정규 2 | 첫 공성형 특수 적, 전방 시설 방어 |
| 정규 3 | 라인 거리 차이와 다중 접전지 압박 |
| 정규 4 | 침투·지원형 적, 복합 웨이브 |
| 정규 5 | 고티어 적 건물, 특수 적 혼합, 최종 공세 |

스테이지 수와 정확한 특수 적 순서는 콘텐츠 제작량과 플레이테스트에 따라 조정할 수 있다.

## 6. 절차적 생성 범위

- 튜토리얼은 생성기 대상에서 제외한다.
- 정규 스테이지만 `StageArchetype`, `MapTemplate`, `EnemyBuildArchetype`, `WavePatternCard`를 조합한다.
- 생성 결과는 전투 전에 `StageManifest`로 고정한다.
- 같은 시드·난이도·제약·생성기 버전은 같은 결과를 만든다.
- 플레이 중 숨은 동적 난이도나 즉석 카운터 생성은 사용하지 않는다.

## 7. 제약 시스템과의 관계

제약은 기본 난이도와 별개인 플레이어 선택형 도전 규칙이다.

```text
기본 스테이지 진행 난이도
+ 선택한 Difficulty Profile
+ 선택한 제약
= 최종 StageManifest
```

- 튜토리얼에서는 제약을 사용할 수 없다.
- 튜토리얼 완료 후 정규 스테이지 준비 화면에서 선택한다.
- 기본값은 제약 없음이다.
- 제약의 효과와 보상은 시작 전에 모두 공개한다.
- 제약 때문에 대응 불가능한 스테이지가 나오지 않도록 Validator가 검사한다.

세부 규칙은 `docs/design/proposals/0003-constraint-system.md`에서 검토한다.

## 8. 구현 경계

이 문서는 캠페인의 구조를 승인한 것이며 Godot 구현 승인이 아니다. 실제 코드·데이터 작업은 별도의 Codex Plan Mode 구현 제안서와 사용자 승인을 거친다.
