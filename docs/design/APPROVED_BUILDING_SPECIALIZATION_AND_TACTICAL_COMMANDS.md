# 승인된 전투 중 건설, 건물 전문화와 전술 명령 방향

- 상태: **핵심 구조 승인됨 / 세부 수치와 개별 효과 조정 대기**
- 승인일: 2026-07-14
- 관련 제안서:
  - `docs/design/proposals/0005-building-tiers-lifecycle-and-economy.md`
  - `docs/design/proposals/0006-tactical-commands.md`

## 1. 적이 있어도 건설과 업그레이드는 계속된다

적 유닛이 건설 노드 주변에 있거나 건물을 공격하고 있어도 건설·업그레이드 진행도를 정지하지 않는다.

```text
적 웨이브 접근
→ 전방 노드에 포탑 건설 시작
→ 건설 중 구조물이 공격받음
→ 구조물이 파괴되기 전에 완공
→ 포탑 즉시 가동
→ 아슬아슬한 방어 성공 가능
```

계약:

- 적 존재는 새 건설·업그레이드 명령을 차단하지 않는다.
- 건설·업그레이드는 피격 중에도 계속 진행된다.
- 건설 중 구조물은 적의 공격 대상이며 완공 전에 파괴될 수 있다.
- 건설 중에는 생산·수입·식량·룰렛 토큰·포탑 공격 기능이 없다.
- 완공되는 시뮬레이션 틱부터 정상 기능이 활성화된다.
- 완공 전에 체력이 0이 되면 건설 실패, 환불 없음, 폐허 상태로 전환한다.
- 건설 중 구조물의 시작 체력과 진행도별 체력 곡선은 데이터로 조정한다.
- 건설 명령을 반복해 적의 이동을 막는 악용을 방지하도록 건설 중 구조물의 충돌·길막 규칙을 별도로 검증한다.

## 2. 3티어는 유지하되 선택형 전문화로 변경한다

기존의 완전 고정형 3티어는 다음 구조로 대체한다.

```text
Tier 1: 공통 기본 기능
→ Tier 2: 건물 역할 또는 병종 전문화 선택
→ Tier 3: 선택한 방향을 심화하거나 해당 건물 전용 교리 선택
```

원칙:

- Tier 2 선택은 해당 건물이 파괴·철거될 때까지 유지한다.
- 기본적으로 같은 건물에서 서로 다른 Tier 2 전문화를 동시에 섞지 않는다.
- 전문화 변경은 철거 후 재건설을 기본 방식으로 하며, 재전문화 아이템은 후속 검토한다.
- 업그레이드 중에는 이전 Tier의 기능과 기존 룰렛 토큰을 유지한다.
- 업그레이드 완료 순간 전문화 효과와 변경된 토큰을 적용한다.
- 전문화 선택 전 비용·시간·능력·토큰·확률 변화를 미리 표시한다.

## 3. 토큰 전문화

건물 전문화 후보 중 하나로 `토큰 증폭`을 허용한다.

기본 건물 토큰 계약:

- 토큰 제공 건물 1동은 기본적으로 세 릴 각각에 대응 토큰 1개를 제공한다.

토큰 증폭 계약:

- 전문화 완료 시 대응 심벌 토큰 1개를 **세 릴 중 정확히 한 릴에만 추가**한다.
- 추가될 릴은 스테이지 시드와 건물 인스턴스를 사용해 결정론적으로 추첨한다.
- 선택된 릴은 해당 건물이 유지되는 동안 고정되며 UI에 공개한다.
- 매 회전마다 추가 릴을 다시 추첨하지 않는다.
- 파괴·철거 시 해당 보너스 토큰은 다음 회전부터 제거한다.
- 건설·업그레이드 선택 화면에서 릴별 확률 변화를 미리 보여준다.

이 비대칭 토큰은 건물 수를 늘리지 않고 특정 릴을 조정하는 전문화이며, 모든 릴에 토큰을 하나씩 더 주는 효과는 아니다.

## 4. 생산 유닛 강화 전문화

생산시설은 `생산량·속도` 외에 해당 시설에서 생산된 유닛을 강화하는 방향을 가질 수 있다.

- 강화는 해당 시설에서 새로 생산되는 유닛에만 적용한다.
- 이미 생산된 유닛과 상점 용병에는 소급 적용하지 않는다.
- 생산 시 유닛 데이터에 출처와 강화 효과를 기록한다.
- 생산시설이 파괴돼도 이미 출전한 유닛의 획득 강화는 유지한다.
- 정확한 공격력·체력·방어·이동속도 수치는 데이터와 플레이테스트로 조정한다.

## 5. 기본 병영의 병종 전문화

프로토타입의 기본 병영은 다음 구조를 사용한다.

### Tier 1

- 기본 생산 유닛: 검사
- 기본 룰렛 토큰: 검사
- 역할: 초반에 안정적인 전열을 제공하는 공통 병영

### Tier 2 병종 선택

Tier 2 업그레이드 시 다음 세 가지 중 하나를 선택한다.

1. 기병 전문화
2. 창병 전문화
3. 궁병 전문화

업그레이드 완료 시:

- 이후 자동 생산 병종이 선택한 병종으로 변경된다.
- 병영이 세 릴에 제공하던 검사 토큰이 선택한 병종 토큰으로 변경된다.
- 업그레이드 전 생산한 검사와 이미 출전한 유닛은 변경되지 않는다.
- 업그레이드 중 진행되던 생산 진척도는 보존하고, 완료 뒤 나오는 다음 유닛부터 새 병종을 적용한다.
- 현재 진행 중인 룰렛 스냅샷은 바꾸지 않고 다음 회전부터 토큰 변경을 적용한다.

### Tier 3 교리 후보

선택한 병종을 유지한 채 다음 중 하나를 선택하는 방향을 기본안으로 둔다.

- **대량생산:** 생산 간격 감소
- **정예훈련:** 생산 유닛 강화 또는 일정 주기마다 엘리트 생산
- **토큰 증폭:** 선택 병종 토큰 1개를 결정된 랜덤 릴 하나에 추가

세 교리의 정확한 수치와 병종별 차별화는 후속 조정 항목이다.

## 6. 포탑 전문화

포탑은 Tier 2에서 역할을 선택하고 Tier 3에서 같은 역할을 심화하는 구조를 기본안으로 둔다.

- **제압형:** 공격이 작은 범위 또는 추가 대상에 영향을 줌
- **요새형:** 체력·방어·피격 저항 강화
- **장거리형:** 사거리 증가, 고티어에서 접전지 가장자리 제한 지원

원칙:

- 장거리형이 아닌 포탑은 접전지를 공격하지 않는다.
- 장거리형도 접전지 전체를 덮거나 적 진영 깊숙한 곳까지 공격해서는 안 된다.
- 제압형의 범위 공격은 적 밀집 대응용이며 본진·시설 철거 수단이 되지 않게 조정한다.
- 요새형은 시간을 벌지만 공격 병력을 대체할 정도의 영구 봉쇄 능력을 갖지 않는다.
- 전문화별 외형·아이콘·사거리 오버레이를 명확히 구분한다.

## 7. 금화 소모형 일회성 전술 명령

플레이어는 전투 중 금화를 지불하고 즉시 또는 짧은 예고 뒤 발동하는 `전술 명령`을 사용할 수 있다.

첫 프로토타입 후보:

1. 바리케이드 건설
2. 화살비
3. 역병
4. 강화지대

공통 계약:

- 각 발동은 금화를 소모하는 1회성 효과다.
- 룰렛 토큰을 추가하지 않는다.
- 식량과 건설 노드를 사용하지 않는다.
- 적 본진과 생산시설을 직접 파괴하는 주력 수단으로 만들지 않는다.
- 일시정지 중 목표를 예약할 수 있고 재개 시 실행한다.
- 효과 범위, 지속시간, 예상 피해·강화량과 금화 비용을 실행 전에 표시한다.
- 시장 중심 빌드가 축적한 금화를 전장 대응력으로 전환하는 주요 소비처다.

세부 규칙은 `docs/design/proposals/0006-tactical-commands.md`에서 검토한다.

## 8. 데이터와 UI 계약

건물 전문화 데이터는 최소 다음 필드를 가져야 한다.

```text
building_id
tier
specialization_id
production_unit_id
base_token_id
bonus_token_reel
production_modifiers
spawned_unit_modifiers
turret_modifiers
upgrade_cost
upgrade_time
```

전술 명령 데이터는 최소 다음 필드를 가져야 한다.

```text
command_id
gold_cost
target_type
cast_delay
duration
cooldown
global_cooldown
effect_payload
stacking_rule
allowed_stage_tags
```

UI는 다음을 명확히 보여준다.

- 적이 있어도 남은 건설·업그레이드 시간
- 건설 중 구조물의 현재 체력과 완공 예상 시점
- Tier 2 전문화 3개 비교
- 병영 전문화 후 생산 병종과 토큰 교체
- 토큰 증폭으로 추가되는 정확한 릴과 확률 변화
- 포탑 전문화별 사거리·범위·내구도 변화
- 전술 명령 비용, 범위, 효과, 재사용 가능 시점

## 9. 아직 미확정인 세부

- 건설 중 시작 체력과 진행도별 체력 상승 곡선
- 건설 중 구조물의 충돌·길막 범위
- 농장과 시장의 정확한 전문화 목록
- 병영 Tier 3 교리의 정확한 수치
- 토큰 증폭의 Tier 2·Tier 3 배치 여부
- 포탑 제압형의 범위와 최대 대상 수
- 전술 명령별 비용·지속시간·재사용 대기시간
- 전술 명령의 저장형 아이템 여부와 동시 보유 제한

이 문서는 핵심 방향을 승인하지만 세부 수치를 구현 승인으로 간주하지 않는다. Godot 구현은 별도의 Codex Plan Mode 제안서와 사용자 승인을 거쳐야 한다.
