# OM-IMG-018 — 패배·제품 유료 재시도 화면 브리프

- Decision ID: `OMW-DEC-20260801-VISUAL-SCREEN-BOARD-V2`
- 화면 ID: `OM-IMG-018`
- 상태: `TEXT_BRIEF_CURRENT / IMAGE_NOT_GENERATED`
- 역할: `DEFEAT / PAID_RETRY / RUN_END`

## 1. 플레이어 질문

> 이 런을 종료할 것인가, 영구재화를 사용해 같은 문제를 한 번 더 풀 것인가, 무엇이 복원되고 무엇이 사라지는가?

## 2. 핵심 구도

- 배경: 패배 직전 전장을 어둡게 정지한 장면.
- 중앙: `패배`와 실패 Stage.
- 좌측: `런 종료` 선택.
- 우측: 조건을 충족한 경우 `유료 재시도` 선택.
- 하단 또는 상세 패널: 복원 범위·폐기 범위·사용 가능 횟수.
- 현실 화폐 상점이나 과도한 구매 유도처럼 보이지 않게 한다.

## 3. 제품 유료 재시도 조건

```text
Stage 1~4: 제품 유료 재시도 비활성
Stage 5 이후: MapRun당 최대 1회
비용: 프로필 정산 영구재화
현재 런 미정산 재화·골드·식량·무료 회전 사용 불가
```

영구재화 정본명과 실제 비용은 미확정이다. 샘플 화면에서는 `[영구재화]`, `[비용 미정]`을 사용한다.

## 4. 재시도 시 복원

표시해야 할 핵심:

- 실패 Stage 준비 checkpoint.
- 동일 seed·공세·미션·룰렛 RNG 계보.
- checkpoint 당시 건물·릴·보관·배치·경제 상태.
- 재시도 사용 상태.

## 5. 재시도 시 폐기

- 실패 전투 중 피해·사망.
- 소비·점령 변화.
- 실패 전투 중 생성된 미정산 보상.
- checkpoint 이후 임시 사건.

복원과 폐기를 두 열 또는 두 아이콘 그룹으로 명확히 구분한다.

## 6. 거래 안전 정보

- 복원 가능 여부를 먼저 검증한다.
- 복원 실패 시 영구재화를 차감하지 않는다.
- 같은 transaction을 반복해도 이중 차감하지 않는다.
- 이미 재시도를 사용했으면 이유와 함께 비활성화한다.

기술 transaction ID를 기본 화면에 노출하지 않는다.

## 7. 선택 문구 예시

```text
동일 공세·동일 RNG 계보
[영구재화] [비용 미정] 사용
```

## 8. 벨루

- 복원 범위를 한 문장으로 설명한다.
- 재시도를 강요하거나 런 종료를 실패·손실로 비난하지 않는다.
- 영구재화 부족을 구매 유도로 연결하지 않는다.

## 9. 접근성

- `런 종료`와 `재시도`의 포커스·결과를 명확히 분리.
- 파괴적 선택은 색+아이콘+문구로 구분.
- 비용과 잔액은 같은 단위·위치에서 비교.
- 키보드 기본 포커스는 자동 결제 버튼이 아니라 중립 위치 또는 안전 선택에 둔다.

## 10. 금지

- 현금·카드·상점·광고 이미지를 연상시키는 UI.
- 카운트다운으로 결제를 압박.
- 미확정 영구재화명·비용 숫자 발명.
- Stage 1~4에서 사용 가능한 것처럼 표현.
- seed·공세가 바뀌는 새 문제를 같은 Retry로 표현.
- 무료 개발 restart와 제품 유료 Retry 혼합.
- Retry 선택을 기본 자동 확정.

## 11. 검수

- 두 선택의 비용·결과가 대칭적으로 이해되는가.
- 같은 문제를 다시 푼다는 점이 읽히는가.
- 복원·폐기 범위가 기술 문서 없이 이해되는가.
- 사용 횟수와 자격 조건이 명확한가.
- 현실 화폐 결제나 강압적 monetization으로 보이지 않는가.
