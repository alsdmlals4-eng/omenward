# OM-IMG-017 — Stage 정산·인과 복기 화면 브리프

- Decision ID: `OMW-DEC-20260801-VISUAL-SCREEN-BOARD-V2`
- 화면 ID: `OM-IMG-017`
- 상태: `TEXT_BRIEF_CURRENT / IMAGE_NOT_GENERATED`
- 역할: `STAGE_RESULT / CAUSAL_RECAP`

## 1. 플레이어 질문

> 이번 결과는 운 때문이었는가, 내가 만든 릴 구조·건물·배치 때문이었는가, 다음 Stage에서 무엇을 바꿔야 하는가?

## 2. 핵심 구도

- 좌측 또는 상단: Stage 결과와 세 라인 요약.
- 중앙: 가장 중요한 원인 사슬.
- 우측 또는 하단: 보상·손실·미션·다음 행동.
- 상세 사건 로그는 접힌 2차 정보로 둔다.
- 결과 화면은 전투 장면의 정지 배경 또는 축약 battlefield strip을 사용해 원인과 공간을 연결한다.

## 3. 원인 사슬

기본 표시:

```text
건물·TokenSource
→ TokenInstance와 릴 구조
→ SpinSnapshot 결과
→ PendingReward 처리
→ 배치 라인
→ 주요 전투 사건
→ Stage 결과
```

각 단계는 실제 ID·출처·라인을 추적할 수 있어야 하지만, 기술 로그처럼 긴 문자열을 기본 화면에 노출하지 않는다.

## 4. 결과 요약

필수:

- Stage 승리 또는 패배 직전 결과.
- 상·중·하 라인의 전선 변화.
- 생존 병력·손실 병력.
- 소유 거점 변화.
- 파괴·BLOCKED·유지된 주요 건물.
- 골드·식량·보관함 영향.
- 미션 진행 또는 완료.

정확한 수치는 실제 데이터가 존재하는 범위에서만 표시한다. 컨셉 이미지에서는 placeholder를 사용한다.

## 5. 상위 원인

기본 화면에는 다음만 표시한다.

- 도움이 된 원인 최대 3개.
- 손해를 만든 원인 최대 3개.
- 각 원인은 `행동/구조 → 사건 → 결과` 문장으로 표현.

예시 형식:

```text
중앙 병영 TokenSource가 보병 토큰을 세 릴에 공급
→ 중앙 판정선에서 병력 결과 확정
→ 중단 라인 방어 유지
```

실제 병종명·수치는 데이터 확정 전 발명하지 않는다.

## 6. 다음 행동

- `다음 Stage 준비`.
- 필요 시 `상세 사건 보기`.
- 미션 선택 Stage라면 미션 후보 또는 거절 진입.
- 위험 Stage 직전이면 다음 공세 경고.
- save/checkpoint 성공 상태를 짧게 표시.

## 7. 벨루

- 결과의 가장 큰 인과 하나를 짧게 요약한다.
- 운이 나빴다는 단정이나 플레이어 비난을 하지 않는다.
- 같은 원인 카드의 내용을 장문으로 반복하지 않는다.

## 8. 정보 위계

```text
1. 승패·다음 행동
2. 세 라인의 결과 변화
3. 상위 원인 사슬
4. 보상·손실·미션
5. 상세 사건 로그
```

## 9. 금지

- 경험치·레벨업·아이템 상자 중심 결과 화면.
- 일반 전리품 희귀도 카드.
- 원인 없이 보상 숫자만 나열.
- 기술 event log를 기본 화면 전체에 노출.
- 가상의 정확 통계·백분율 발명.
- 룰렛 결과와 배치 라인의 연결 누락.
- `좋은 운/나쁜 운` 하나로 결과를 단순화.

## 10. 검수

- 건물→릴→결과→배치→전투 인과가 한눈에 이어지는가.
- 세 라인의 공간 결과가 보이는가.
- 보상보다 다음 설계 판단이 더 중요한 화면으로 읽히는가.
- 상위 원인이 기술 로그가 아니라 플레이어 문장으로 표현되는가.
- 일반 로그라이크 전리품 결과 화면으로 오인되지 않는가.

```text
IMAGE_GENERATION: NOT_STARTED
CAUSE_EVENT_SCHEMA: IMPLEMENTATION_PENDING
RUNTIME_VALIDATION: NOT_RUN
```
