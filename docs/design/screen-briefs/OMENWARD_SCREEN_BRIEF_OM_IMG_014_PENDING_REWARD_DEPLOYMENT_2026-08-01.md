# OM-IMG-014 — PendingReward·보관·판매·배치 화면 브리프

- Decision ID: `OMW-DEC-20260801-VISUAL-SCREEN-BOARD-V2`
- 화면 ID: `OM-IMG-014`
- 상태: `TEXT_BRIEF_CURRENT / IMAGE_NOT_GENERATED`
- 역할: `RESOURCE_MANAGEMENT / PENDING_REWARD / IRREVERSIBLE_DEPLOYMENT`

## 1. 플레이어 질문

> 이번 릴 결과를 보관할지, 판매할지, 어느 라인에 영구 배치할지 결정할 수 있는가?

## 2. 핵심 구도

- 중앙 상단: 현재 확정된 `PendingReward` 한 건.
- 좌측: 보관 병력 목록과 보관 용량.
- 중앙 하단: `보관`, `판매`, `배치` 세 행동.
- 우측: 상·중·하 세 라인의 현재 상태 비교.
- 배치를 선택하면 라인 하나를 고르고 최종 확인한다.

이 화면은 장비 인벤토리가 아니라 **병력 결과 처리와 전선 커밋 화면**이다.

## 3. PendingReward 카드

필수 정보:

- 병종 또는 역할 심벌.
- 등급.
- 출처 TokenSource.
- 생성된 SpinSnapshot 요약.
- 식량 비용 또는 예약 영향 placeholder.
- 현재 처리 상태.

금지:

- 무기·방어구 슬롯.
- 랜덤 옵션·보석·룬.
- 영웅 초상화 중심 카드.
- 확정되지 않은 정확 능력치.

## 4. 세 행동

### 보관

- 보관 병력은 식량을 사용하지 않는다.
- 보관 용량과 남은 칸을 표시한다.
- 공간 부족 시 이유와 대안을 표시한다.

### 판매

- 판매 예상값을 확정 전 preview한다.
- 정확한 판매가는 미정이므로 샘플 이미지에서는 기호 또는 placeholder를 쓴다.
- 판매 후 복구할 수 없음을 짧게 표시한다.

### 배치

- 상·중·하 중 한 라인을 선택한다.
- 배치 가능 식량과 예약 후 잔여량을 preview한다.
- 배치 확정 전에는 선택 변경 가능.
- 배치 확정 뒤 라인 변경·회수·판매 불가.

## 5. 라인 비교 정보

각 라인은 작은 카드가 아니라 동일 전장의 축약 strip으로 표시한다.

필수:

- 현재 전선 위치.
- 아군·적 주력 병력.
- 현재/다음 공세.
- 식량 예약 영향.
- 위험 또는 기회 한 줄.

분석을 돕되 하나의 정답 라인을 자동 강조하지 않는다.

## 6. 비가역 확인

최종 배치 확인은 다음을 명시한다.

```text
이 병력은 [상/중/하] 라인에 배치됩니다.
배치 후 라인 변경·회수·판매가 불가능합니다.
식량 [값 미정]이 예약됩니다.
```

확정 버튼과 취소 버튼을 명확히 분리한다. 취소는 확정 전 화면 복귀이며, 이미 확정된 배치를 되돌리는 기능이 아니다.

## 7. 정보 위계

```text
1. 현재 처리해야 할 PendingReward
2. 보관·판매·배치 선택
3. 선택한 라인의 현재 위험과 식량 영향
4. 출처·snapshot·장기 분석
```

## 8. 벨루

- 첫 비가역 배치에서 한 번만 경고 가능.
- `이 라인이 정답`이라고 말하지 않는다.
- 공간 부족·식량 부족·배치 불가 원인을 요약할 수 있다.

## 9. 접근성

- 세 행동은 아이콘과 텍스트를 함께 사용.
- 라인은 위치·명칭·형태로 구분하며 색만 쓰지 않는다.
- 비가역 경고는 아이콘·굵은 제목·확인 문장으로 반복한다.
- 키보드 이동 순서는 PendingReward → 행동 → 라인 → 확인 순서.

## 10. 검수

- 일반 장비 인벤토리로 오인되지 않는가.
- 처리 대상이 항상 한 건의 PendingReward임이 명확한가.
- 보관 병력과 배치 병력이 구분되는가.
- 식량이 배치 시 예약되고 보관에는 사용되지 않는다는 점이 읽히는가.
- 확정 전 변경과 확정 뒤 비가역성이 혼동되지 않는가.

```text
IMAGE_GENERATION: NOT_STARTED
EXACT_SELL_AND_FOOD_VALUES: PENDING
RUNTIME_VALIDATION: NOT_RUN
```
