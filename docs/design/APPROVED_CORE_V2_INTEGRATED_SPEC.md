## 1. 최종 제품 약속

> **예고된 세 전선의 공세를 읽고, 제한된 건물로 세 원형 릴의 토큰 구조를 설계·영구 편집한 뒤, 당첨 병력을 어느 전선에 커밋할지 결정해 전황을 뒤집는 실시간 전략 오토배틀 게임.**

```text
건물로 룰렛을 만들고
→ 룰렛으로 병력을 확보하고
→ 병력을 한 전선에 커밋하고
→ 자동전투 결과로 다음 설계를 수정한다
```

## 3. 2026-07-24 확정 계약

1. 가로 이동은 선택 행의 노출 인덱스 사이에서 `TokenInstance`만 순환 교환한다. 배열 길이와 cursor는 변하지 않는다.
2. 토큰 추가는 가장 낮은 안정 배열 인덱스의 X를 교체하고 X가 없을 때만 append한다.
3. 멈춤 시 전체 릴·cursor·보드·비용·출처 후보·reward payload를 immutable `SpinSnapshot`으로 동결한다.
4. 세부 출처는 snapshot 전체 릴의 동일 심벌 출처 풀에서 결정한다.
5. 럭키는 숨김 `15/25/35/45/55/100%`와 승인 truth table을 사용한다.
6. 전술 아이템 룰렛 심벌은 보류하며 `TokenSource` 건물만 토큰을 공급한다.
7. 코어 PoC와 첫 수직 슬라이스는 mid-run save를 지원하지 않는다. 정식 20스테이지 전 준비 화면 checkpoint를 별도 승인한다.

## 8. 코어 성공 질문

1. 건설로 릴 구성이 바뀌는 것을 플레이어가 설명하는가.
2. 가로 이동의 현재·미래 효과를 이해하는가.
3. 이동 자원을 쓸지 보존할지 고민하는가.
4. 보관과 영구 배치가 공세 예고와 연결되는가.
5. 위험 스테이지가 클릭 속도보다 판단 압박으로 느껴지는가.
6. 실패 뒤 다음 건설·조작·배치를 수정하는가.

## 9. 구현 전 금지

- V2 코드를 기존 서비스에 바로 덧대지 않는다.
- 기존 C1 resolver 테스트를 삭제하지 않는다.
- 문서 승인만으로 `PROVEN`, `COMPLETE`, `CORE_LOCK_V2`를 사용하지 않는다.
- 전술 아이템 심벌, mid-run save, 대규모 메타를 임의 구현하지 않는다.
- 제품 코드 변경은 별도 Plan Mode 제안과 사용자 승인을 거친다.
