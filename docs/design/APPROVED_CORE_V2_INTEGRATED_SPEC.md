## 1. 최종 제품 약속

> **예고된 세 전선의 공세를 읽고, 제한된 건물로 세 원형 릴의 토큰 구조를 설계·영구 편집한 뒤, 당첨 병력을 어느 전선에 커밋할지 결정해 전황을 뒤집는 실시간 전략 오토배틀 게임.**

```text
건물로 룰렛을 만들고
→ 룰렛으로 병력을 확보하고
→ 병력을 한 전선에 커밋하고
→ 자동전투 결과로 다음 설계를 수정한다
```

시장 구분:

> 3×3 슬롯으로 병력을 뽑는 게임이 아니라, 건물과 가로 이동으로 미래 룰렛 자체를 다시 쓰는 3전선 지휘 게임.

핵심 문구:

> 건물로 룰렛을 만들고, 룰렛으로 전선을 지휘한다.

## 3. 기본 V2 계약

1. 가로 이동은 선택 행의 노출 인덱스 사이에서 `TokenInstance`만 순환 교환한다. 배열 길이와 cursor는 변하지 않는다.
2. 토큰 추가는 가장 낮은 안정 배열 인덱스의 `NORMAL_X`를 교체하고 `NORMAL_X`가 없을 때만 append한다. `SOURCE_BOUND_X`는 일반 교체 대상이 아니다.
3. 멈춤 시 전체 릴·cursor·보드·비용·출처 후보·reward payload를 immutable `SpinSnapshot`으로 동결한다.
4. 세부 출처는 snapshot 전체 릴의 동일 계열 심벌 출처 건물을 `source_building_instance_id`로 중복 제거한 풀에서 결정한다.
5. 출처 건물 가중치는 마지막 완성 Tier이며 세부 병종 총가중치는 해당 건물들의 Tier 합이다.
6. 럭키는 숨김 `15/25/35/45/55/100%`를 사용하고 현재 SpinSession 전용 무료 이동을 제공한다.
7. 전술 아이템 룰렛 심벌은 보류하며 `TokenSource` 건물만 토큰을 공급한다.
8. 코어 PoC와 첫 수직 슬라이스는 mid-run save를 지원하지 않는다.
9. 성공·무보상·보상·카운터·출처는 `[확정]`에서 원자적으로 정확히 한 번 처리한다.
10. 미확정 SpinSession과 미처리 PendingReward가 있으면 다음 회전을 시작할 수 없다.

## 4. 유닛 보상 구성

같은 기본 병종 계열은 Tier와 세부 병종이 달라도 같은 계열 심벌을 공유한다. Tier 1 기본 병사 건물부터 계열 토큰을 각 릴에 하나씩 공급한다. 업그레이드는 토큰 ID·위치·개수·계열 심벌을 유지하고 출처 Tier·세부 병종·payload만 완료 시 갱신한다.

최종 생성 순서:

```text
최종 보드와 등급 확정
→ snapshot의 동일 계열 출처 건물 수집
→ 완성 Tier 가중 추첨
→ 선택 세부 병종 유지
→ 출처 Tier로 패시브 생성·강화
→ 룰렛 등급으로 액티브 기술 생성·강화
→ 병종별 작성 우선순위로 AI 자동 발동
```

과거의 `엘리트·영웅·전설 계열 고정 템플릿`은 현재 정본이 아니다.

Tier별 패시브:

| Tier | 패시브 구성 |
|---:|---|
| 1 | 패시브 1 기본형 |
| 2 | 패시브 1 1차 강화 + 패시브 2 생성 |
| 3 | 패시브 1 2차 강화 + 패시브 2 1차 강화 + 패시브 3 생성 |

등급별 액티브:

| 등급 | 액티브 구성 |
|---|---|
| 일반 | 기술 1 기본형 생성 |
| 엘리트 | 기술 1 강화 |
| 영웅 | 강화된 기술 1 + 기술 2 생성 |
| 전설 | 강화된 기술 1 + 기술 2 강화 + 기술 3 생성 |

## 5. 이동 경제와 결과 처리

- 보관형 이동 아이템 상한은 3개다.
- 럭키 무료 이동을 먼저 소비하며 미사용분은 확정 시 소멸한다.
- 확정 무보상 누적 2회마다 보관형 이동 아이템을 지급한다.
- 상한에서 발생한 무보상 보상은 pending 1개로 보류하고 pending 동안 누적 카운터를 정지한다.
- 같은 SpinSession 안의 n번째 상점 구매 가격은 `nP`, k개 총비용은 `P*k(k+1)/2`다.
- `P`는 가장 저렴한 의미 있는 건설 또는 핵심 업그레이드 비용의 50%를 기준으로 하고 40~60%를 검증한다.
- 유닛 결과는 PendingReward에서 보관·판매·라인 배치 중 하나로 처리한다.
- 금화 결과는 확정 거래에서 즉시 글로벌 고정소수점 장부에 적립한다.

## 6. 전장 명령과 지속 상태

- 유닛은 라인 배치 즉시 출격한다. 아군 주기적 3기 배치 묶음은 사용하지 않는다.
- 라인마다 최신 `[대기: 앵커]` 또는 `[공격]` 명령 하나를 가진다.
- 현재·이동 중·향후 배치 유닛이 최신 명령을 상속한다.
- 대기 유닛은 앵커별 `HoldRadius` 안에서 자동전투하고 반경 밖 추격을 중단한다.
- 점령은 고정 8초 비교전 진행이며 적 진입 시 정지, 점령측 0명 시 초기화, 완료 즉시 소유권 변경이다.
- 같은 맵의 wave·stage 전환은 모든 런타임 상태를 보존한다.
- 다른 맵은 NEW GAME이며 런타임 상태를 이월하지 않는다.

## 7. 건설·차단·구조물

- 모든 건설·업그레이드·교체·철거는 결정론적 시뮬레이션 시간으로 진행한다.
- 일반 건물은 직접 공격할 수 없으며 점령 시 `BLOCKED`, 적 교체 완료 시 영구 삭제한다.
- blocked TokenSource 토큰은 위치를 보존한 `SOURCE_BOUND_X`가 된다.
- 방어탑만 직접 공격 가능한 일반 건물 예외이며 HP 0에서 즉시 삭제된다.
- 살아 있는 방어탑이 있는 앵커가 점령되면 현재 HP·레벨을 보존해 점령자에게 즉시 이전한다.
- 방어탑·성문·본진 수리는 하나의 글로벌 예산과 고정소수점 금화 장부를 사용한다.
- 성문 HP 0은 `BREACHED`; 재건은 기본 성문 비용 50%, 고정 30초, 시작 HP 50%, 진행 치유 50%다.
- 재건 중 적 존재는 진행을 정지하지 않으며 footprint가 비어야 활성화한다.

정확한 거래 순서·환불·수리 임금·재건 이벤트 순서는 통합 결정 원장을 따른다.

## 10. 코어 성공 질문

1. 건설로 릴 구성이 바뀌는 것을 플레이어가 설명하는가.
2. 가로 이동의 현재·미래 효과를 이해하는가.
3. 이동 자원을 쓸지 보존할지 고민하는가.
4. 출처 Tier 가중치와 실제 세부 병종 확률을 이해하는가.
5. Tier 패시브와 룰렛 등급 액티브의 차이를 설명하는가.
6. 대기 앵커와 공격 명령으로 전선 흐름을 의도적으로 바꾸는가.
7. 위험 스테이지가 클릭 속도보다 판단 압박으로 느껴지는가.
8. 실패 뒤 다음 건설·조작·배치를 수정하는가.

## 11. 구현 전 금지

- V2 코드를 기존 서비스에 바로 덧대지 않는다.
- 기존 C1 resolver 테스트를 삭제하지 않는다.
- 문서 승인만으로 `PROVEN`, `COMPLETE`, `CORE_LOCK_V2`를 사용하지 않는다.
- 전술 아이템 심벌, mid-run save와 무한 성장 수치를 임의 구현하지 않는다.
- 과거 계열 고정 상위 등급 템플릿 또는 아군 3기 묶음 출격을 현재 정본으로 구현하지 않는다.
- 제품 코드 변경은 별도 Plan Mode 제안과 사용자 승인을 거친다.
