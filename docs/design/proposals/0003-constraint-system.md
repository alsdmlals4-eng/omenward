# 제안서 0003 — 플레이어 선택형 제약 시스템

- 상태: **사용자 조정안 대기**
- 전제: `docs/design/APPROVED_PROTOTYPE_CAMPAIGN_STRUCTURE.md`
- 구현 상태: 승인 전 구현 금지

## 1. 목적

기본 난이도를 완료한 플레이어가 같은 스테이지를 더 까다로운 조건으로 다시 도전할 수 있게 한다. 제약은 숨은 난이도 보정이 아니라, 플레이어가 시작 전에 직접 선택하고 효과를 확인하는 공개형 규칙이다.

핵심 목표:

- 기본 캠페인의 접근성을 유지하면서 추가 도전 제공
- 같은 시드와 맵의 재도전 가치 증가
- 특정 빌드만 반복하지 않고 다른 전략을 실험하게 함
- 난이도 상승 원인을 플레이어가 명확히 이해하게 함
- 영구 능력치 보상 없이도 점수·도전 기록을 제공

## 2. 기본 구조

```text
Stage Archetype
+ Difficulty Profile
+ 선택한 Constraint Set
+ Seed
+ Generator Version
= StageManifest
```

- 튜토리얼에서는 제약을 사용할 수 없다.
- 튜토리얼 완료 후 정규 스테이지에서 해금한다.
- 스테이지 준비 화면에서 선택한다.
- 기본값은 제약 없음이다.
- 전투 시작 후 제약을 추가·제거할 수 없다.
- 같은 시드·난이도·제약 조합은 같은 스테이지를 만든다.

## 3. 제약 포인트

각 제약은 위험도에 따라 1~3점의 제약 점수를 가진다.

| 등급 | 점수 | 의미 |
|---|---:|---|
| 경미 | 1 | 한 시스템의 여유를 조금 줄임 |
| 중간 | 2 | 빌드와 운영 방식에 분명한 변화 요구 |
| 강함 | 3 | 스테이지 전체 전략을 바꾸는 조건 |

추천 초기 규칙:

- 정규 스테이지 첫 도전: 0~2점 선택 가능
- 해당 스테이지 첫 클리어 후: 최대 5점까지 선택 가능
- 어려움 난이도 클리어 후: 최대 7점까지 선택 가능
- 제약을 선택하지 않아도 캠페인 진행에 불이익 없음

정확한 상한은 플레이테스트 조정 항목이다.

## 4. 제약 데이터 계약

각 제약은 최소 다음 정보를 가진다.

```text
constraint_id
display_name
description
category
severity
constraint_points
minimum_stage_index
required_unlocks
effect_parameters
incompatible_tags
validation_rules
score_multiplier
ui_warning_text
```

효과는 코드 분기보다 데이터 매개변수로 정의하는 것을 우선한다.

## 5. 초기 제약 후보

### 5.1 경제 제약

| 이름 | 점수 | 효과 |
|---|---:|---|
| 빈곤한 출정 | 1 | 시작 금화 감소 |
| 불황 | 2 | 시장 금화 생산량 감소 |
| 고비용 건설 | 2 | 건설·업그레이드 비용 증가 |
| 공사 지연 | 1 | 건설시간 증가 |

### 5.2 보급·건설 제약

| 이름 | 점수 | 효과 |
|---|---:|---|
| 보급난 | 2 | 기본 최대 식량 감소 |
| 폐허 장기화 | 1 | 파괴 노드의 폐허 유지시간 증가 |
| 봉쇄된 후방 | 3 | 후방 안전 노드 1개 사용 불가 |
| 제한 방어 | 2 | 라인당 포탑 건설 수 제한 |

### 5.3 룰렛 제약

| 이름 | 점수 | 효과 |
|---|---:|---|
| 비싼 회전 | 1 | 룰렛 비용 증가 |
| 불운한 흐름 | 2 | 럭키 찬스 실패 누적 증가량 감소 |
| 흐린 예감 | 2 | 럭키 찬스 이동권 상점 등장 빈도 감소 |

룰렛 결과를 조작하거나 플레이어가 알 수 없는 확률 보정은 사용하지 않는다.

### 5.4 전장·접전지 제약

| 이름 | 점수 | 효과 |
|---|---:|---|
| 빈약한 거점 | 1 | 접전지 금화 수입 감소 |
| 긴 보급로 | 2 | 한 개 이상의 라인 이동거리 증가 |
| 약한 본진 | 2 | 플레이어 본진 최대 체력 감소 |

맵 거리 제약은 기본 포탑 사거리와 대응 시간을 Validator가 다시 검사해야 한다.

### 5.5 적 강화 제약

| 이름 | 점수 | 효과 |
|---|---:|---|
| 빠른 공세 | 2 | 정규 웨이브 간격 감소 |
| 정예 편성 | 2 | 일정 웨이브마다 엘리트 유닛 추가 |
| 강화 거점 | 2 | 적 전방 건물 일부가 높은 Tier로 시작 |
| 특수 선봉 | 3 | 해당 스테이지에서 허용된 특수 적이 더 일찍 등장 |

## 6. 초기 제외 제약

첫 프로토타입에서는 다음 제약을 제외하는 것을 추천한다.

- 적 웨이브의 병종·라인·수량 정보 숨기기
- 일시정지 금지
- 단 한 번의 패배로 캠페인 초기화
- 무작위로 건물 또는 유닛 삭제
- 플레이 도중 예고 없이 규칙 변경
- 특정 병종을 완전히 금지해 필수 카운터가 사라지는 조건
- 저장 불가 또는 강제 철인 모드

이 제약들은 전략보다 정보 부족과 피로도를 높일 가능성이 크다.

## 7. 조합 규칙

모든 제약을 자유롭게 중첩하지 않는다.

예시 금지 조합:

- `보급난` + 지나치게 높은 `봉쇄된 후방`
- `빠른 공세` + `공사 지연`이 대응 준비시간 하한을 깨는 경우
- `긴 보급로` + 맵 템플릿의 최장 거리 변형
- `특수 선봉` + 아직 해당 특수 적 설명이 해금되지 않은 스테이지
- 경제 제약 여러 개가 첫 필수 건물 건설을 불가능하게 만드는 경우

제약은 `incompatible_tags`와 Validator 규칙으로 차단한다.

## 8. 보상 구조

프로토타입에서는 제약 보상이 전투력을 영구적으로 높이지 않게 한다.

추천 보상:

- 제약 점수에 따른 결과 점수 배율
- 스테이지별 최고 제약 점수 기록
- 난이도·제약 조합 완료 메달
- 결과 화면의 빌드·제약 요약
- 높은 제약 점수 달성 시 추가 제약 단계 또는 도전 프리셋 해금

제외 보상:

- 영구 공격력·체력 증가
- 다음 스테이지 시작 금화 증가
- 제약을 사용하지 않는 플레이어가 손해 보는 필수 자원

## 9. UI 흐름

스테이지 준비 화면:

1. 난이도 선택
2. 시드 확인 또는 변경
3. 제약 목록 확인
4. 제약 선택
5. 변경되는 수치와 규칙 비교
6. 예상 위험도, 총 제약 점수, 점수 배율 표시
7. Validator 확인 후 시작

각 제약에는 다음이 보여야 한다.

- 영향을 받는 시스템 아이콘
- 정확한 효과
- 제약 점수
- 점수 배율
- 충돌하는 다른 제약
- 현재 스테이지에서 선택할 수 없는 이유

## 10. Validator 계약

제약 적용 후 다음을 다시 검증한다.

1. 첫 필수 건물을 건설할 자원과 시간이 남아 있다.
2. 첫 카운터 웨이브 전에 대응 수단을 확보할 수 있다.
3. 기본 포탑 사거리 계약이 유지된다.
4. 해금되지 않은 병종이나 특수 적이 필수 대응으로 요구되지 않는다.
5. 웨이브 전조와 실제 출격이 일치한다.
6. 식량·노드·건설 제약이 플레이 시작부터 소프트락을 만들지 않는다.
7. 총 위협량이 난이도와 제약 상한을 넘지 않는다.
8. 같은 입력은 같은 StageManifest를 만든다.

검증에 실패하면 해당 조합의 시작을 차단하고 이유를 표시한다. 자동으로 다른 제약으로 교체하지 않는다.

## 11. 추천 초기 콘텐츠 규모

첫 공개 프로토타입 추천:

- 전체 제약 10~12개
- 카테고리당 2~3개
- 1점 제약 4개 이상
- 2점 제약 4개 이상
- 3점 제약 2개 이상
- 개발자용 검증 프리셋 5개

프리셋 예시:

- 경제 압박
- 보급 압박
- 빠른 웨이브
- 전방 거점 방어
- 종합 고난도

## 12. 검증 시나리오

- 같은 시드·난이도·제약은 동일한 StageManifest를 만든다.
- 제약이 없는 스테이지와 있는 스테이지의 차이가 UI와 데이터에 일치한다.
- 금지 조합은 선택 즉시 차단되고 이유가 표시된다.
- 경제 제약을 적용해도 최소 한 가지 합법적인 시작 빌드가 존재한다.
- 특수 적 조기 등장 제약은 허용된 스테이지에서만 선택할 수 있다.
- 결과 화면에 난이도, 제약, 점수 배율과 클리어 기록이 표시된다.
- 제약 보상이 영구 전투력에 영향을 주지 않는다.

## 13. 사용자 조정이 필요한 핵심 항목

1. 제약을 튜토리얼 완료 직후 해금하는 안
2. 정규 스테이지 첫 도전부터 0~2점을 선택할 수 있게 하는 안
3. 첫 클리어 후 최대 5점, 어려움 클리어 후 최대 7점으로 확장하는 안
4. 초기 제약을 10~12개로 구성하는 안
5. 정보 숨김·일시정지 금지·철인 모드 제약을 프로토타입에서 제외하는 안
6. 보상은 점수·메달·기록 중심으로 하고 영구 전투력 보상을 제외하는 안
7. 불공정 조합은 자동 수정하지 않고 선택을 차단하고 이유를 표시하는 안

## 14. 승인 게이트

현재 상태는 `사용자 조정안 대기`다. 승인된 뒤 게임 기획서, StageManifest 계약과 후속 Codex Plan Mode 구현 제안서에 반영한다.
