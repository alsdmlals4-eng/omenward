# 제안서 0002 — 3시간 프로토타입 캠페인과 절차적 스테이지 생성기

- 상태: 사용자 조정안 대기
- 전제: `docs/design/APPROVED_MATCH_STRUCTURE.md`
- 구현 상태: 승인 전 구현 금지

## 1. 목적

첫 공개 프로토타입이 약 3시간의 플레이 분량을 제공하면서, 모든 스테이지의 맵·적 건물·웨이브·난이도 수치를 수작업으로 개별 코딩하지 않도록 한다.

생성기는 무제한 무작위 콘텐츠를 만드는 시스템이 아니라, **검증된 스테이지 부품과 규칙을 시드에 따라 조합하고 자동 검증하는 정적·결정론적 생성기**로 설계한다.

핵심 목표:

- 약 3시간의 캠페인 진행
- 같은 규칙 안에서 재도전 가치 제공
- 난이도별 수치와 구성 자동화
- 스테이지 제작자의 반복 작업 감소
- 같은 시드에서 동일 결과를 재현해 디버깅 가능
- 전조와 상성 대응이 불가능한 불공정 조합 방지

## 2. 추천 캠페인 구조

첫 프로토타입은 **6개 스테이지 안팎의 선형 캠페인**을 추천한다.

| 스테이지 | 목표 시간 | 학습·검증 역할 | 생성 복잡도 제한 |
|---|---:|---|---|
| 1. 개전 | 20~25분 | 건설, 토큰, 첫 룰렛, 한 라인 배치 | 한 라인 중심, 기본 검사 웨이브 |
| 2. 상성 | 25~30분 | 검사·기병·창병·궁병 상성 | 최대 두 라인 동시 압박 |
| 3. 삼중 전선 | 25~30분 | 세 라인과 접전지 경제 | 세 라인 활성, 특수 웨이브 없음 |
| 4. 전방 거점 | 30~35분 | 전방 시설 위험과 적 건물 파괴 | 시설 공격 웨이브 허용 |
| 5. 고티어 전쟁 | 30~35분 | Tier 2~3, 복합 웨이브 | 제한된 특수 웨이브 허용 |
| 6. 결전 | 35~40분 | 전체 시스템 종합 | 복합 압박과 최종 적 본진 |

예상 총량은 165~195분이며 튜토리얼, 결과 화면, 재정비 시간을 포함해 약 3시간을 목표로 한다.

정확한 스테이지 수보다 중요한 것은 각 스테이지가 새로운 규칙을 하나씩 추가하고, 이전 규칙을 다시 검증하는 것이다.

## 3. 생성 방식

### 3.1 생성 시점

- 스테이지 진입 전에 한 번 생성한다.
- 전투 중 맵 구조, 적 건물, 예정 웨이브를 몰래 바꾸지 않는다.
- 생성 결과는 `StageManifest`로 고정한다.
- 같은 시드와 같은 난이도는 항상 같은 스테이지를 만든다.
- 재도전 시 같은 시드 또는 새 시드를 선택할 수 있다.

### 3.2 생성 입력

```text
Campaign Seed
+ Stage Index
+ Stage Archetype
+ Difficulty Profile
+ Unlock State
+ Generator Rule Set Version
= Stage Manifest
```

플레이 기록에 따라 몰래 적을 강화하는 동적 난이도는 MVP에서 제외한다. 난이도 변화가 필요하면 캠페인 시작 또는 재도전 화면에서 명시적으로 선택한다.

### 3.3 생성 출력

`StageManifest`는 최소 다음 정보를 가진다.

```text
stage_id
seed
generator_version
stage_index
stage_archetype_id
difficulty_profile_id
map_template_id
lane_configs
player_start_config
enemy_building_configs
wave_schedule
capture_point_configs
unlock_rules
stage_modifiers
validation_result
```

## 4. 조합할 스테이지 부품

### 4.1 Stage Archetype

스테이지의 학습 목표와 허용 복잡도를 정한다.

예시:

- `opening_single_lane`
- `counter_training`
- `three_lane_control`
- `forward_outpost_pressure`
- `high_tier_escalation`
- `final_assault`

Archetype은 완전한 스테이지 데이터가 아니라 다음을 제한하는 규칙 묶음이다.

- 사용 가능한 병종과 건물
- 동시 압박 가능한 라인 수
- 적 건물 Tier 상한
- 특수 웨이브 허용 여부
- 목표 웨이브 수와 목표 시간
- 플레이어에게 처음 공개할 튜토리얼

### 4.2 Map Template

프로토타입에서는 완전 자유형 맵 생성보다 **검증된 맵 골격의 변형**을 사용한다.

고정 계약:

- 세 라인 유지
- 플레이어 후방 노드 6개 유지
- 라인별 전방 노드 3개 유지
- 라인별 중앙 접전지 1개 유지
- 본진 → 전방 거점 → 접전지 → 적 전방 거점 → 적 본진 순서 유지
- 기본 포탑은 접전지에 닿지 않음
- 승인된 고티어 사거리에서만 접전지 지원 가능

변형 가능 항목:

- 본진과 전방 거점 사이 거리
- 전방 거점과 접전지 사이 거리
- 라인별 이동 거리의 작은 차이
- 건물 노드의 시각적 배치
- 장식, 지형 테마, 경고 표현

이동 경로가 끊기거나 한 라인만 지나치게 짧아지는 변형은 금지한다.

### 4.3 Enemy Build Archetype

적 건물 구성의 전략적 성향이다.

예시:

- 보병 중심
- 기병 돌파
- 창병 방어
- 궁병 후방 화력
- 경제 성장
- 한 라인 전방 거점 강화
- 균형형

적 건물은 무작위로 하나씩 뽑는 것이 아니라 Threat Budget과 스테이지 역할에 맞춰 구성한다.

### 4.4 Wave Pattern Card

웨이브를 작은 패턴 단위로 작성하고 생성기가 배치한다.

예시:

- 한 라인 정면 공격
- 두 라인 분산 공격
- 약한 세 라인 압박
- 기병 돌격
- 원거리 후방 지원
- 시설 우선 공격
- 후방 침투
- 결전 웨이브

각 패턴은 다음을 가진다.

```text
allowed_stage_range
allowed_difficulties
threat_cost
required_enemy_buildings
forbidden_combinations
telegraph_type
unit_slots
lane_rules
```

### 4.5 Stage Modifier

프로토타입에서는 한 스테이지에 0~1개의 명확한 수정자만 허용한다.

후보:

- 시장 생산량 소폭 증가
- 접전지 수입 감소
- 건물 건설시간 증가
- 특정 라인의 이동거리 증가
- 적 특정 병종 Tier 상한 증가

플레이어가 시작 전에 수정자를 확인할 수 있어야 하며 숨은 규칙은 사용하지 않는다.

## 5. 난이도 자동화

### 5.1 Difficulty Profile

난이도는 하나의 피해 배율만 바꾸지 않고 여러 축을 제한된 범위에서 조정한다.

| 축 | 쉬움 | 보통 | 어려움 |
|---|---|---|---|
| 시작 경제 | 여유 | 기준 | 제한 |
| 적 Threat Budget | 낮음 | 기준 | 높음 |
| 웨이브 간격 | 김 | 기준 | 짧음 |
| 적 건물 Tier 상한 | 낮음 | 단계별 | 빠르게 상승 |
| 실패 복구 | 큼 | 기준 | 작음 |
| 전조 정보 | 정확 공개 | 정확 공개 | 정확 공개 유지 |

난이도가 높아져도 병종, 수량, 라인을 숨기지 않는다. 어려움은 더 높은 압박과 더 적은 여유를 의미하며 정보 부족을 의미하지 않는다.

### 5.2 Threat Budget

각 스테이지는 적 위협을 포인트 예산으로 관리한다.

```text
기본 위협 예산
+ 스테이지 진행 보정
+ 난이도 보정
+ 스테이지 역할 보정
= 전체 Threat Budget
```

생성기는 전체 예산을 다음에 배분한다.

- 적 건물 종류와 Tier
- 웨이브 수량
- 웨이브 빈도
- 다중 라인 압박
- 특수 웨이브
- 후반 압박 상승

한 축에 전체 예산을 몰아 불가능한 조합을 만들지 않도록 축별 상한을 둔다.

## 6. 공정성 제약

생성 결과는 다음 조건을 모두 통과해야 한다.

1. 첫 스테이지와 첫 웨이브는 한 라인 중심이다.
2. 첫 대응 웨이브 전에 필요한 카운터 훈련소를 건설할 시간과 금화가 있다.
3. 플레이어가 아직 해금하지 않은 병종을 필수 대응책으로 요구하지 않는다.
4. 전조에 표시한 라인·병종·수량은 실제 출격과 일치한다.
5. 기본 포탑은 중앙 접전지에 닿지 않는다.
6. 한 라인의 최단 이동시간이 다른 라인의 절반 이하가 되지 않는다.
7. 동시에 발생하는 위협의 총량이 해당 스테이지 Threat Budget을 넘지 않는다.
8. 후방 침투와 공성 웨이브는 해당 기능을 소개한 이후에만 등장한다.
9. 모든 스테이지에 최소 하나 이상의 현실적인 회복 경로가 있다.
10. 같은 시드의 생성 결과가 재현된다.

검증 실패 시 다른 부품을 다시 조합하며, 재시도 횟수 상한을 넘으면 수동으로 검증된 안전 스테이지를 사용한다.

## 7. 생성 파이프라인

```text
1. Stage Archetype 선택
2. Difficulty Profile 적용
3. 목표 시간과 Threat Budget 계산
4. Map Template 선택·거리 변형
5. 적 Build Archetype과 건물 배치
6. Wave Pattern Card로 웨이브 스케줄 작성
7. Stage Modifier 선택
8. 자동 Validator 실행
9. 실패 시 제한된 횟수만큼 재생성
10. StageManifest 저장 및 플레이 시작
```

## 8. 개발자 도구

생성기에는 플레이어용 화면과 별도로 개발자 확인 화면이 필요하다.

- 시드 직접 입력
- 스테이지 번호와 난이도 선택
- 생성 결과 JSON 또는 Resource 출력
- 맵 거리, 포탑 사거리, 적 건물과 웨이브 타임라인 표시
- Threat Budget 사용 내역 표시
- Validator 통과·실패 이유 표시
- 동일 시드 100회 재생성 일치 확인
- 다수 시드 일괄 생성 및 실패 목록 저장

이 도구는 스테이지 제작 자동화와 디버깅 효율에 직접 연결되므로 프로토타입 범위에 포함하는 것을 추천한다.

## 9. 프로토타입 범위 추천

무한 생성보다 작은 부품 세트를 안정적으로 조합하는 것이 우선이다.

초기 목표 가설:

- Stage Archetype 6개
- Map Template 3개
- Enemy Build Archetype 6개
- Wave Pattern Card 12~16개
- Stage Modifier 6~8개
- Difficulty Profile 3개
- 검증된 안전 시드 1개 이상/스테이지

이 숫자는 콘텐츠 제작량 추정을 위한 초기값이며 조정 가능하다.

## 10. 포함 범위

- 시드 기반 결정론적 생성
- 약 3시간 분량의 6스테이지 캠페인
- 스테이지 역할별 복잡도 제한
- 맵 골격 변형
- 적 건물과 웨이브 자동 구성
- 쉬움·보통·어려움 난이도 프로필
- Threat Budget
- 자동 공정성 검증
- 같은 시드 재도전
- 생성 결과 개발자 확인 도구

## 11. 제외 범위

- 전투 중 몰래 변하는 동적 난이도
- AI/LLM이 자유 형식으로 스테이지를 작성하는 기능
- 무제한 자유형 맵 지형 생성
- 절차적으로 새로운 병종·건물·스킬을 발명하는 기능
- 플레이어 행동을 실시간 분석해 카운터만 생성하는 적응형 치팅 AI
- 무한 캠페인과 영구 메타 성장
- 온라인 일일 시드와 순위표

## 12. 검증 시나리오

- 동일한 시드·난이도·버전으로 생성한 두 StageManifest가 동일하다.
- 서로 다른 시드가 허용 범위 안에서 다른 건물·웨이브 조합을 만든다.
- 모든 생성 스테이지에서 기본 포탑이 접전지에 닿지 않는다.
- 첫 카운터 웨이브 전에 필요한 대응 수단을 확보할 수 있다.
- 전조 정보와 실제 출격 구성이 일치한다.
- 해금되지 않은 병종이 필수 대응책으로 요구되지 않는다.
- 쉬움·보통·어려움의 Threat Budget과 경제 여유가 순서대로 변화한다.
- 생성 실패 시 안전 스테이지로 대체된다.
- 같은 시드 재도전과 새 시드 재도전이 각각 동작한다.

## 13. 사용자 조정이 필요한 핵심 항목

1. 첫 프로토타입을 **6개 스테이지, 약 3시간**으로 구성하는 안
2. 캠페인을 선형 진행으로 시작하고 분기 경로는 후속으로 미루는 안
3. 생성기를 전투 시작 전 고정되는 **정적·시드 기반 방식**으로 만드는 안
4. 난이도는 쉬움·보통·어려움 3단계로 시작하고 정보 공개량은 동일하게 유지하는 안
5. 완전 무작위 맵 대신 검증된 맵 골격 3개의 거리·배치 변형을 사용하는 안
6. 플레이 성적에 따른 숨은 동적 난이도는 제외하는 안
7. StageManifest와 Validator 개발자 도구를 프로토타입 필수 범위에 넣는 안
