# 제안서 0004 — 룰렛 결과 판정, 대기칸 부족과 럭키 찬스

- 상태: **사용자 조정안 대기**
- 구현 상태: 승인 전 구현 금지
- 관련 문서: `docs/GAME_DESIGN.md`, `docs/DECISIONS_PENDING.md`, `docs/design/DESIGN_FREEZE_CHECKLIST.md`

## 1. 목적

룰렛 회전의 시작부터 보상 정리까지의 상태 전이와 예외 처리를 고정한다.

특히 다음 상황에서 Codex가 임의 규칙을 만들지 않게 한다.

- 기준 줄 선택 시점
- 혼합 심벌 보상
- 별 단계와 병사·엘리트·영웅 품질의 관계
- 대기칸이 부족할 때의 보상 보존
- 금화 토큰의 무한 회전 방지
- 럭키 찬스의 확률, 실패 누적, 이동권과 확정 시점

## 2. 추천 핵심 결정

1. 기준 가로줄은 **회전 전에 선택하고 고정**한다.
2. 선택 줄의 모든 비-X 심벌 그룹은 동시에 보상한다.
3. 같은 심벌 수는 별 단계, 3개 일치 뒤의 완성 줄 수는 품질 단계를 결정한다.
4. 룰렛 보상은 대기칸이 아니라 먼저 `결과 보관함`에 생성한다.
5. 결과 보관함을 모두 정리하기 전에는 다음 회전을 할 수 없다.
6. 금화 토큰은 현재 회전 비용의 일부를 환급하며 100% 이상 돌려주지 않는다.
7. 럭키 찬스는 회전 결과 공개 뒤 보상 판정 전에 한 번의 순환 이동을 제공한다.
8. 자연 럭키 찬스와 이동권을 합쳐 한 회전에 최대 한 번만 이동한다.

## 3. 룰렛 상태 전이

```text
Idle
→ RowSelected
→ CostPaidAndSnapshotLocked
→ Spinning
→ BoardRevealed
→ LuckyDecision 또는 ResultLock
→ ResultLock
→ RewardResolution
→ RewardsPending 또는 Idle
→ Idle
```

### 3.1 회전 시작 조건

다음을 모두 만족해야 한다.

- 판정할 가로줄이 선택돼 있다.
- 현재 릴에 실제 토큰이 1개 이상 존재한다.
- 현재 회전 비용을 지불할 수 있다.
- 이전 회전의 결과 보관함이 비어 있다.
- 다른 회전이나 럭키 찬스 판정이 진행 중이지 않다.

실제 토큰이 0개라 각 릴이 `[X, X, X]`인 상태에서는 회전 버튼을 비활성화하고 `먼저 시장이나 훈련시설을 완공하세요`라고 안내한다.

### 3.2 기준 줄 선택

- 상단·중단·하단 중 하나를 회전 전에 선택한다.
- 비용을 지불하기 전에는 자유롭게 변경할 수 있다.
- 회전이 시작되면 해당 줄 번호가 고정된다.
- 럭키 찬스로 판을 이동해도 선택 줄 자체는 바뀌지 않는다.
- 회전 후 가장 좋은 줄을 새로 고르는 기능은 제공하지 않는다.

이 규칙은 결과를 보고 최선의 줄을 고르는 방식보다 건물 기반 확률 설계와 럭키 찬스의 가치를 유지한다.

## 4. 판 생성 규칙

### 4.1 회전 스냅샷

회전 비용을 지불한 순간 다음을 스냅샷으로 고정한다.

- 완공된 토큰 제공 건물 목록
- 릴별 실제 토큰 구성
- 부족분 X 토큰
- 현재 회전 비용
- 난수 시드와 회전 번호
- 선택된 가로줄

회전 도중 건물이 완공·파괴·철거돼도 현재 판에는 영향을 주지 않고 다음 회전부터 반영한다.

### 4.2 릴별 추출

각 세로 릴은 같은 구성의 독립 풀을 사용한다.

1. 완공 건물 기준 실제 토큰을 구성한다.
2. 실제 토큰이 3개 미만이면 X를 채운다.
3. 릴별로 독립 셔플한다.
4. 셔플된 풀에서 앞의 3개를 **비복원 추출**해 위·중간·아래 칸에 표시한다.

풀이 3개보다 크면 해당 회전에 보일 3개만 추출한다. 건물 여러 동이 만든 같은 종류의 중복 토큰은 서로 다른 풀 항목으로 취급한다.

## 5. 선택 줄 보상

### 5.1 그룹별 동시 보상

선택 줄의 X를 제외한 토큰을 종류별로 센다.

| 같은 토큰 수 | 보상 |
|---:|---|
| 1개 | 해당 종류 1성 보상 1개 |
| 2개 | 해당 종류 2성 보상 1개 |
| 3개 | 해당 종류 3성 보상 1개 + 추가 완성 줄 검사 |

서로 다른 토큰은 각각 보상한다.

예시:

```text
[검사, 검사, 금화]
→ 2성 검사 1개
→ 1단계 금화 환급
```

```text
[검사, 기병, 궁병]
→ 1성 검사 1개
→ 1성 기병 1개
→ 1성 궁병 1개
```

```text
[검사, X, 금화]
→ 1성 검사 1개
→ 1단계 금화 환급
```

X는 보상, 완성 줄, 별 단계에 포함하지 않는다.

### 5.2 별 단계와 품질 단계 분리

두 개념을 명확히 분리한다.

- **별 단계:** 선택 줄에서 같은 토큰이 몇 개 나왔는가
- **품질 단계:** 선택 줄 3개 일치 뒤 전체 판에서 같은 심벌 완성 줄이 몇 개인가

1개 또는 2개 일치 보상의 기본 품질은 병사다.

선택 줄에서 유닛 심벌 3개가 일치한 경우에만 전체 8개 줄을 검사한다.

```text
3개 가로줄
+ 3개 세로줄
+ 2개 대각선
= 총 8개 줄
```

- 선택한 기준 줄도 완성 줄 1개로 센다.
- 서로 겹치는 줄도 각각 센다.
- 선택 줄에서 3개가 일치한 유닛 심벌과 같은 심벌만 검사한다.
- 다른 심벌의 완성 줄은 무시한다.
- 기준 줄이 3개 일치가 아니면 다른 줄의 빙고도 무시한다.

| 같은 유닛 심벌 완성 줄 수 | 최종 품질 |
|---:|---|
| 1줄 | 병사 |
| 2줄 | 엘리트 |
| 3줄 이상 | 영웅 |

예시:

```text
선택 줄 검사 3개 + 전체 판 검사 완성 줄 2개
→ 3성 엘리트 검사 1개
```

프로토타입에서는 3줄 이상을 영웅으로 상한 처리한다. 원본 완성 줄 수는 결과 기록과 디버그 정보에 보존해 향후 전설·신화 조건에 사용할 수 있게 한다.

### 5.3 수동 합성 제외

첫 프로토타입에서는 대기칸의 같은 유닛을 자동 또는 수동으로 합쳐 별 단계를 올리는 기능을 넣지 않는다.

- 훈련시설이 생산한 1성 유닛은 개별 유닛이다.
- 룰렛에서 나온 2성·3성 유닛도 보상 단위 하나다.
- 같은 병종 여러 개를 보유해도 자동 합쳐지지 않는다.

합성은 룰렛의 같은 심벌 보상 가치를 흐릴 수 있으므로 후속 실험으로 분리한다.

## 6. 금화 토큰과 무한 회전 방지

금화 토큰은 고정 금액을 새로 생성하기보다 **실제로 지불한 현재 회전 비용의 일부를 환급**한다.

초기 밸런스 가설:

| 선택 줄 금화 수 | 환급 비율 |
|---:|---:|
| 1개 | 지불 비용의 20% |
| 2개 | 지불 비용의 45% |
| 3개 | 지불 비용의 75% |

```text
금화 보상 = floor(실제 지불한 회전 비용 × 환급 비율)
```

- 할인 후 실제 지불액을 기준으로 한다.
- 환급은 보상 확정 시 즉시 금화에 더한다.
- 금화 3개가 나와도 회전 비용 전액 이상을 돌려주지 않는다.
- 금화 심벌은 병사·엘리트·영웅 품질 검사를 하지 않는다.
- 다른 줄의 금화 빙고는 추가 금화를 주지 않는다.

따라서 시장 3개로 금화 심벌만 나오게 구성해도 룰렛 자체만으로 무한 회전할 수 없다. 시장의 지속 수입과 접전지 수입은 별도 경제 수단으로 유지한다.

정확한 환급 비율은 데이터로 조정하지만 `최대 환급률 < 100%` 계약은 유지한다.

## 7. 결과 보관함과 대기칸 부족

### 7.1 결과 보관함

최종 판정 뒤 유닛 보상은 바로 대기칸에 넣지 않고 `결과 보관함`에 생성한다.

- 선택 줄에는 최대 3종의 토큰이 있으므로 보관함은 최대 3개 보상 묶음을 표시한다.
- 금화는 즉시 환급하므로 보관함 슬롯을 사용하지 않는다.
- 결과 보관함이 남아 있는 동안 전투, 건설, 배치와 카메라는 계속 진행된다.
- 다음 룰렛 회전만 차단된다.
- 보상은 자동 폐기되거나 덮어쓰이지 않는다.

### 7.2 보상 묶음 처리 선택지

각 유닛 보상 묶음은 다음 중 하나로 정리한다.

1. 대기칸으로 이동
2. 선택한 라인에 즉시 출전
3. 금화로 판매

조건:

- 대기칸 이동은 빈 슬롯이 필요하다.
- 즉시 출전은 식량 한도와 출전 가능 상태를 만족해야 한다.
- 판매는 항상 가능해 보상 정리 소프트락을 방지한다.
- 결과 보관함의 모든 보상을 정리해야 다음 회전을 시작할 수 있다.

### 7.3 대기칸 계약

- 보상 묶음 1개는 별·품질과 관계없이 대기칸 1칸을 차지한다.
- 대기칸 보관 자체는 식량을 사용하지 않는다.
- 식량은 실제 라인 출전 시에만 사용한다.
- 식량이 부족해도 대기칸 보관과 판매는 가능하다.
- 대기칸이 가득 차도 이미 획득한 룰렛 보상은 결과 보관함에 안전하게 남는다.

초기 대기칸 용량 추천값은 **8칸**이다. 용량은 플레이테스트 데이터로 조정하되 제한된 공간과 결과 보관함 구조는 유지한다.

## 8. 럭키 찬스

### 8.1 발생 시점

- 3×3 판이 모두 공개된 뒤 판정한다.
- 최종 보상 계산 전이다.
- 자연 럭키 찬스가 발생하면 무료 이동 기회 1회를 제공한다.
- 발생하지 않았다면 보유한 이동권 1장을 사용할 수 있다.
- 한 회전에 자연 발생과 이동권을 합쳐 **최대 한 번만 이동**한다.

### 8.2 실패 누적 추천값

초기 데이터 가설:

```text
기본 확률: 12%
자연 실패 1회당: +8%p
6회 연속 자연 실패 후 다음 회전: 100% 확정
자연 발생 시: 기본 확률로 초기화
```

자연 발생 확률 예시:

```text
12% → 20% → 28% → 36% → 44% → 52% → 100%
```

- 확률은 UI에 공개한다.
- 자연 럭키 찬스가 제시되면 사용하지 않고 넘겨도 누적치는 초기화된다.
- 이동권 사용은 자연 발생으로 간주하지 않는다.
- 자연 발생에 실패한 회전에서 이동권을 사용해도 실패 누적치는 증가한다.
- 스테이지 시작 시 누적치는 0으로 초기화한다.

정확한 12%·8%p·6회 수치는 데이터 조정 대상이지만 `실패 누적 + 공개 확률 + 유한 횟수 내 확정` 구조는 고정한다.

### 8.3 이동권

- 상점에서 구매해 보관한다.
- 자연 럭키 찬스가 발생하지 않은 회전에서만 사용할 수 있다.
- 자연 럭키 찬스가 발생하면 이동권은 소비되지 않는다.
- 프로토타입 보유 상한 추천값은 3장이다.
- 이동권 가격과 상점 출현 빈도는 데이터로 조정한다.

### 8.4 허용 이동

정확히 하나를 선택한다.

- 가로줄 하나를 왼쪽으로 1칸 순환
- 가로줄 하나를 오른쪽으로 1칸 순환
- 세로줄 하나를 위로 1칸 순환
- 세로줄 하나를 아래로 1칸 순환

순환 이동이므로 밀려난 토큰은 반대편 끝으로 이동한다.

### 8.5 미리보기와 확정

- 행·열과 방향을 선택하면 이동 후 판을 미리 보여준다.
- 선택 줄에서 받을 별 보상과 완성 줄 수를 함께 미리 보여준다.
- 확정 전에는 다른 행·열·방향으로 바꾸거나 원본 판으로 취소할 수 있다.
- `확정` 후에는 되돌릴 수 없다.
- 럭키 찬스를 사용하지 않고 원본 판을 확정할 수 있다.
- 별도의 시간 제한은 두지 않는다. 전투는 계속 진행되며 플레이어는 필요하면 일시정지를 사용할 수 있다.

최종 확정 뒤 보상을 한 번만 계산한다. 이동 전 보상과 이동 후 보상을 중복 지급하지 않는다.

## 9. 전체 회전 예시

```text
1. 중단 기준 줄 선택
2. 회전 비용 지불
3. 완공 건물과 토큰 풀 스냅샷
4. 세 릴 독립 셔플·3개 추출
5. 3×3 판 공개
6. 자연 럭키 찬스 판정
7. 선택적으로 행·열 1칸 순환
8. 최종 판 고정
9. 중단의 비-X 토큰을 그룹별 계산
10. 유닛 3개 일치가 있으면 8개 줄 검사
11. 금화 환급 즉시 적용
12. 유닛 보상을 결과 보관함에 생성
13. 이동·즉시 출전·판매로 보관함 정리
14. 다음 회전 가능
```

## 10. UI 필수 정보

룰렛 패널에 다음을 표시한다.

- 현재 선택 줄
- 현재 회전 비용
- 현재 토큰 수와 칸당 확률
- X 토큰 수
- 자연 럭키 찬스 현재 확률과 확정까지 남은 실패 횟수
- 보유 이동권 수
- 결과 보관함 미정리 개수
- 회전 불가 이유

럭키 찬스 미리보기에는 다음을 표시한다.

- 이동 전·후 선택 줄
- 예상 유닛 별 단계
- 예상 품질과 완성 줄 수
- 예상 금화 환급

## 11. 검증 시나리오

- 실제 토큰 0개에서는 회전할 수 없다.
- 선택 줄은 비용 지불 뒤 변경할 수 없다.
- `[검사, 검사, 금화]`가 2성 검사와 1단계 금화 환급을 만든다.
- `[검사, 기병, 궁병]`이 세 개의 1성 보상 묶음을 만든다.
- X는 어떤 보상이나 완성 줄에도 포함되지 않는다.
- 기준 줄 3개 일치가 없으면 다른 줄의 빙고가 있어도 품질이 올라가지 않는다.
- 완성 줄 3개 이상은 프로토타입에서 영웅으로 상한 처리된다.
- 대기칸이 가득 차도 보상이 사라지지 않는다.
- 결과 보관함이 남아 있으면 다음 회전만 차단된다.
- 식량 부족 상태에서도 대기칸 보관과 판매가 가능하다.
- 금화 3개 결과의 환급이 실제 지불 비용보다 작다.
- 같은 회전에 자연 럭키 찬스와 이동권을 중복 사용할 수 없다.
- 이동 미리보기 취소 후 원본 판을 확정할 수 있다.
- 확정 뒤 보상은 정확히 한 번만 지급된다.
- 자연 럭키 찬스 실패 누적과 초기화가 데이터 규칙대로 동작한다.

## 12. 사용자 조정이 필요한 핵심 항목

1. 기준 줄을 회전 전에 선택·고정하는 안
2. 혼합 심벌을 종류별로 모두 보상하는 안
3. `별 단계`와 `병사·엘리트·영웅 품질`을 별도 축으로 유지하는 안
4. 결과 보관함을 두고 미정리 중 다음 회전만 차단하는 안
5. 대기칸 초기 추천값 8칸과 수동 합성 제외
6. 금화 환급 비율 20% / 45% / 75% 기본안
7. 럭키 찬스 12% 시작, 실패당 +8%p, 7번째 적격 회전 확정 기본안
8. 자연 발생과 이동권을 합쳐 회전당 이동 1회 제한
9. 럭키 찬스 선택에 시간 제한을 두지 않는 안
