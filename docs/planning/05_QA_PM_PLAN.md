- 책임 팀: **QA(품질 관리)·PM(프로젝트 관리)**
- 갱신일: 2026-07-17
- 상태: **자동 기준선 통과 / 1920×1080·1280×720 수동 QA 미실행 / 예산 미정**
- 적용 범위: 자동·수동·시각·오디오·성능 QA, 버그 등급, 완료·릴리스 게이트, 일정·위험·예산, 협업·인수인계

이 문서는 무엇이 검증됐고 무엇이 아직 가정인지 한눈에 보여 주는 활성 책임 원본이다. QA는 실제 증거 없이 `통과`를 기록하지 않으며, PM은 확정되지 않은 일정·예산을 만들지 않는다.

## 1. 품질 원칙

- 확정, 구현, 자동 검증, 수동 검증, 미확정을 구분한다.
- 재현 절차·환경·예상·실제 결과·증거가 없는 버그 보고는 완료되지 않았다.
- 문서 변경도 제품 변경이다. 다섯 본책, 링크, 이미지 안정 경로를 검증한다.
- 규칙 변경은 게임 본책, 구현 변경은 프로그래밍 본책, 시각·사운드 변경은 각 본책과 함께 검증 상태를 갱신한다.
- 실패한 테스트를 임시 제외하거나 기대값을 근거 없이 바꿔 통과시키지 않는다.

## 2. 자동 QA 기준선

저장소 루트에서 Godot 실행 경로를 환경에 맞게 지정한다. 현재 테스트 파일은 `tests/headless/*_test.gd` 6종이다.

```powershell
& $Godot --headless --editor --path . --quit
if ($LASTEXITCODE -ne 0) { throw "Editor import failed" }
Get-ChildItem tests/headless/*_test.gd | ForEach-Object {
  & $Godot --headless --path . --script $_.FullName
  if ($LASTEXITCODE -ne 0) { throw "Headless test failed: $($_.Name)" }
}
& $Godot --headless --path . --quit-after 1
if ($LASTEXITCODE -ne 0) { throw "Runtime smoke failed" }
git diff --check
powershell -ExecutionPolicy Bypass -File tools/validate_documentation.ps1
```

새 체크아웃에서는 전역 클래스 캐시 생성을 위해 editor import를 headless 테스트보다 먼저 실행한다. 변경 위험에 따라 관련 단위 테스트를 추가 실행할 수 있지만, PR 완료 전에는 editor import·6종 전체·runtime smoke·문서 검증을 모두 실행한다.

## 3. 수동 플레이 QA

### 공통 환경

- Windows PC, 마우스·키보드.
- 1920×1080과 1280×720 각각 별도 실행.
- 새 게임에서 튜토리얼 4단계와 W1~20 핵심 진행을 확인한다.
- 캡처에는 해상도, 빌드·커밋, 시나리오, 결과를 함께 기록한다.

### 필수 시나리오

1. 건물 선택·건설 노드 배치·자원 차감·생산 완료.
2. 3×3 룰렛 회전·감속·결과·보관·라인 이동.
3. 상·중·하단 독립 이동과 접전지 전투.
4. 중간거점 점령 시 건설권·자원 생산권 이전.
5. 4개 우회로와 중앙 교차 구간에서 침투 병력 교전.
6. 성문 피해·돌파 후 본진과 본진 건물 공격.
7. W5·W10·W15·W20 위협 단계와 승리·초과전 흐름.
8. 벨루 안내, 경고, 반복 방지와 UI 가림 여부.

## 4. 시각·UI QA

- 전장 인게임 기준 이미지와 실제 화면의 구조적 의도를 비교하되 이미지 자체를 토폴로지 계약으로 사용하지 않는다.
- 세 라인의 상태, 성문, 중간거점, 접전지, 건설 노드, 우회로 입출구가 줌 수준별로 읽혀야 한다.
- 1280×720에서 텍스트 잘림, 패널 겹침, 룰렛 칸 축소, 벨루 대화창 가림을 우선 확인한다.
- 아군·적군, 병종, 등급, 공격 전조를 색상 하나에 의존하지 않고 구분한다.
- 생성 이미지는 크롭·배경·알파·색공간·픽셀 그리드·명칭을 후처리하고 실제 엔진 삽입으로 승인한다.
- 최신 공식 이미지와 권리·교체 상태는 `../images/VISUAL_REFERENCE_INDEX.md`에서 확인한다.

## 5. 오디오 QA

- 전조음이 판정음보다 먼저 들리고 실제 이벤트 타이밍과 일치하는지 확인한다.
- 거점 점령, 성문 위기, 암살자 침투, 자원 부족이 혼전에서도 구분되는지 확인한다.
- 동일 SFX 동시 재생 제한과 장시간 반복 피로를 확인한다.
- BGM·SFX·음성 볼륨 분리, 자막·시각 대체 신호를 확인한다.
- 최종 자산이 없는 항목은 `미실행` 또는 `임시 자산`으로 기록한다.

## 6. 성능·결정론 QA

- 정상 목표: 지상 120, 비행 24, 투사체 160, VFX 80.
- 하드 상한: 지상 200, 비행 40, 투사체 260, VFX 140.
- 목표·상한 각각에서 프레임 시간, 메모리, 타기팅·오라·점령 갱신 병목을 계측한다.
- 같은 시드·데이터·입력의 룰렛, 웨이브, 전투 결과가 재현되는지 확인한다.
- 측정 환경과 결과가 없으면 `성능 통과`로 기록하지 않는다.

## 7. 버그 등급과 처리

| 등급 | 정의 | 예시 | 게이트 |
|---|---|---|---|
| Blocker | 실행·저장·핵심 진행 불가 | 부팅 실패, 웨이브 진행 중단 | 즉시 중단·수정 |
| Critical | 핵심 규칙·데이터 무결성 붕괴 | 자원 복제, 라인 규칙 위반, 결정론 실패 | 병합 금지 |
| Major | 주요 기능·가독성·성능 저하 | 720p UI 가림, 거점 상태 오표시 | 릴리스 전 수정 |
| Minor | 우회 가능하고 영향이 제한적 | 사소한 정렬·문구·비핵심 연출 | 기록 후 우선순위 결정 |

모든 이슈에 환경, 커밋, 재현 단계, 예상, 실제, 빈도, 증거, 영향 분야, 회귀 테스트를 기록한다.

## 8. PM 운영과 문서 갱신 주기

```text
작업 영향 분야 선택
→ 관련 본책과 부록 확인
→ 승인 범위에서 구현·제작
→ 자동·수동 검증
→ 영향 받은 본책·검증 상태·최신 이미지 갱신
→ Active Context·Handoff에는 현재 상태와 읽기 순서만 연결
```

- Issue와 PR에는 게임·프로그래밍·아트·사운드·QA·PM 영향 체크와 갱신 본책을 적는다.
- 작업 종료 시 문서 영향이 없으면 이유를 명시한다.
- 일정은 다음 게이트와 의존성 중심으로 관리하며 확인되지 않은 날짜를 확정 일정처럼 쓰지 않는다.
- 예산은 인건비·외주·라이선스·음성·마케팅 등 항목만 준비하고 승인 전 금액은 `미정`으로 둔다.
- 이미지와 음원은 출처, 승인일, 용도, 권리, 교체 필요 여부를 기록한다.
