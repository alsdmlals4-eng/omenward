# 오멘워드 버티컬 슬라이스 적대적 검토

- 검토일: 2026-07-27
- 검토 대상: 최신 사용자 승인안과 main의 활성 V2 문서
- 검토 상태: `DESIGN_REVIEW_COMPLETE / DOCUMENT_SYNC_IN_PROGRESS`
- 제품 코드: 변경하지 않음

이 검토는 설계가 그럴듯한지를 평가하는 문서가 아니라, 서로 다른 문서와 상태 전이가 실제 구현에서 충돌·악용·손실·비결정성을 만들 수 있는지를 공격적으로 확인한 기록이다.

## 1. 판정 기준

| 등급 | 의미 | 반영 조건 |
|---|---|---|
| BLOCKER | 서로 양립할 수 없는 정본 또는 구현 불가능한 계약 | 반드시 해소 |
| CRITICAL | 경제 붕괴, 무한 증식, 저장 손상, 원자성 위반 | 반드시 해소 |

## 3. BLOCKER 검토

### B-01. 3스테이지 최소 슬라이스와 20스테이지 전체 시스템 슬라이스 충돌

**공격:** 기존 PROJECT_CORE와 GDD는 대표 병종 2~4종, TokenSource 2종, 일반 2 + 위험 1스테이지를 첫 슬라이스로 정의한다. 최신 사용자 지시는 코어 PoC를 건너뛰고 20스테이지, 미션, 메타, 저장, 전체 주요 시스템을 포함한다.

**결과:** 두 범위를 동시에 정본으로 둘 수 없다.

**해소:** 최신 사용자 지시를 우선해 `FULL_SYSTEM_VERTICAL_SLICE / MINIMUM_CONTENT_BREADTH`를 정본으로 승격한다. 기존 3스테이지 범위는 과거 제안으로 남기고 활성 목표에서 제거한다.

### B-02. 전장 토폴로지 충돌

**공격:** 기존 문서는 라인당 중앙 접전지 하나만 활성 코어로 설명하고 중간 거점은 후속 재평가 대상으로 둔다. 최신 계약은 아군 중간 거점 → 중앙 경합 지역 → 적 중간 거점을 필수 경로로 사용한다.

**해소:** 최신 5구간 라인 구조와 전체 30개 건설 노드를 정본으로 고정한다. legacy 중간거점 상태기와 `capture_power` 합산은 재사용하지 않는다.

### B-03. 건물 파괴·재건 계약 충돌

**공격:** 기존 V2 문서에는 파괴 건물 재건, 성문 BREACHED, 30초 재건, 작업자 임금이 남아 있다. 최신 계약은 HP 0 즉시 제거, 노드 EMPTY, 잔해·재건 없음, 작업자 없음이다.

**해소:** 일반 건물의 재건·잔해·작업자·글로벌 수리 예산을 폐기한다. 제품 구현 전 legacy 계약은 `SUPERSEDED`로 취급한다.

### B-04. 저장 범위 충돌

**공격:** 기존 문서는 첫 수직 슬라이스에서 mid-run save를 지원하지 않는다. 최신 범위는 저장과 메타를 포함한다.

**해소:** 활성 전투 임의 프레임 저장은 제외하고, 준비 화면 진입과 스테이지 정산 완료 시 versioned checkpoint를 지원한다. 안전 경계 저장이므로 전투 중간 복원 비결정성을 피하면서 20스테이지 런 지속성을 검증한다.

## 4. CRITICAL 검토

### C-01. 금고의 경제 이중·삼중 증폭

**공격:** 금고 Tier가 골드/초, 금화 토큰 보상액, 상위 금화 변형 선택 가중치를 모두 올리면 금고 투자 수익이 중첩 폭증한다.

**해소:** 금고 Tier는 지속 골드/초만 강화한다. 금화 토큰은 모든 Tier에서 같은 `[금화]` 심벌이며 보상은 실제 회전 비용의 75/200/500% 규칙을 사용한다. 금화 변형 Tier 선택은 없다.

### C-02. 금화 기대수익을 제외한 비용표 고정

**공격:** 기존 `100/140/180골드`, `24/29/35초`는 금화 토큰의 기대수익을 포함하지 않았다. 그대로 고정하면 업그레이드 회수기간이 의도보다 짧아질 수 있다.

**해소:** 해당 값은 시뮬레이션 입력용 잠정값으로 강등한다. 유료 회전 비용, 무료 회전 기준가, 초기 릴, 금고 수량을 포함한 100,000시드 경제 시뮬레이션 뒤 확정한다.

### C-03. TokenSource 정의가 병영 전용으로 남는 문제

**공격:** 기존 문서에서 TokenSource는 사실상 병영을 뜻한다. 최신 계약에서는 금고도 토큰을 공급한다. 타입을 병영으로 하드코딩하면 금고 토큰 생명주기가 누락된다.

**해소:** `TokenSource`를 건물 종류가 아니라 기능 계약으로 정의한다. 금고는 GOLD TokenSource, 병영은 UNIT TokenSource다. 물리 노드 결속 슬롯과 비활성화 거래를 공통 사용한다.

### C-04. 점령 시 양측 토큰·수입 동시 활성

**공격:** 금고 소유권, 골드/초, 플레이어 릴 토큰을 따로 갱신하면 한 틱 동안 이전 소유자와 새 소유자가 동시에 효과를 받을 수 있다.

**해소:** 건물 생존 확정 → 거점 소유권 이전 → 건물 소유권 이전 → 기존 소유자 토큰 비활성화 → 새 소유자 효과 재결속을 하나의 원자 거래로 처리한다. 플레이어가 소유권을 잃으면 즉시 X로 복구한다.

### C-05. 수리가 파괴를 취소하는 동일 틱 부활

**공격:** 수리를 피해보다 먼저 적용하거나 HP 0 뒤 수리를 허용하면 파괴된 건물이 같은 틱 부활한다.

**해소:** 피해 → HP 반영 → 파괴 확정 → 생존 건물 수리 순서로 고정한다. 커밋된 파괴를 수리가 취소할 수 없다.

### C-06. 한 건물 수리 작업 무한 중첩

**공격:** “여러 개 수리 가능”을 한 건물에 여러 수리 작업으로 해석하면 골드만큼 순간 HPS를 무한 확장할 수 있다.

**해소:** 건물당 활성 수리 작업 하나, 전역 동시 수리 건물 수는 무제한으로 정규화한다.

### C-07. SpinSnapshot 이후 source 제거가 보상 변조

**공격:** 금고·병영 파괴가 이미 멈춘 보드의 후보 풀까지 바꾸면 같은 입력에서 보상이 달라진다.

**해소:** SpinSnapshot은 exact reward 후보와 출처 정보를 불변으로 보존한다. live 릴 변경은 다음 스핀부터만 반영한다.

## 5. MAJOR 검토

### M-01. 보관·판매 담당 건물 삭제로 시스템 누락

**공격:** 시장·창고 건물을 제거하면서 보관·판매까지 제거될 위험이 있다.

**해소:** 보관함과 판매는 플레이어 공통 런 UI로 유지한다. 건물 5종 제한과 시스템 포함을 동시에 만족한다.

### M-02. 지휘소가 파괴 불가능한 전역 버프가 되는 문제

**공격:** 비전투 건물인 지휘소가 강한 전역 오라를 주면 상대는 거점 전체를 점령하기 전까지 대응할 수 없다.

**해소:** 기본 지휘소는 지역 원형 오라다. 돌격/수비 분기 모두 제한 반경을 사용한다. 전역 효과는 기본 건물 계약에서 제외한다.

### M-03. 지휘소 다중 중첩 폭증

**공격:** 여러 지휘소가 공격속도·이동속도·방어력을 무제한 합산하면 노드 수가 곧 지수적 전투력으로 전환된다.

**해소:** 같은 계열은 최고 Tier 하나만 적용하고, 서로 다른 돌격·수비 계열만 공존한다.

### M-04. 타워 분기가 역할 중복 또는 만능화

**공격:** 단일 타워가 단일·광역·대공을 모두 잘하면 분기 의미가 없고 방어 정답이 된다.

**해소:** 연사탑은 지상·비행 단일 대상, 포격탑은 지상 광역으로 분리한다. Tier 3은 메커니즘을 추가하지 않고 선택 계열만 강화한다.

### M-05. 병영의 Tier 3 선형화 오해

**공격:** “Tier 2 분기, Tier 3 선형 강화”를 병영에도 적용하면 이미 승인된 각 Tier 2 병종의 두 Tier 3 전문화와 충돌한다.

**해소:** 해당 지시는 타워와 지휘소에 적용한다. 병영은 T2 10병종, T3 각 2전문화를 유지한다.

### M-06. noncombat 건물 면역으로 공격 규칙 혼동

**공격:** 비전투 건물은 직접·부수 피해 면역이지만 점령 후 이전된다. 플레이어가 왜 타워만 공격 가능한지 이해하기 어렵다.

**해소:** 건물 패널과 전술 오버레이에서 `전투 구조물 / 점령 구조물` 태그를 명시한다. 타워는 HP로 제거 가능, 나머지는 거점 점령으로 제어권을 바꾼다.

### M-07. 호위병 광역 피해 분담 급사

**공격:** 호위병 자신과 주변 다수 아군이 같은 광역 피해를 받으면 자기 피해 + 모든 25% 분담으로 급사한다.

**판정:** 의도된 카운터로 수용한다.

**안전장치:** 같은 피해 이벤트에서 가장 가까운 호위병 하나만 선택하고, 동일 틱에 이미 배정된 분담은 일괄 처리한다. 중첩·재귀·분할은 금지한다. 수치 QA에서 광역 대상 수별 생존시간을 필수 측정한다.

### M-08. 철벽수호병 3단계의 완전 강제 이동 면역

**공격:** 보스 기믹까지 면역이면 스테이지 패턴을 무효화한다.

**해소:** 일반 전투 밀치기·끌기·띄우기에만 면역이다. 순간이동, 위치 교환, 보스·시스템 재배치는 적용되며 성공 시 철벽 0단계로 초기화한다.

### M-09. 철벽수호병 자동 추격이 자기 능력을 제거

**공격:** 일반 근접 AI를 사용하면 적의 작은 이동마다 철벽이 해제된다.

**해소:** 0단계 정상 추적, 1단계 2.5D, 2단계 1.25D, 3단계 추적 없음으로 고정한다.

### M-10. 방패병 우선도로 전문 적 정체성 소멸

**공격:** 모든 적이 방패병을 우선하면 암살·대공·공성 역할이 작동하지 않는다.

**해소:** 공통 점수식에 전문 프로필 음수 보정을 추가한다. 여러 조건이 겹쳐도 가장 강한 보정 하나만 적용한다.

### M-11. 표적 재평가 핑퐁

**공격:** 거리와 상태를 매 틱 계산하면 표적이 계속 바뀌고 공격이 취소된다.

**해소:** 공격 주기를 커밋하고 종료 시점에만 재평가한다. 새 표적은 20% 이상 우수해야 전환한다. 사망·무효·도달 불가만 즉시 전환한다.

### M-12. 벨루가 플레이를 방해하거나 숨은 자동결정을 만드는 문제

**공격:** 조언이 자동 팝업·일시정지·자동 선택을 사용하면 플레이어 책임을 약화한다.

**해소:** 자동 조언은 한 문장 비상호작용, 팁은 수동 비모달 패널이다. 추천은 최대 2개, 결정론적 이유와 단점을 제시하고 자동 선택하지 않는다.

## 6. 동일 시각 거래 회귀 표

| 사건 조합 | 확정 순서 |
|---|---|
| 건물 피해 + 수리 | 피해 → 파괴 확정 → 생존 시 수리 |
| 건설 완료 + 같은 시각 피해 | 진행 반영 → HP/피해 반영 → 생존 확정 → 생존 시 효과·토큰 활성 |
| TokenSource 파괴 + SpinSnapshot | 기존 snapshot 불변, live 슬롯만 X 복구 |
| 거점 점령 + 건물 파괴 | 해당 시각 진행·피해·파괴 확정 뒤 남은 건물만 이전 |
| 거점 점령 + TokenSource | 기존 소유 토큰 해제 → 소유권 이전 → 호환성에 따라 재활성 또는 BLOCKED |
| 철벽 피해 + 예외 재배치 | 재배치 전 단계로 피해 계산 → 재배치 커밋 → 0단계 초기화 |
| 호위병 분담 + 호위병 사망 | 틱 시작 배정 고정 → 동일 틱 분담 전부 처리 → 사망 확정 |
| 업그레이드 취소 + 점령 | 해당 시각 우선 사건 ID와 거래 잠금으로 하나만 커밋, 다른 요청 재검증 |

구현 계획에서 사건 우선순위와 transaction id를 명시적 테스트로 고정해야 한다.

## 7. 경제 적대 시뮬레이션 요구

최종 비용 고정 전 최소 다음 축을 100,000시드 이상 검증한다.

- 금고 0~최대 노드 수.
- 금고 Tier 분포.
- 금화 토큰 수와 X 수.
- 무료·유료 회전 비율.
- 가로·세로 이동 구매.
- 금화 1/2/3+ 완성선 발생률.
- 판매·보관·배치 선택.
- 중앙 경합 지역 0~3개 수입.
- 동시 수리 건물 수.
- 병렬 업그레이드 수.

필수 실패 탐지:

- 골드 기대값이 스핀 비용보다 지속적으로 높은 양의 무한 루프.
- 금고를 더 지을수록 회수기간이 단조롭게 0에 수렴하는 현상.
- 수리를 켠 상태에서 골드가 음수가 되거나 무료 회복이 발생하는 현상.
- 판매만 반복하는 전략이 배치보다 항상 우월한 현상.
- 초기 X 비율 때문에 진행 불가능 또는 확정적 폭증이 발생하는 현상.

---

## 8. 저장 적대 검토 요구

checkpoint는 다음 중간 실패를 견뎌야 한다.

- 파일 쓰기 도중 종료.
- 스키마 버전 불일치.
- 토큰 source lifecycle 중복 이벤트.
- 점령 거래 직전·직후 저장.
- 업그레이드 에스크로와 자금 제공자 불일치.
- PendingReward와 live 릴 불일치.
- BLOCKED 건물과 소유권 불일치.

권장 방식은 임시 파일 작성 → 검증 → 원자 교체 → 이전 정상본 보존이다. 상세 포맷은 구현 계획에서 결정한다.

## 10. 최종 결론

정본 충돌, 경제 이중 증폭, TokenSource 타입 누락, 수리 부활, 저장 범위 충돌은 문서 계약 수준에서 해소했다. 남은 항목은 주로 수치·콘텐츠·스키마 상세다.
