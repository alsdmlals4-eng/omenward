# Issue #69: [V2 Plan Mode][R1+R2] 중앙 판정 보존 seam·물리 릴 순수 도메인

## Issue body
## 상태

```text

CODEX_PLAN_MODE_INPUT: READY
```

이 Issue는 Codex Plan Mode의 읽기 전용 조사와 제안서 작성을 위한 입력이다. 사용자 승인 전에는 게임 코드·Scene·Resource·데이터·workflow를 수정하지 않는다.

## 목표

검증된 Legacy C1 중앙 판정·완성선·등급·금화·결정론을 순수 `RouletteBoardResolver` seam으로 보존하고, V2의 세 원형 릴·토큰 인스턴스·불변 `SpinSnapshot`·최소 `SpinSession` 상태 경계를 경제·건물·UI·보상 지급과 분리해 설계한다.

## 플레이어 가치

이번 패키지는 화면 기능을 늘리는 작업이 아니다. 이후 플레이어가 건물과 가로 이동으로 미래 룰렛을 설계할 수 있도록, 기존 당첨 판정을 잃지 않는 안전한 기반과 재현 가능한 물리 릴 상태를 만든다.

## 권장 아키텍처

```text
Legacy RouletteService orchestration
├─ economy / buildings / manifest / input log
├─ legacy 9-cell generation — 이번 패키지에서 유지
├─ legendary state / reward creation — 이번 패키지에서 유지
└─ RouletteBoardResolver — 순수 중앙 판정 seam

V2 isolated pure domain
RouletteTokenInstance
→ RouletteReelState × 3
→ RouletteRunState
→ RouletteSpinSnapshot
→ RouletteSpinSession
```

### 핵심 경계

- `RouletteService.spin()`의 Legacy 9칸 생성 경로는 이번 패키지에서 V2 릴로 교체하지 않는다.
- `StageRun`·건물 이벤트·경제·UI·보관·판매·배치에는 V2 릴 상태를 연결하지 않는다.
- 새 V2 도메인은 직접 headless test에서만 생성·검증한다.
- `RouletteBoardResolver`는 경제·UI·전설 사용 상태·보상 저장을 소유하지 않는다.
- 기존 `roulette_contract_test.gd`의 관찰 결과를 삭제하거나 완화하지 않는다.

## 포함 범위

### R1 — Resolver preservation seam

- 중앙 가로줄 선행 판정
- 8개 완성선 계산
- 1 / 2 / 3~7 / 8선 등급
- 금화 75% / 200% / 500%
- 동일 입력·시드의 출처 선택 결정론
- `RouletteService`의 resolver 위임 adapter
- 기존 C1 결과 불변 테스트

### R2 — Physical reel pure domain

- `RouletteTokenInstance`
- 길이 3 이상 원형 `RouletteReelState`
- 정확히 세 릴을 소유하는 `RouletteRunState`
- 전역 token instance ID 유일성
- 길이 3·4·N wrap 노출
- cursor 정규화
- 가장 낮은 안정 index의 `NORMAL_X` 교체
- `NORMAL_X`가 없을 때 append
- `SOURCE_BOUND_X`를 일반 교체에서 제외하는 타입 경계
- 동일 상태·시드의 동일 정지 시작 index
- 깊은 복사 불변 `RouletteSpinSnapshot`
- snapshot의 3×3 row-major board projection
- live run과 분리된 최소 `RouletteSpinSession` 상태

## 제외 범위

- TokenSource 완공·파괴·blocked 동기화

- 보관·판매·배치·식량

## Codex Plan Mode 필수 조사

1. 실제 클래스·preload·typed Array 패턴을 확인한다.
2. resolver 추출 후에도 현재 C1 테스트와 validator가 어떤 최소 변경을 요구하는지 제시한다.
3. 새 도메인 타입을 `RefCounted`와 `Resource` 중 어디에 둘지 비교하고 권장안을 선택한다.
4. token ID 생성 책임을 이번 패키지에서 만들지, 호출자가 주입할지 결정 근거를 제시한다.
5. snapshot 불변성을 GDScript에서 어떻게 강제·검증할지 제시한다.
6. `SpinSession`의 최소 상태가 R4 거래를 선행 구현하지 않도록 인터페이스를 제한한다.
7. `.github/workflows/validate-omenward-core.yml`, `tools/validate_c1_roulette.py`, Python mutation test의 변경 영향을 확인한다.
8. 단계별 Red→Green→Refactor와 독립 커밋 순서를 제시한다.
9. 롤백 시 Legacy C1 실행 경로가 즉시 복구되는 방식을 제시한다.

- [ ] 공개 메서드 시그니처와 typed 반환값이 제시된다.

- [ ] R2 invariant와 반례 테스트가 구체적으로 제시된다.
- [ ] Legacy 실행 경로와 V2 격리 도메인의 연결 금지선이 명시된다.
- [ ] 정적 validator·Python mutation·Godot headless·import·전체 회귀 명령이 제시된다.
