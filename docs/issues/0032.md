# Issue #32: [Proposal][Vertical Slice] 공용 병종·3라인 핵심 루프 Plan Mode

## Issue body
## 현재 상태

**수직 슬라이스 Plan Mode 준비 / 공용 10병종·진영별 Visual Set 계약 반영 / Phase 0 완료 전 구현 금지**

이 Issue는 Issue #1의 Phase 0 구현이 완료된 뒤 실제 파일·명령을 확인하고 Codex Plan Mode 제안서를 작성하기 위한 실행 기준이다.

## 목표

```text
베일의 징조
→ 건설
→ 룰렛
→ 공용 병종 배치
→ 3라인 교전
→ 접전지·중간거점 점령
→ 암살자 우회
→ 성문 공성
→ 스테이지 승리
```

## 공용 병종 불변 조건

```text
UnitArchetypeProfile × 10
+ TierProfile
+ RankProfile
+ owner_team_id
+ FactionVisualProfile
```

- 대표 archetype을 아군·적군 Visual Set으로 각각 생성한다.
- 능력치·스킬·타기팅·상태·판정 타이밍은 동일하다.
- 적군 전용 UnitProfile, Unit Scene, 스탯·스킬·AnimationContract를 만들지 않는다.
- 웨이브는 공용 `archetype_id`에 enemy 팀과 veil Visual Set을 지정한다.
- `visual_faction_id`는 능력치와 판정을 바꾸지 않는다.

## 승인된 전장 초기값

- 중간거점: 중립화 10초 + 점령 10초, 최대 점령력 2.0, 안정화 5초, 금화 +2/30초.
- 성문: HP 5,000, 방어·마저 80, 일반 구조물 피해 40%, 공성 200%, 붕괴 2초.
- 암살자: 진입 1초, 이동 9초, 도착 2.5초 전 경고, 출현 준비 0.6초.

## 최소 모션

```text
deploy
idle
move
attack_basic
skill_1 또는 역할 행동
hit_light
death
capture 또는 점령 대기
victory
```

- 암살자: `bypass_enter`, `bypass_exit`.
- 공성 역할: `structure_attack`.
- 양 진영 시트는 상태·프레임·피벗·접촉·투사체 이벤트를 공유한다.
- 공격은 준비→판정→회복, 오차 한 프레임 이내.

## Plan Mode에서 제안할 구현 묶음

1. 3라인 그레이박스와 이동 그래프.
2. 성문 6개와 독립 HP·붕괴.
3. 중간거점·접전지 상태 머신.
4. 전방 2·후방 1 노드와 최소 건물 2종.
5. 거점 건설권·생산권 이전.
6. 최소 3×3 룰렛과 공용 archetype 결과 생성.
7. 공용 Unit Scene과 대표 archetype 3~5종.
8. 대표 archetype의 아군·적군 Visual Set.
9. 최소 적 웨이브와 베일의 징조.
10. 암살자 안개 우회.
11. 공격 판정·애니메이션 이벤트 동기화.
12. 성문 붕괴·점령·승리 연출.
13. 디버그 오버레이와 결정론적 재현.
14. 데이터·Visual 호환·headless·수동 검증.

## 제외 범위

- 공용 10병종 전체와 모든 Rank 스킬.
- 별도 적군 10병종 데이터·모션 제작.
- 전체 W1~20.
- 모든 Tier 3.
- 최종 UI·아트·음악·성우.
- 전체 양 진영 Visual Set.
- 암살자 탐지 건물.
- 성문 수리·재건.

## 제안서 완료 기준

- 실제 파일·Scene·Resource·Signal 구조가 명시된다.
- 공용 Unit Scene과 데이터 주입 흐름이 있다.
- 적군 데이터 복제를 막는 검증이 있다.
- 양 Visual Set의 상태·프레임·피벗·이벤트 호환 검사가 있다.
- 작은 구현 단계와 관찰 가능한 결과가 있다.
- 자동·수동·모션 가독성·성능 검증이 있다.
- 사용자 승인 요청과 범위 밖 항목이 명확하다.

사용자 승인 전 구현 브랜치·커밋·PR을 만들지 않는다.
