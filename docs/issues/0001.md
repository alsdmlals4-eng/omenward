# Issue #1: [Plan Mode Ready][Phase 0] 새 Codex 채팅용 Godot·공용 병종 데이터 작업 패키지

## Issue body
## 현재 상태

**새 Codex 채팅용 Work Order 준비 완료 / Codex Plan Mode 실행 대기 / Codex 제안서 미제출 / 구현 금지**

이번 Issue의 다음 행동은 구현이 아니다. 새 Codex 채팅에서 저장소를 읽기 전용으로 조사하고 Phase 0 구현 제안서를 제출하는 것이다.

## 시작 문서

- 작업 요청·복사 프롬프트: `docs/work_orders/0001-phase-0-codex-plan-mode.md`
- Goal: `docs/goals/0001-engine-selection-and-bootstrap.md`
- 제안 형식: `docs/PROPOSAL_WORKFLOW.md`
- 기획 측 사전 기술 추천안: `docs/design/proposals/0001-phase-0-godot-bootstrap.md`

사전 기술 추천안은 Codex가 작성한 최종 Plan Mode 제안서가 아니다. Codex는 실제 저장소, Base, urban-legend와 공식 Godot 근거를 확인해 채택·수정·기각 이유를 제시한다.

## 새 Codex 채팅에서 할 일

1. Work Order의 시작 프롬프트를 읽는다.
2. Handoff·Documentation Map·GDD·관련 APPROVED·Roadmap·Goal을 읽는다.
3. 현재 `main`의 실제 구현 파일·경로·테스트·명령을 조사한다.
4. Base의 공용 방법과 urban-legend의 실제 Godot 사례에서 채택·제외할 요소를 분석한다.
5. `docs/design/proposals/0001-phase-0-godot-bootstrap.md`의 사전 추천을 비판적으로 검토한다.
6. `docs/PROPOSAL_WORKFLOW.md` 형식으로 Codex Plan Mode 제안서를 제출한다.
7. 사용자 승인 전 구현하지 않는다.

## 승인된 데이터 불변 조건

```text
UnitArchetypeProfile × 10
+ TierProfile
+ RankProfile
+ owner_team_id
+ FactionVisualProfile
```

- 아군·적군은 능력치·스킬·타기팅·점령·구조물 피해·AnimationContract를 공유한다.
- 별도 `EnemyUnitProfile`, 적군용 Unit Scene, 적군 전용 전투 데이터·모션 상태 머신을 만들지 않는다.
- 차이는 팀, 출격 방식과 이미지·초상화·아이콘·팔레트·표시명이다.
- 일반 적 웨이브는 공용 `archetype_id`를 참조한다.
- W15·W20 보스는 공용 base archetype + BossBehaviorPackage + BossPhaseProfile + 전용 Visual Set이다.

## Codex가 계획해야 하는 작업 묶음

- 현재 공식 Godot stable 버전·renderer·CLI.
- 1920×1080 출력, 내부 해상도·stretch·픽셀 QA.
- 최소 Scene·Script·Resource·Data·Test 구조.
- Main·GameSession·Clock·Determinism·Registry의 상태 소유.
- AutoLoad 미사용 추천과 대안.
- 공용 UnitArchetype·Tier·Rank·FactionVisual·AnimationContract.
- BattlefieldProfile·StageManifest·Boss package의 Phase 0 범위.
- Resource·JSON·CSV 경계.
- AnimatedSprite2D·AnimationPlayer와 판정 이벤트 책임 분리.
- active combat tick·planning·seed·RNG stream·input log.
- 적군 데이터 복사, Visual 불일치, 전장 계약을 막는 validator.
- headless·수동 검증과 Goal 0002 인수인계.

## 이번 채팅의 제외 범위

- `project.godot`, Scene, GDScript, Resource, 데이터, 테스트와 자산 생성·수정.
- 구현 브랜치·커밋·Pull Request.
- 실제 전투·룰렛·건설·점령·성문·우회로·웨이브 구현.
- 최종 스프라이트·애니메이션·VFX·오디오.
- 적군 전용 병종 데이터·Scene·모션.

## Codex 제안서 완료 기준

- 실제 저장소와 참고 자료 근거가 있다.
- 사전 추천의 채택·수정·기각 이유가 있다.
- 예상 파일·Scene·Resource·상태 소유가 명확하다.
- 공용 10병종·진영별 Visual Set 계약을 유지한다.
- 적군 데이터 복제를 막는 자동 검증이 있다.
- 단계별 구현 결과와 headless·수동 검증이 있다.
- 위험과 사용자 결정 요청이 분리된다.
