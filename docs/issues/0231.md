# Issue #231: [Asset Coverage] Audit current screen and image consumers

## Issue body
Implement the user-approved screen-first image coverage contract.\n\nScope:\n- Separate runtime, production-reference, and release images.\n- Derive coverage from actual Godot scenes, resource consumers, states, and expression method.\n- Add a machine-checkable audit for existing current runtime image consumers.\n- Do not generate duplicate raster assets where procedural Godot/theme expression is the active consumer.\n\nAcceptance:\n- All current consumer-bound PNG paths resolve.\n- Unit state fallback coverage is verified.\n- Planned but unimplemented screens are explicitly deferred, not misclassified as missing runtime assets.
