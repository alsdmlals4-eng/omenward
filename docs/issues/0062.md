# Issue #62: [GitHub Pro Pilot] solo-main-safety Ruleset·ci-gate·자동 병합 적용

## Issue body
# 목적

GitHub Pro 비공개 저장소 시범 적용 대상으로 `omenward`에 Base의 저장소 보호·자동 병합 계약을 적용한다.

Base 정책 준비 Branch:
- `alsdmlals4-eng/Base:gpt/github-pro-governance-20260724`
- 정본: `docs/GITHUB_PRO_OPERATING_POLICY.md`
- Ruleset Template: `templates/project-operations/github/rulesets/solo-main-safety.json`

# 확인된 현재 상태

- Repository visibility: `private`
- Default branch: `main`
- 현재 Workflow: `.github/workflows/validate-omenward-core.yml`
- PR fast job: `contracts_pr`
- Godot job: `godot`
- main/manual full matrix: `contracts_full`
- PR concurrency `cancel-in-progress: true` 적용됨
- 현재 안정된 통합 Required Check `ci-gate`는 없음
- 현재 Repository의 `Allow auto-merge`·Ruleset 상태는 도구로 확인하지 못했으므로 `UNVERIFIED_REPOSITORY_SETTING`

# 선행 작업

Ruleset을 먼저 active로 만들면 존재하지 않는 `ci-gate` 때문에 `main` 병합이 차단될 수 있다. 다음 순서를 지킨다.

1. 현재 Workflow를 변경 위험별로 재검수한다.
2. PR에서 항상 종료되는 `ci-gate`를 추가한다.
3. Godot 변경 시 `contracts_pr`·`godot`, 비-Godot 계약 변경 시 필요한 정적 Job이 `ci-gate`에 반영되는지 검사한다.
4. `ci-gate`가 실제 PR에서 success인 것을 확인한다.
5. Repository Settings → General → Pull Requests → `Allow auto-merge`를 활성화한다.
6. Base의 `solo-main-safety.json`을 Repository Ruleset으로 import한다.
7. 대상 `~DEFAULT_BRANCH`, approval 0, conversation resolution, squash, strict `ci-gate`, deletion·force-push 차단을 확인한다.
8. Pilot PR을 Draft 해제하고 `AUTO_MERGE_ELIGIBLE` 판정 뒤 auto-merge를 활성화한다.
9. Required Check 통과 후 실제 자동 병합 증거를 기록한다.

# 자동 병합 허용 조건

- [ ] PR이 Draft가 아님
- [ ] 검수 HEAD SHA와 현재 HEAD SHA 일치
- [ ] `PACKAGE_APPROVED` 또는 `PACKAGE_APPROVED_WITH_TECHNICAL_CHANGES`
- [ ] `ci-gate` success
- [ ] unresolved review thread 0
- [ ] `USER_REVIEW_REQUIRED` 없음
- [ ] `CHANGE_PROPOSAL` 없음
- [ ] Repository `Allow auto-merge` 확인
- [ ] `solo-main-safety` Ruleset active 확인

# 자동 병합 차단

- `USER_REVIEW_REQUIRED`
- `CHANGE_PROPOSAL`
- `REVISE`
- `BLOCKED`
- `UNVERIFIED`
- `UNVERIFIED_REPOSITORY_SETTING`
- Required Check 실패·취소·미실행

# 롤백

1. Ruleset을 disabled로 전환한다.
2. Auto-merge를 비활성화한다.
3. Pilot PR을 Draft로 되돌린다.
4. `ci-gate`와 조건부 Job 결과를 대조한다.
5. 직접 Push로 우회하지 않고 Workflow 또는 Ruleset 설정을 수정한다.

# 완료 조건

- [ ] `ci-gate`가 실제 PR에서 success
- [ ] Repository Governance Profile 작성
- [ ] `Allow auto-merge` verified enabled
- [ ] `solo-main-safety` verified active
- [ ] Pilot PR 실제 자동 병합
- [ ] Actions 사용량과 실행 시간 기록
- [ ] 다른 프로젝트로 확산 가능 여부 판정
