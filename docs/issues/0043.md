# Issue #43: [UX] Implement approved battlefield and roulette dock vertical slice

## Issue body
﻿## Goal
Implement the approved Omenward in-game vertical slice: a readable independent three-lane battlefield and the fixed bottom dock with an interactive 3?3 roulette.

## Design intent
The player reads three isolated lanes at a glance: Lumen gate ? Lumen outpost with node markers ? center clash zone ? Veil outpost ? Veil gate. The dock order is fixed as `roulette / tactical skill / shop / Bellu guide`. Supplied visual sheets are art-direction reference only; no extraction or copying into shipping assets.

## Scope
- Replace the battlefield graybox presentation with three independent tactical lanes, gates, outposts, node markers, and clash zones.
- Replace raw `Spin (20)`, `Tower`, and `Farm` controls with the fixed four-section dock.
- Make the roulette use the existing StageRun spin/deploy contracts: 20 Gold, exactly nine stored results, repeat spin locked while results remain, and one result consumed per lane deploy.
- Hide stage selection after a stage starts.
- Add focused visual/roulette contracts and update active UX/QA publications.

## Exclusions
- No final sprite extraction from reference sheets; no new units, economy, stage-content, or combat-rule changes.
- Tactical skill and shop services are not implemented by this issue; the UI states this explicitly.
- Node click ? build list ? building installation is a follow-up interaction slice, not a hidden immediate-build button.

## Acceptance
- A player can read and use spin ? inspect nine results ? choose lane ? deploy from the visible HUD.
- No cross-lane road is drawn; all three lanes expose their intended landmarks.
- Existing headless suite stays green and dedicated UI visual/interaction contracts pass.
- Manual 1920?1080 / 1280?720 play QA remains marked `[???]` until performed.
