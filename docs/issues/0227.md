# Issue #227: [Visual Coverage] Audit target screen surfaces and asset consumers

## Issue body
## Goal
Establish a screen-first, consumer-grounded visual coverage audit for the current Run Command vertical slice.

## Scope
- Inventory every target-build screen, focus state, overlay, transition, and relevant non-applicable family.
- Map each surface to existing runtime consumers, approved assets, screen-level references, technical evidence, and bounded gaps.
- Preserve the distinction between `SCREEN_DESIGN_REFERENCE`, runtime assets, Godot/procedural UI, and no-new-image-required surfaces.
- Record five adversarial passes and handoff-ready, non-generative next actions.

## Exclusions
- No image generation, no visual asset approval/promotion, and no Godot gameplay or balance changes.
- No inference of consumers for title, settings, save/load, or future progression screens.

## Acceptance
- P0/P1/P2 and not-applicable families are explicit.
- The matrix links actual scene/node consumers and evidence.
- Gaps are requirement/defer records, not automatic production work.
- Repository and human-facing Notion summary are synchronized with readback.
