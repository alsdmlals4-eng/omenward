# Issue #105: UX-VALIDATION-001: V2 3라인·릴·배치 UX 검증 준비

## Issue body
# 목적

OMENWARD V2의 위협 예고→릴 설계→비가역 배치→전투→복기 흐름을 구현 전에 검증 가능한 fixture와 사람 테스트 계약으로 고정한다.

- 실행 계획: `docs/superpowers/plans/2026-07-29-ux-ui-validation-plan.md`
- UX 책임 원본: `docs/UX_UI_SYSTEM.md`
- 상위 제품 Issue: #69
- 현재 상태: `BLOCKED_BY_V6_PLANNING_GATE`
- Work Mode: `PLAN`
- 실행 프로필: `PLANNING_ONLY_PROFILE`
- 제품 코드 승인: `NO`

# 현재 수행 범위

- [ ] 단일 즉시 위험 라인 fixture
- [ ] 두 라인 위험 시점 비교 fixture
- [ ] 비용·제약·기대 효과가 상충하는 릴 후보 fixture
- [ ] 자원 부족·배치 불가·토큰 충돌 fixture
- [ ] 실행 전 되돌리기와 커밋 뒤 비가역 배치 fixture
- [ ] 예상과 실제 결과가 달라지는 전투 사건 fixture
- [ ] 긴 한국어·최대 수치·모달·누락 자산 fixture

# 사람 테스트 기준

- 신규 플레이어 5명, 10~15분 과제
- 5명 중 4명 이상이 최우선 위협과 선택 비용을 설명
- 5명 중 4명 이상이 배치 취소 가능 시점과 비가역 시점을 구분
- 5명 중 4명 이상이 패배 원인을 다음 릴·배치 변경과 연결
- 1920×1080·1280×720에서 위험·비용·입력 상태가 겹치거나 잘리지 않음
- 키보드·마우스·게임패드로 준비→배치→실행→복기 완주

# 제품 변경 허용 조건

1. v6 기획 완료와 사용자 승인
2. `PRODUCT_CODE_AUTHORIZED: YES` 전환
3. 별도 Codex Goal·구현 Issue 승인
4. 실제 V2 Scene·View Data·Signal 소유자 읽기 전용 조사 완료

# 완료 기준

- [ ] fixture와 검증 패킷이 사용자 승인됨
- [ ] Legacy C1·C2·C3를 V2 통과 증거로 사용하지 않음
- [ ] 자동·런타임·입력·사람 증거를 독립 상태로 보고할 계약이 확정됨

# 금지

- UI에서 위협 우선순위·시너지·피해·배치 가능성 재계산
- Legacy 구현을 V2 검증 완료로 표현
- 사용자 승인 전 Codex Build
- 제품 코드·Scene·data·asset 선행 변경
- HTML 기획 대시보드 추가
