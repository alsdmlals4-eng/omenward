## 2. 제품 약속

### 한 문장

> 건물을 지어 룰렛 확률과 증원 체계를 설계하고, 베일의 징조로 예고된 공세를 세 전선에서 뒤집는 판타지 전략 오토배틀 게임.

### 핵심 플레이 경험

플레이어는 다음 공세의 라인과 위협 태그를 미리 읽고, 제한된 금화·식량·건설 노드 안에서 건물과 룰렛 확률을 설계한다. 룰렛으로 획득한 병력을 원하는 라인에 배치하고, 거점·성문·암살자 우회로를 이용해 예고된 위기를 역전한다.

### 핵심 루프

```text
베일의 징조 확인
→ 건물·토큰·전술 선택
→ 3×3 룰렛
→ 병력 획득·라인 배치
→ 3라인 교전
→ 접전지·중간거점 공방
→ 암살자 우회 또는 성문 공성
→ 다음 공세 준비
```

### 첫 10분 약속

- 세계관과 전선 위기를 짧게 이해한다.
- 건설→룰렛→배치→역전을 두 번 체험한다.
- 한 번의 이동권 조작으로 상위 등급의 강함을 체감한다.
- 방패병·대검전사·암살자 중 첫 전문화를 선택한다.
- 설명보다 행동과 즉시 반응으로 시스템을 학습한다.

## 3. 변경 시 사용자 승인이 필요한 불변 구조

### 전장

```text
아군 본진
→ 라인별 아군 성문
→ 아군 중간거점
→ 중앙 접전지
→ 적 중간거점
→ 라인별 적 성문
→ 적 본진
```

- 좌우 대칭의 독립된 상·중·하 3라인.
- 일반 유닛의 라인 간 횡단과 기본 라인 변경 없음.
- 각 라인에 독립 성문 1개씩, 진영당 총 3개.
- 각 중간거점에 전방 건설 노드 2개와 후방 노드 1개.
- 중간거점 점령 시 건설권과 기본 생산권 이전.
- 중앙 접전지는 다른 라인과 연결되지 않고 건설 불가.
- 암살자는 적 후방 직접 배치가 아니라 같은 라인의 안개 우회로 사용.
- 전장이 기본 전략 화면에 들어오므로 미니맵 없음.

책임 원본: `docs/design/APPROVED_BATTLEFIELD_TOPOLOGY_AND_SCALE_V1.md`

### 병종과 데이터

- 전투 규칙 기준 병종은 공용 아키타입 10개뿐이다.
- 아군 10병종과 적군 10병종의 별도 스탯·스킬·애니메이션 데이터 세트를 만들지 않는다.
- 같은 공용 병종 데이터에 아군 이미지 세트 또는 적군 이미지 세트를 연결한다.
- 아군과 적군의 차이는 소유 팀, 출격 방식, 이미지·초상화·아이콘·표시명이다.
- 일반 적군의 난이도는 수량, Tier, 등급, 라인 편성, 출격 시점으로 만든다.
- W15·W20 보스는 공용 아키타입에 BossBehaviorPackage와 전용 Visual Set을 추가한다.

책임 원본: `docs/design/APPROVED_SHARED_UNIT_ARCHETYPE_AND_FACTION_VISUAL_DATA_V1.md`

### 등급과 Tier

- 플레이어 등급: 일반·엘리트·영웅·전설.
- 플레이어 신화급 없음.
- 적군 신화는 W20 보스 전용 패키지.
- Tier는 생산시설·병종 전문화, 등급은 룰렛 결과와 스킬 성장.

### 문서와 구현

- 한 주제당 활성 책임 원본 하나.
- 이전 버전은 일반적으로 Git 이력에서 보존.
- 코드·Scene·Resource·데이터 구조 변경은 Plan Mode 제안서 승인 후 시작.
- 문서 승인 상태를 구현 완료로 보고하지 않는다.

## 4. 승인된 수직 슬라이스 전장 초기값

### 중간거점

```text
중립화 10초 + 점령 10초 at 점령력 1.0
최대 유효 점령력 2.0
진행 유지 3초
복귀 초당 10%
점령 완료 후 안정화 5초
소유 수입 금화 +2 / 30초
```

점령력:

- 방패·수호형 1.25.
- 일반 근접·기병 1.0.
- 원거리·지원·거인 0.5.
- 암살자·비행·순수 공성 병기 0.

처리:

- 점령 시도 중 생산·신규 건설·업그레이드 정지.
- 중립화 시 기존 건물 비활성.
- 점령 완료 시 기존 건물 폐허화, 환불 없음.
- 5초 안정화 후 새 소유자의 건설·생산 활성.

### 성문

```text
HP 5000
방어 80
마법저항 80
일반 구조물 피해 40%
공성 태그 피해 200%
고정 피해 50%
붕괴 2초
```

- 아군 통과, 적은 파괴 전까지 차단.
- 군중제어·밀쳐내기·비율 피해 면역.
- 폐허는 길을 막지 않음.
- 수직 슬라이스에서 수리·재건 없음.

### 암살자 우회

```text
진입 준비 1초
오프맵 이동 9초
도착 2.5초 전 수비 경고
출현 후 준비 0.6초
적 중간거점에서 본진 방향 120 units
도착 영역 160 × 120 units
막힘 보정 반경 80 units
점령력 0
```

- 진입 확정 후 취소·후퇴 불가.
- 우회 중 전투·피격·점령·버프 없음.
- 경로는 암살자 선택·배치 중에만 표시.
- 탐지 전용 건물은 수직 슬라이스 제외.

위 수치는 PoC 초기값이며 플레이테스트 근거로 같은 구조 안에서 조정할 수 있다.

## 5. 공용 10병종

### 기본 병영 6종

1. 방패병 — 전열·원거리 대응.
2. 대검전사 — 정면 범위·파쇄.
3. 암살자 — 안개 우회로와 후열 제거.
4. 창병 — 돌진·대형 저지.
5. 궁병 — 지속 원거리·대공.
6. 기병 — 기동·돌진·후열 압박.

### 특수병단 4종

1. 사제 — 치유·전투 지원.
2. 마법사 — 광역 마법·제어.
3. 비행병 — 지상 전열 우회·후열 압박.
4. 거인 — 대형 범위·방어·공성.

### 아군·적군 표현

```text
공용 UnitArchetype
+ TierProfile
+ RankProfile
+ owner_team_id
+ visual_faction_id
```

- 아군과 적군은 같은 능력·수치·타이밍을 사용한다.
- 적군은 베일종 이미지 세트와 표시명을 사용한다.
- 웨이브는 공용 `archetype_id`를 참조한다.
- 별도 `EnemyUnitProfile`을 만들지 않는다.

## 6. 애니메이션·전투 연출 계약

### 공통 필수 상태

```text
deploy
idle
move
attack_basic
skill_1
hit_light
death
victory
```

추가:

- 점령 가능 병종: `capture`.
- 암살자: `bypass_enter`, `bypass_exit`.
- 기병: `charge`, `turn_recover`.
- 비행병: 상승, 순항, 급강하, 회복.
- 거인: `structure_attack`, `heavy_stagger`.

### 핵심 원칙

- 공격은 준비→판정→회복으로 구분.
- 무기 접촉·투사체 발사와 실제 판정은 한 프레임 이내로 동기화.
- 이동 위치는 코드가 소유하며 애니메이션 루트 모션으로 결정하지 않음.
- 가벼운 연속 피격은 큰 경직 대신 짧은 플래시·미세 반동.
- 공용 아키타입 하나의 상태·프레임·이벤트 계약에 아군·적군 이미지 시트를 각각 맞춘다.
- 적군 모션을 별도 상태 머신이나 별도 타이밍 데이터로 제작하지 않는다.

### 승리 연출

- 개별 처치: 별도 승리 모션 없음.
- 웨이브 정리: 0.4~0.8초 무기 정리.
- 거점 점령: 참여 유닛 0.6~1.0초 확인 동작.
- 성문 파괴: 0.5초 이내 짧은 반응.
- 스테이지 승리: 2.5~4.0초 병종별 승리 시퀀스→벨루→결과 UI.

책임 원본: `docs/design/APPROVED_UNIT_ANIMATION_AND_BATTLE_PRESENTATION_GUIDE_V1.md`

## 7. UI·아트 방향

- 기준 출력 1920×1080, 내부 960×540 정수 확대 후보.
- 기본 전략 줌에서 양측 본진과 세 라인 전체 확인.
- 미니맵 대신 실제 전장 위 성문·거점·접전지 상태 표시.
- 클린 전술 픽셀 + 미니어처 치비 비율 + 고해상도 픽셀 재질 완성도.
- 병종은 얼굴보다 무기, 자세, 몸통, 이동 리듬으로 식별.
- 아군·적군은 같은 병종 데이터와 모션 계약을 쓰되 이미지 실루엣과 소재는 다르게 제작.
- 색상만으로 진영·등급·병종을 구분하지 않음.
- 생성형 이미지는 탐색용이며 최종 자산은 픽셀 그리드·손·무기·관절·광원 검수 필수.

## 9. 현재 실행 순서

### Gate 1 — Phase 0 제안서

책임: Issue #1, Goal 0001.

Codex Plan Mode에서 다음을 제안한다.

- 정확한 Godot stable 버전.
- 해상도·stretch·Camera2D 정책.

### Gate 2 — Phase 0 구현

승인된 범위만 브랜치와 PR로 구현한다.

완료 조건:

- 빈 프로젝트 headless 로드.
- 데이터 참조 검증.
- 동일 시드 재현 골격.
- 공용 아키타입과 진영 비주얼 분리 골격.
- 수직 슬라이스가 사용할 실제 파일 경로 확정.

### Gate 3 — 수직 슬라이스 제안서

책임: Issue #32, Goal 0002.

- 3라인 그레이박스.
- 성문, 중간거점, 접전지.
- 최소 건설·경제·룰렛.
- 암살자 우회.
- 공용 아키타입을 양 진영 이미지로 생성.
- 대표 이동·공격·피격·사망·승리 모션.
- 자동·수동 검증.

사용자 승인 전 구현 금지.

### Gate 4 — 핵심 수직 슬라이스

10~15분 플레이에서 핵심 루프와 가장 위험한 가정을 검증한다. 20병종·전체 캠페인·최종 아트는 범위 밖이다.

## 10. 수직 슬라이스 대표 제작 범위

공용 데이터 아키타입 기준으로 다음 역할을 우선한다.

- 전열: 방패병 또는 검사형.
- 원거리: 궁병.
- 침투: 암살자.
- 지원: 사제.
- 공성: 거인 또는 공성 더미.

각 아키타입은 아군 이미지 세트와 적군 이미지 세트로 최소 한 번씩 생성해 데이터 공유를 검증한다.

최소 모션:

```text
deploy
idle
move
attack_basic
skill_1 또는 역할 행동
hit_light
death
capture 또는 점령 대기
victory
```

암살자는 우회 진입·출현, 공성 역할은 구조물 공격을 추가한다.

## 11. 구현 전 반드시 확인할 미확정

Phase 0에서 결정:

- Godot 정확한 stable 버전.
- 내부 논리 해상도와 stretch.
- AnimatedSprite2D, AnimationPlayer 또는 조합 구조.
- Resource·JSON·CSV 사용 경계.
- 아틀라스, 피벗, 프레임·이벤트 검증 방식.
- 시간축과 히트 스톱 분리.

PoC·플레이테스트에서 조정:

- 유닛·건물·룰렛·웨이브 수치.
- 점령·성문·우회 시간과 대응성.
- 애니메이션 FPS와 정확한 프레임 수.
- 카메라 흔들림·히트 스톱 강도.
- 최종 팔레트·스프라이트·아이콘·오디오.

장기 콘텐츠에서 결정:

- 최종 적군 표시명과 보스 고유명.
- 전체 캠페인 대사와 스테이지 보스.
- 성문 수리·재건.
- 암살자 탐지 건물.
- 전체 Tier 3와 최종 밸런스.

## 12. Base 공용 지식 사용

Base 저장소는 프로젝트 규칙보다 낮은 공용 참고자료다.

- 인수인계: `Base/docs/knowledge/methods/PROJECT_HANDOFF_CONTEXT_METHOD.md`
- 아트 디렉션: `Base/docs/knowledge/methods/ART_DIRECTION_METHOD.md`
- 애니메이션·연출: `Base/docs/knowledge/methods/ANIMATION_AND_PRESENTATION_METHOD.md`
- 조사·벤치마킹: `Base/docs/knowledge/research/DESIGN_RESEARCH_AND_EVIDENCE_METHOD.md`
- 실무 검수: `Base/docs/knowledge/skills/`
- 일반화된 프로젝트 사례: `Base/docs/knowledge/cases/`

적용 순서:

```text
오멘워드 최신 사용자 결정·책임 문서
→ 현재 Issue·Goal
→ 실제 파일
→ Base 공용 방법·스킬·사례
→ 외부 벤치마킹
```

Base의 사례와 방법을 그대로 복제하지 않고 오멘워드의 화면·성능·데이터 요구에 맞게 사용한다.

## 13. 하지 말아야 할 것

- 적군 10병종의 별도 스탯·스킬·애니메이션 데이터 제작.
- 아군 Scene을 복사해 Enemy Scene으로 분기하고 같은 필드를 중복 소유.
- 미니맵 추가.
- 암살자 적 후방 직접 생성.
- 라인 간 일반 횡단로 추가.
- 중간거점 노드를 전방 2·후방 1 외 구조로 변경.
- 일반 공격마다 큰 화면 흔들림·히트 스톱 사용.
- 전설 등급을 크기와 발광만으로 표현.
- 문서의 PoC 수치를 최종 밸런스로 고정.
- 승인 없이 Godot 코드·Scene·Resource 생성.
- Base 또는 벤치마킹 자료가 최신 사용자 결정을 덮어쓰게 함.

## 14. 콜드 스타트 확인 질문

새 작업자는 문서를 읽고 10분 안에 다음을 답해야 한다.

2. 현재 코드를 바로 수정해도 되는가?
3. 다음 작업은 Issue #1과 #32 중 무엇인가?
4. 전장 불변 구조는 무엇인가?
5. 아군과 적군은 몇 개의 전투 병종 데이터를 사용하는가?
6. 적군과 아군의 차이는 어디에 저장하는가?
7. 암살자 우회로와 성문의 초기값은 무엇인가?
8. 애니메이션 판정은 어떻게 동기화하는가?
9. 어떤 수치는 PoC 조정 가능하고 어떤 구조는 승인 대상인가?

정확히 답하지 못하면 이 문서와 Documentation Map의 링크·상태·용어를 먼저 보강한다.
