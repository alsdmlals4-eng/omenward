# 오멘워드 문서 생명주기 규칙

- 상태: **프로젝트 문서 운영 기준**
- 작성일: 2026-07-17
- 적용 범위: `README.md`, `AGENTS.md`, `docs/`, Issue·Goal의 기획 정보

이 규칙의 목적은 같은 내용을 여러 파일에서 반복 수정하는 일을 줄이고, 작업자가 항상 최신 승인본만 읽게 하는 것이다.

## 1. 기본 원칙

- 한 주제에는 활성 책임 원본을 하나만 둔다.
- 사용자가 새 결정을 확정하면 책임 원본을 같은 경로에서 갱신한다.
- 활성 폴더에 `_v2`, `_최종`, `_최종수정`, `_new`, `_copy` 같은 중복 파일을 만들지 않는다.
- 과거 버전의 기본 백업은 Git 커밋 이력이다.
- 새 문서를 추가하기 전에 기존 책임 원본을 수정할 수 있는지 먼저 확인한다.
- 관련 없는 문서를 관성적으로 모두 수정하지 않고, 충돌을 없애는 데 필요한 최소 문서만 갱신한다.

## 2. 문서 우선순위

```text
사용자의 최신 승인 지시
→ docs/planning/ 5개 활성 본책
→ 관련 APPROVED 상세 부록
→ DOCUMENTATION_MAP.md
→ HANDOFF_CONTEXT·ACTIVE_CONTEXT
→ DECISIONS_PENDING
→ 작업 제안서·Issue·Goal
→ archive와 과거 Git 이력
```

같은 내용이 충돌하면 상위 문서를 기준으로 하위 문서를 바로 동기화하거나, 하위 문서의 중복 설명을 삭제하고 책임 원본 링크로 교체한다.

## 3. 업데이트 방식

기획 결정이 확정되면 다음 순서로 처리한다.

1. 작업 시작 시 게임·프로그래밍·아트·사운드·QA·PM 영향 분야를 선택한다.
2. 영향 분야의 `docs/planning/` 본책과 관련 `docs/design/APPROVED_*.md` 부록을 확인한다.
3. 구현·제작·검증 후 관련 본책의 상태, 최신 자료, 완료 기준을 갱신한다.
4. 구체 수치·데이터 계약이 바뀌면 해당 APPROVED 부록도 갱신한다.
5. 문서 경로나 책임 관계가 바뀌면 `DOCUMENTATION_MAP.md`를 갱신한다.
6. Handoff와 Active Context에는 본책을 복제하지 않고 현재 상태와 읽기 순서만 연결한다.
7. 변경 뒤 서로 모순되는 오래된 표현과 깨진 링크가 남았는지 검증한다.

### 영향별 필수 갱신 매트릭스

| 변경 | 필수 확인·갱신 |
|---|---|
| 게임 규칙·시나리오·UI/UX·밸런스 | `01_GAME_DESIGN.md`, 관련 승인 부록, QA 상태 |
| 코드·Scene·데이터·AI·성능·로드맵 | `02_PROGRAMMING_MVP_ROADMAP.md`, 테스트·QA 상태 |
| 캐릭터·전장·건물·UI·애니메이션·VFX | `03_ART_DIRECTION.md`, 시각자료 인덱스, 시각 QA |
| BGM·SFX·음성·믹싱 | `04_SOUND_DIRECTION.md`, 오디오 QA |
| 테스트·버그·일정·위험·예산·릴리스 | `05_QA_PM_PLAN.md` |
| 공식 이미지 교체 | `docs/images/current/` 안정 경로, 이미지 인덱스, 아트 본책 |

공식 이미지는 `_v2`, 날짜, `final` 접미사를 붙이지 않은 안정 경로 하나를 사용한다. 이전 버전은 별도 활성 파일이 아니라 Git 이력으로 보존한다.

### GitHub Issue 미러

- `docs/issues/`는 GitHub Issue의 추적 가능한 Markdown 미러다.
- 승인 기획의 책임 원본은 계속 `docs/design/`, Goal, Work Order이며 Issue 미러는 이를 덮어쓰지 않는다.
- Issue 이벤트는 GitHub Actions가 동기화 PR로 제안하고, 검토·병합 전에는 `main`의 미러를 바꾸지 않는다.
- `docs/issues/` 변경이 `main`에 병합되면 해당 Issue의 제목·본문·상태를 GitHub에 되돌려 보낸다.
- 양쪽 본문이 마지막 동기화 이후 모두 달라지면 자동 덮어쓰기를 금지하고 책임 원본을 기준으로 수동 해결한다.
- Issue 댓글·첨부는 GitHub에만 보관한다.

## 4. 이전 버전 처리

### 기본 처리: Git 이력

- 같은 책임 문서는 파일을 복제하지 않고 제자리에서 갱신한다.
- 이전 내용은 커밋 이력으로 복원할 수 있으므로 활성 저장소에 별도 사본을 남기지 않는다.
- 단순 문구 수정, 수치 조정, 승인 규칙 갱신은 모두 Git 이력만 사용한다.

### 예외 처리: `docs/archive/`

다음 경우에만 과거 파일을 `docs/archive/YYYY-MM/`로 이동한다.

- 외부 계약·납품·심사에 사용된 고정 스냅샷
- 대규모 방향 전환 전후를 비교해야 하는 문서
- 다른 저장소나 외부 링크가 과거 파일 경로에 의존하는 문서
- 삭제하면 의사결정 근거를 이해하기 어려운 연구·검증 보고서

아카이브 문서는 현재 작업의 읽기 순서에 포함하지 않는다.

## 5. 금지 사항

- 최신 내용과 과거 내용이 동시에 활성 책임 문서로 남는 상태
- 같은 규칙을 여러 문서에 복사한 뒤 각각 독립적으로 수정하는 방식
- GitHub 반영에 실패했는데 반영 완료로 보고하는 행위
- 사용자가 폐기한 안을 ACTIVE_CONTEXT나 공식 기획서에 남기는 행위
- 아카이브 문서를 구현 근거로 사용하는 행위

## 6. 작업 완료 체크

- [ ] 최신 사용자 결정이 책임 원본에 반영됐는가
- [ ] 영향 받은 5개 본책과 충돌하지 않는가
- [ ] `ACTIVE_CONTEXT.md`가 현재 상태를 설명하는가
- [ ] DOCUMENTATION_MAP이 올바른 책임 원본을 가리키는가
- [ ] 활성 폴더에 중복 버전 파일이 생기지 않았는가
- [ ] 과거 버전은 Git 이력 또는 필요한 경우 archive에만 남았는가
- [ ] 커밋 SHA가 생성됐는가

## 7. 현재 전장 문서 적용 예시

전장 관련 최신 책임 원본은 `docs/design/APPROVED_BATTLEFIELD_TOPOLOGY_AND_SCALE_V1.md`다.

새로운 전장 결정은 별도 `V2` 파일을 만들지 않고 이 파일을 갱신하며, 전체 요약은 `planning/01_GAME_DESIGN.md`, 시각 방향은 `planning/03_ART_DIRECTION.md`, 검증 상태는 `planning/05_QA_PM_PLAN.md`에 동기화한다. 과거 전장 초안은 Git 이력에서 확인한다.
