상태: RESEARCHED / DESIGN_RECOMMENDATIONS. 핵심 유지와 재설계 조사는 사용자 승인. 개별 신규 규칙은 아래 제안이며 기존 런타임에 적용하지 않았다. 조사일 2026-09-10. 출발 main `9ea3245b5e4372222faa24e6acf84da7de8161d9`, 현재 접수 PR 258; PR 257은 읽기 전용 구현 비교. Base remote `2f93e872d9ed4fa18018ac759b01acd7d34e9b58`, main adapter 9.4.3 보존.

## 1. 고정한 핵심과 판단 기준

**룰렛으로 병력을 구성하고 하나의 전선에서 자동전투한다.** 시스템·화면·신규 그림과 모션은 이 경험을 잘 만들도록 다시 설계한다. 세계관·룰렛 화면·건물 개수 등 세부 요소가 과거 문서에 있다는 이유만으로 유지하지 않는다. 기존 이미지는 참고자료다.

유지는 선택의 의미가 있고 코어를 돕는 경우, 보완은 의미는 있으나 전달/회복/학습이 부족한 경우, 통합은 같은 결정을 중복 수행하는 경우, 폐기 후보는 가치보다 인지·제작 비용이 큰 경우다. 창의적인 추가도 기존 문제·실제 화면·검증 방법이 없으면 보류한다.

평가 축: 플레이어 선택의 의미 / 인과 가독성 / 기존 사례와 구별되는 행동 / 초보 학습 / 실패 후 회복 / 반복 플레이 / Godot 구현·저장 호환 / 이미지·모션 생산비 / 실제로 반증 가능한가. 매출·리텐션·시장 규모·세계 최초 여부를 추정 점수로 만들지 않는다.

## 3. 실무 조사에서 가져올 방법

- [Into the Breach GDC 개발 회고 원문](https://media.gdcvault.com/gdc2019/presentations/Into%20the%20Breach%20Postmortem%20Final.pdf): 팀 규모·가독성·적은 메뉴 등 제약에서 설계를 발전시키고 UI 제약이 전투 규칙에도 영향을 준 사례. ADAPT: 단일전선·한 번에 한 주요 결정·병종 가독성을 기준으로 기능을 줄인다. 해당 게임의 완전 예고 규칙까지 복제하지 않는다.
- [Slay the Spire GDC 발표 개요](https://www.gdcvault.com/play/1025731/-Slay-the-Spire-Metrics): 개발 중 지표와 커뮤니티 피드백을 결합하는 접근. 개요를 읽었으며 전체 강연 시청 완료로 주장하지 않는다. ADAPT: 승률 외에 선택 이유/공세 이해/결과 귀인을 함께 검증한다. 강한 옵션의 선택률만 보고 자동 하향하지 않는다.
- [Aseprite 공식 export](https://www.aseprite.org/docs/cli/), [Godot 2D sprite animation](https://docs.godotengine.org/en/stable/tutorials/2d/2d_sprite_animation.html): 시트와 데이터, 프레임 재생의 실제 경로. ADAPT: 그림→상태→시간→엔진 consumer 연결을 한 pilot에서 검증한다. PNG를 묶었다고 동작 제작 완료로 세지 않는다.
- 프로젝트 기존 `OMENWARD_ROULETTE_AGENCY_EVIDENCE_PACK_2026-07-29.md`: 확률 통제감·패배 원인 설명을 묻는 검증 질문은 재사용 가능. 세 전선 및 오래된 권한 표시는 역사로만 취급한다.

| 반복 성장·메타 보상 | 수평 해금 우선 비교 | 실패에서도 새 실험 동기 | 영구 능력치 노가다가 난이도 해법이 되는지 검증 |

## 6. 서로 다른 재설계 대안

| 안 | 핵심 선택 | 장점 | 약점 | 판정 |
|---|---|---|---|---|
| A 확률 콤보 중심 | 토큰·규칙 수정자를 결합해 강한 소환 | 빠른 보상, 다양한 조합 | B01/B03/B04와 중첩, 군단 전투가 점수 연출로 축소 가능 | 비교 기준 |
| B 예고·군수 중심 | 공세를 읽고 제한된 건물 구성을 바꿔 다음 증원을 설계 | 기존 건물 인과 활용, 세계관과 행동 연결 | 설명 부담, 최적 카운터 한 개로 굳을 위험 | 우선 권장 |
| C 증원 시점 중심 | 얻은 병력을 언제 투입할지 판단 | 전투 관찰과 개입 긴장감 | 수동 조작 부담, 새 타이밍 시스템 구현 비용 | 두 번째 실험 후보 |

B에 A/C를 전부 합치지 않는다. 우선 B의 준비 선택이 충분히 재미있는지 확인한다. 두 개 이상의 대응이 성립하는 공세에서 조합의 장단점을 설명할 수 있어야 한다.

## 7. 독창성과 창의성 후보

독창성은 검색한 11개 안에서의 차이 가설이며 세계 최초·법적 독창성 인증이 아니다. 다음 세 후보는 하나씩 비교한다.

1. **동원 설계의 인과 표시**: 건물 변경 → 실제 토큰 공급 변화 → 획득 병종 → 주요 전투 기여를 동일한 표식으로 추적. 새 화폐 없이 기존 구조를 연결한다. 위험: UI가 복잡해짐. 성공: 사용자가 건물 선택이 전투에 준 영향을 설명.
2. **대응 방식이 여러 개인 징조**: 장갑 공세에 관통, 지연, 보호/지속 공격처럼 서로 다른 투자 축을 시험. 새 상태효과를 무조건 추가하지 않고 기존 역할로 먼저 구성. 위험: 정답 카운터 고착. 성공: 동일 공세에 두 편성이 다른 비용/손실로 성립.
3. **전선별 군수 변주**: 5맵을 재색칠하지 않고 공세 순서/증원 간격/주요 목표를 달리하는 안. 위험: 매번 새로운 룰 학습. 성공: 공통 조작을 유지하면서 준비 선택이 달라짐. 골드/슬롯 보너스와 중복 강화 주의.

## 9. 아트와 모션 대안

| 안 | 제작 방식 | 이득 | 부담 | 권장 |
|---|---|---|---|---|
| 제한 팔레트 픽셀 SD | 이미지 모델 key pose, Aseprite 프레임 정리 | 작은 크기 명료함 | 정밀 cleanup·프레임 consistency 비용 | 비교 시안 |
| 단순화된 동화풍 SD | 명확한 외곽·큰 색면·제한된 질감, 상태별 프레임 | 기존 취향의 정서와 가독성 절충 | 과도한 세부 묘사로 크기 축소 시 소실 | 우선 후보 |
| 부위 분리 2D 리깅 | 몸통·무기·팔다리 분리와 관절 동작 | 반복 동작 재사용 | 분리 원화·관절/갑옷 겹침·toolchain 비용 | pilot 결과로 재평가 |

배경/소품/병사/VFX 분리. 이동 통로는 비우고 전장 가장자리에 소품. 병사는 몸통 질량→무기/기관→진영 색→장식을 읽는다. 배경보다 병사 대비가 높도록 후보를 같은 화면에 올려 비교한다. Aseprite 도입은 화풍 선택의 근거가 아니다.

첫 제작은 방어 역할 아군/베일 pair 또는 주력 원거리 pair 중, 실제 prototype에서 가장 자주 보이는 역할로 고른다. 프레임 수를 먼저 고정하지 않고 idle/move/attack/hit/death의 의미와 impact event, baseline/pivot, loop/interrupt를 먼저 명세한다. 공격 프레임 생산 시 장비·팔 수·실루엣 continuity를 함께 확인한다.

## 10. 검증 계획과 우선순위

P0: 원인-결과 표시, 관리/전투 시간 규칙, 역할 가독성, 슬롯 손실 악순환. P1: 전선별 변주·보상과 성장 구조. P2: 대량 병종/장식/추가 modifier.

- 기술: 같은 seed/행동에서 결과 재현; 실제 토큰 분포와 UI preview 일치; 잠긴 건물 효과 중복/잔류 없음; 탭 전환으로 RNG/시간 재실행 없음; impact 이벤트 중복/사망 뒤 공격 없음.
- 밸런스: 공세×두 대응 편성×자원 부족 조건을 비교. 골드/탑/슬롯 보상을 분리해 선두 강화와 회복 경로를 관찰. 표본을 확보하기 전 최적 수치 확정 없음.
- 사람: 플레이 전 ‘다음 위협/바꾼 효과’, 후 ‘주요 손실 원인/다음 수정’을 본인 말로 설명하도록 확인. 적중률만 점수화하지 않고 오해 사례 기록.
- 아트/모션: 실제 화면 크기·밝고 어두운 배경·다수 병사·배속에서 역할/준비/타격이 구별되는지 확인. 흔들림·발 미끄러짐·무기 잘림·피격 과다 플래시 검사.
- 검증 순서: 위 화면/흐름 명세 → 작은 편성 사례 → 신규 아트/동작 pilot → 실제 Godot → 확장. 신규 이미지·모션·재설계 gameplay runtime과 사용자 시험은 이번 조사에서 NOT_RUN.

## 11. 검토 기록

1. 요구 대조: 핵심 유지 확인, 단일전선/전장 건설 제외 유지, 추가 규칙은 제안으로 표시.
2. 사실 대조: 공식 설명과 우리 추론을 분리, Steam 연령문은 개발사 본문으로 대체, Slotbound 미출시 상태 반영.
3. 중복 대조: 슬롯+오토배틀 독창성 주장 제거, 새 화폐/리깅/전체 애니메이션 양산을 기본값에서 제외.
4. 실패 대조: 슬롯 잠금 악순환, 정답 카운터, 탭 중 시간 진행, 메타 성장 노가다를 검증 대상에 포함.
5. 제작 대조: frame metadata와 상태별 실제 그림/engine 연결을 구별. 강연 개요를 전체 강연 연구로 과장하지 않음.

학습: 다음 기능 제안은 유지/변경 이유뿐 아니라 폐기 조건과 실제 확인할 플레이어 행동을 같이 기록한다. Base 자동 승격은 하지 않는다. 이 보고서는 연구·제안이며 사용자 플레이 검증이나 구현 완료 보고가 아니다.
