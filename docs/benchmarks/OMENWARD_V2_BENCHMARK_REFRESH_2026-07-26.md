# 오멘워드 V2 장르 벤치마크 갱신

- 조사·검수일: 2026-07-26
- 프로젝트: **오멘워드 / OMENWARD**
- 상태: `V2_BENCHMARK_REFRESH_REVIEWED`
- 권한: `PLANNING_INPUT / NOT_IMPLEMENTATION_AUTHORITY`
- 제품 구현: `V2_IMPLEMENTATION_NOT_STARTED`
- 관련 Issue: `#2`, `#69`
- 관련 계획: `docs/superpowers/plans/2026-07-26-omenward-v2-r1-r2-roulette-foundation.md`
- 실제 구현 상태: `docs/CURRENT_IMPLEMENTATION_STATUS.md`
- 프로젝트 코어: `docs/PROJECT_CORE.md`

이 문서는 2026-07-14의 Pre-V2 벤치마크를 현재 V2 정본에 맞춰 갱신한다. 기존 벤치마크 문서는 조사 이력과 과거 승인 추적용으로 보존한다. 현재 제품 규칙과 충돌할 때는 최신 사용자 지시, 통합 결정 원장, V2 통합 명세가 우선한다.

## 1. 검수 목적

현재 구조를 유지하면서 유사 장르가 다음 문제를 어떻게 해결하는지 비교한다.

```text
운을 설계 가능한 상태로 만드는가
→ 배치·순서·출처가 빌드로 읽히는가
→ 자동전투의 실패 원인이 설명되는가
→ 한 순간의 핵심 결정 수가 통제되는가
→ 반복 플레이가 콘텐츠 수가 아니라 학습으로 이어지는가
```

오멘워드의 기준 문장은 유지한다.

> **건물로 룰렛을 만들고, 룰렛으로 전선을 지휘한다.**

시장 구분 문장은 다음처럼 해석한다.

> 오멘워드는 좋은 슬롯 결과를 기다리는 게임이 아니다. 건물을 지어 토큰 출처를 만들고, 세 원형 릴의 미래 배열을 영구 편집한 뒤, 그 결과를 세 전선 중 하나에 커밋하는 전략 오토배틀 게임이다.

## 2. 기존 벤치마크와의 관계

기존 Issue `#2`와 `docs/benchmarks/0001-core-game-benchmark-proposal.md`는 다음 성공·위험 요소를 이미 기록했다.

- 단순한 표면과 깊은 시스템 결과.
- 건설 전 룰렛 변화 미리보기와 토큰 장부.
- 공개 위협에 대한 카운터 판단.
- 라인별 승패 원인 보고.
- 제한된 건설 공간과 명확한 경제·생산·방어 선택.
- 직접 조작 영웅, PvP, 대규모 메타 트리, 초기 조합 폭발 제외.

이 결론은 V2와 호환되는 범위에서 유지한다. 다음 Pre-V2 항목은 현재 구현 근거로 사용하지 않는다.

- `Roulettebound` 명칭.
- 독립 9칸 확률 미리보기.
- T-30/T-15/T-5 고정 전조.
- 구형 럭키와 이동 거래.
- 구형 노드·StageRun 수명주기.

## 3. 비교작별 적용 판정

### 3.1 Luck be a Landlord

공식 설명은 플레이어가 슬롯에 심벌을 추가하고, 각 심벌의 효과와 상호작용으로 빌드를 만든다고 설명한다.

**채택할 원리**

- 무작위 결과를 직접 고르는 대신 미래 결과의 풀을 설계한다.
- 현재 구성과 변화 원인을 항상 읽을 수 있어야 한다.

**오멘워드 적용**

- 심벌 선택 보상 대신 `건물 → TokenSource → TokenInstance` 인과를 유지한다.
- 토큰 수만 아니라 릴 순서, cursor, 출처 건물, `NORMAL_X / SOURCE_BOUND_X`를 청사진으로 보여준다.

**제외**

- 회전 후 후보 심벌 중 하나를 반복 선택하는 일반 슬롯 덱빌더 흐름.
- 수백 개 심벌을 코어 깊이로 대체하는 콘텐츠 확장.

### 3.2 Spin Hero

공식 설명은 릴을 돌리고 심벌을 수집해 시너지와 전략을 발전시키는 로그라이크 덱빌더로 규정한다.

**채택할 원리**

- 회전 결과와 전투 결과가 즉시 연결돼야 한다.
- 패배가 다음 시너지 선택을 바꾸는 학습으로 이어져야 한다.

**오멘워드 적용**

- 차별점은 `심벌을 모은다`가 아니라 `회전 전에 릴 구조를 설계한다`로 고정한다.
- 회전 결과가 출처 건물·Tier·세부 병종·전선 커밋으로 이어지는 인과를 표시한다.

### 3.3 Backpack Battles

공식 설명은 무엇을 구매했는지뿐 아니라 배낭 안에 어떻게 배치했는지가 전투 빌드를 결정한다고 강조한다.

**채택할 원리**

- 구성 요소의 위치와 순서 자체가 빌드다.
- 전투 전에 배치 결과를 비교하고 수정할 수 있어야 한다.

**오멘워드 적용**

- 별도의 인접 보너스 시스템을 추가하지 않는다.
- 릴 배열 순서와 노출까지의 거리, 이동 전후 고스트 배열을 빌드 정보로 취급한다.

### 3.4 Mechabellum

공식 설명은 병력 선택, 유닛 커스터마이즈, 대형과 카운터 중심의 오토배틀을 강조하며 조작량보다 전략 판단을 전면에 둔다.

**채택할 원리**

- 위협을 읽고 대응 자원을 비교한다.
- 자동전투 결과가 어떤 배치와 카운터 때문에 발생했는지 설명된다.

**오멘워드 적용**

- 정확한 공세 예고를 `무엇이 오는가 → 왜 위험한가 → 현재 대응 수단은 무엇인가`로 정리한다.
- 시스템이 정답 라인을 자동 선택하지 않는다.
- 전투 후에는 건물·릴·보상·배치·명령·AI 발동을 연결한 핵심 인과만 요약한다.

### 3.5 Thronefall

공식 설명은 작은 왕국의 건설과 방어를 최소주의 구조로 제공한다.

**채택할 원리**

- 한 순간에 처리할 결정이 분명해야 한다.
- 경제·생산·방어 차이가 즉시 비교돼야 한다.

**오멘워드 적용**

- 새 시스템을 추가하기보다 건설·릴·전선 결정을 한 화면의 우선순위로 압축한다.
- 기본 화면에는 핵심 상태만 두고 세부 정보는 선택 시 펼친다.

**제외**

- 직접 조작 영웅 전투.
- 낮과 밤의 완전 분리.

### 3.6 Loop Hero

공식 설명은 플레이어가 적·건물·지형 카드를 배치해 영웅이 통과할 위험과 보상을 간접 설계한다고 설명한다.

**채택할 원리**

- 플레이어가 만든 환경 때문에 결과가 발생했다는 책임이 읽혀야 한다.
- 실패가 다음 설계 수정으로 이어진다.

**오멘워드 적용**

- `건물 결정 → 토큰 변화 → 회전 결과 → 전선 커밋 → 전투 결과`를 하나의 학습 사슬로 기록한다.
- 맵 종료 시 최종 빌드와 영향이 컸던 결정을 요약한다.

**제외**

- 별도의 카드 덱으로 적·지형을 배치하는 두 번째 핵심 게임.

### 3.7 The King is Watching

공식 설명은 왕의 시선 아래 자원 생산과 군대 훈련 중 어디에 집중할지, 또는 균형을 잡을지 선택하게 한다.

**채택할 원리**

- 모든 생산·군사 선택을 동시에 활성화할 수 없을 때 우선순위가 선명해진다.
- 제한은 시스템 수를 늘리지 않고 긴장을 만든다.

**오멘워드 적용**

- 기존 건설 공간, 금화, 식량, 보관 한도를 핵심 타협으로 유지한다.
- 한 구간에 노출하는 주요 추천 행동은 소수로 제한한다.

**제외**

- 별도의 시선·활성 영역 퍼즐.
- 무작위 건물 획득을 핵심 공급 방식으로 사용하는 구조.

### 3.8 Emberward와 Tower Dominion

공식 설명은 블록이나 타일로 미로·지형·경로를 직접 설계해 적의 이동을 통제하는 것을 핵심으로 둔다.

**판정: 명시적 제외**

- 오멘워드의 고정 3라인과 경쟁하는 지형·경로 편집을 추가하지 않는다.
- 릴 설계와 경로 설계가 동시에 핵심이 되면 제품 문장이 분산된다.
- AI 경로 탐색, 아트, 전투 원인 분석 비용이 크게 증가한다.

### 3.9 9 Kings와 The Last Flame

공식 설명은 매우 많은 조합과 시너지 빌드를 반복 가치로 강조한다.

**판정: 후속 검토**

- 코어 V2에서 적은 수의 병종·건물·출처가 읽히는지 먼저 검증한다.
- 초기부터 수천 개 조합이나 대량 콘텐츠를 목표로 하지 않는다.
- 선택형 난이도, 도전 모드, 무한 모드는 코어 인과가 증명된 뒤 검토한다.

## 4. 최종 반영 분류

### A. V2 UX 요구사항으로 채택

#### A-1. 설계 청사진

다음 정보를 하나의 일관된 도메인 snapshot에서 표시한다.

```text
세 릴의 전체 토큰 배열
현재 cursor와 노출 3×3
각 TokenInstance의 출처 건물
NORMAL_X / SOURCE_BOUND_X
가로 이동 전후 고스트 배열
다시 노출되기까지의 거리
현재 판정 후보와 출처 후보 풀
```

플레이어가 다음 질문에 답할 수 있어야 한다.

- 이 토큰은 왜 여기에 있는가.
- 어느 건물이 만들었는가.
- 이동이 현재 결과와 미래 배열을 어떻게 바꾸는가.
- 출처 건물이 blocked가 되면 어떤 토큰이 변하는가.

#### A-2. 전선 대응 브리핑

라인별 정보를 다음 구조로 제시한다.

```text
무엇이 오는가
→ 왜 현재 전선에 위험한가
→ 지금 보유한 대응 자원은 무엇인가
→ 아직 해결되지 않은 위험은 무엇인가
```

제한:

- 자동으로 정답 배치를 선택하지 않는다.
- 추천 병종을 강제하지 않는다.
- 숨은 전투 정보를 추측해 사실처럼 표시하지 않는다.

#### A-3. 전투 인과 사슬

전체 전투 로그가 아니라 영향이 큰 인과를 소수로 정리한다.

```text
건물 결정
→ 릴 토큰 변화
→ SpinSnapshot 결과
→ 출처·Tier·등급
→ 보관·판매·라인 배치
→ 라인 명령과 AI 기술 발동
→ 전선 변화
→ 승패·손실 원인
```

### B. UX 표현으로만 채택하며 새 코어 규칙으로 만들지 않음

#### B-1. 설계 점검 구간

- 강제 일시정지, 별도 계획 페이즈, 새 시간 규칙을 추가하지 않는다.
- 기존 Stage·Wave 전환 또는 전투 압력이 낮은 시점에 정보를 묶어 보여주는 UX surface로 정의한다.
- 현재 실시간 전투와 위험 압박을 제거하지 않는다.

표시 순서:

```text
이전 전투 원인
→ 다음 공세
→ 건설·업그레이드·철거
→ 릴 배열·이동 자원
→ 보관·식량
```

#### B-2. 런 청사진 기록

코어 범위에서는 맵 종료 로컬 요약만 정의한다.

```text
최종 릴 배열
최종 건물과 Tier
라인별 명령
주요 배치 병력
영향이 큰 회전·건설 결정
주요 실패 또는 승리 원인
최종 결과
```

현재 제외:

- mid-run save.
- 재도전 프리셋 자동 적용.
- 온라인 공유.
- 리플레이 재생.
- 영구 통계 서비스.

### C. 코어 검증 이후 후속 후보

- 선택형 난이도 제약과 Mutator.
- 일일·주간 도전.
- 런 청사진 공유.
- 무한·고득점 모드.
- 콘텐츠 대량 확장.
- 사용자 제작 룰렛·모드.

### D. 명시적 제외

- 지형·경로 편집.
- 직접 영웅 조작.
- 회전마다 후보 심벌을 선택하는 일반 슬롯 덱빌더화.
- 무제한 리롤·무료 재배치.
- 온라인 PvP와 시즌 랭크.
- 초기부터의 대규모 조합 폭발.

## 5. R1+R2 영향 판정

```text
BENCHMARK_REFRESH
≠ R1_R2_SCOPE_EXPANSION
≠ LIVE_UI_IMPLEMENTATION
≠ TELEMETRY_IMPLEMENTATION
```

R1+R2는 다음 범위를 그대로 유지한다.

- Legacy 중앙 판정 보존 seam.
- 세 원형 릴의 순수 상태.
- 결정론적 정지.
- 깊은 복사 `SpinSnapshot`.
- stopped-only `SpinSession`.

이번 벤치마크로 R1+R2에 추가하지 않는 것:

- HUD·브리핑·인과 보고 UI.
- StageRun·MapRun 연결.
- 로그·통계 수집.
- 런 요약 저장.
- 이동·확정·보상 거래.

후속 패키지는 R1+R2의 primitive snapshot과 도메인 결과를 소비해야 하며, UX 요구 때문에 순수 도메인이 UI를 참조하게 해서는 안 된다.

## 6. 향후 검증 질문

### 설계 이해

- 플레이어가 10초 안에 특정 토큰의 출처 건물을 찾을 수 있는가.
- 가로 이동 전 현재 보드와 미래 배열 변화 방향을 설명할 수 있는가.
- `NORMAL_X`와 `SOURCE_BOUND_X`의 차이를 설명할 수 있는가.

### 위협 대응

- 플레이어가 다음 위험 라인과 위험 이유를 말할 수 있는가.
- 현재 보관·식량·건설·릴 상태에서 가능한 대응 수단을 찾을 수 있는가.
- 브리핑이 정답을 대신 선택하지 않는가.

### 결과 학습

- 패배 후 잘못된 건설·릴·배치 결정을 한 문장으로 설명할 수 있는가.
- 런 요약이 다음 시도의 구체적인 수정 행동으로 이어지는가.
- 전투 인과 보고가 단순 상관관계를 원인으로 오인하지 않는가.
