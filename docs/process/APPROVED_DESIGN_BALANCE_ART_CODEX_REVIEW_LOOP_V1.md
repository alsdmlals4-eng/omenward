# 승인된 기획·밸런스·아트 Codex 검수 루프 V1

- 상태: **프로세스 승인**
- 작성일: 2026-07-15
- 적용 범위: 오멘워드의 남은 기획, 밸런싱, UI/UX, 아트 디자인, 데이터 계약, 구현 준비 검수
- 구현 경계: 이 문서는 작업 방식만 승인하며 Godot 코드·Scene·Resource·테스트 구현을 승인하지 않는다.

## 1. 역할 분담

### ChatGPT — 설계 담당

- 현재 승인 문서와 사용자 결정을 읽고 작업 패킷 초안을 작성한다.
- 기획 규칙, 수치 가설, 상성, 예외, UI 표현, 데이터 필드, 검증 기준을 함께 제안한다.
- Codex 검수 결과를 심각도별로 분류하고 수정안을 만든다.
- 사용자 결정을 요구하는 핵심 선택지만 짧게 정리한다.
- 승인된 결과를 책임 문서, `ACTIVE_CONTEXT.md`, `DECISIONS_PENDING.md`, 관련 이슈에 반영한다.

### Codex — 저장소 검수 담당

- 현재 저장소의 모든 `APPROVED_*.md`, 활성 컨텍스트, 로드맵, 미확정 목록과 작업 패킷을 비교한다.
- 기획 모순, 밸런스 위험, 데이터 누락, 구현 난점, 테스트 불가능 조건, 명칭 충돌을 찾는다.
- 코드를 작성하지 않고 검수 보고서만 작성한다.
- 수정 권고는 반드시 근거 문서와 영향 범위를 명시한다.

### 사용자 — 방향 승인 담당

- 게임의 정체성, 재미 방향, 핵심 병종, 주요 수치 곡선, 아트 방향처럼 되돌리기 큰 결정을 승인한다.
- 오탈자, 참조 경로, 명백한 문서 불일치 같은 무의미한 재승인은 요구하지 않는다.
- 구현은 별도 Codex Plan Mode 제안서 승인 후 시작한다.

## 2. 작업 패킷 단위

한 번의 루프는 한 가지 핵심 질문만 다룬다.

좋은 예:

- 시작 금화와 전체 경제 곡선.
- 마법사 등급별 능력 계보.
- 1~15웨이브 Threat Budget.
- 아군·적군 10병종 실루엣 계약.
- 룰렛 HUD 정보 우선순위.

나쁜 예:

- 모든 병종, 모든 웨이브, 모든 UI와 모든 아트를 한 문서에서 동시에 확정.

권장 패킷 크기:

- 책임 문서 1개.
- 관련 표 1~4개.
- 핵심 결정 3~10개.
- 검증 기준 5~20개.
- Codex 검수 질문 5~12개.

## 3. 상태 전이

```text
BACKLOG
→ CHATGPT_DRAFT
→ CODEX_REVIEW_REQUESTED
→ CHANGES_REQUIRED 또는 REVIEW_PASSED
→ USER_DECISION_REQUIRED 또는 READY_TO_APPROVE
→ APPROVED_DESIGN
→ READY_FOR_PLAN_MODE
→ IMPLEMENTATION_APPROVED
→ IMPLEMENTED
→ PLAYTEST_VALIDATED
```

규칙:

- `APPROVED_DESIGN` 전에는 책임 문서가 공식 기준이 아니다.
- `READY_FOR_PLAN_MODE`는 구현 가능성이 검수됐다는 의미이지 구현 승인 자체가 아니다.
- `IMPLEMENTATION_APPROVED`는 사용자가 별도 Plan Mode 제안서를 승인한 뒤에만 사용한다.
- 플레이테스트에서 수치가 바뀌어도 구조 계약과 수치 가설을 구분해 기록한다.

## 4. ChatGPT 작업 패킷 형식

각 패킷은 다음 순서를 사용한다.

```text
1. 목적
2. 현재 승인 계약
3. 해결할 문제
4. 제안 구조
5. 수치 또는 시각 가설
6. 상성·예외·실패 조건
7. UI와 플레이어 정보
8. 데이터 계약
9. 검증 계약
10. 다른 문서에 미치는 영향
11. 사용자 결정 필요 항목
12. Codex 검수 질문
```

수치에는 다음 표기를 사용한다.

- `승인`: 구조와 값 모두 고정.
- `초기 PoC 가설`: 첫 구현·플레이테스트 시작값.
- `범위 가설`: 정확한 값을 고르기 전 허용 범위.
- `미확정`: 사용자나 플레이테스트 결정이 필요.

## 5. Codex 검수 형식

Codex는 다음 형식을 사용한다.

```text
검수 결과: PASS / PASS_WITH_NOTES / CHANGES_REQUIRED

P0 — 승인 불가
- 기존 공식 계약과 직접 충돌
- 게임 진행 불가능 또는 무한 루프
- 데이터로 표현 불가능
- 구현 시 대규모 재설계가 확실함

P1 — 승인 전 수정 권장
- 밸런스가 한 전략으로 수렴
- 상성 또는 예외가 빠짐
- UI에서 중요한 정보가 숨겨짐
- 테스트 기준이 불명확함

P2 — 후속 개선
- 명칭, 표현, 문서 구조, 경미한 UX 개선

각 지적 항목:
- 위치
- 문제
- 근거
- 영향
- 권장 수정
- 검증 방법
```

Codex는 취향만으로 거절하지 않는다. 반드시 승인 계약, 계산, 재현 가능한 전투 상황, 데이터 경계 중 하나를 근거로 사용한다.

## 6. Codex 공통 검수 체크리스트

### 기획

1. 기존 공식 문서와 충돌하는가.
2. 플레이어가 10~30초 안에 기본 역할을 이해할 수 있는가.
3. 한 선택이 다른 선택의 완전한 상위호환인가.
4. 승리·패배·일시정지·건물 파괴 예외가 정의됐는가.
5. 3라인 구조와 라인 이동 금지 규칙을 지키는가.

### 밸런스

1. 60초 공세 간격에서 이전 웨이브가 과도하게 누적되는가.
2. 15분 스테이지 안에서 투자 회수 시간이 의미 있는가.
3. 식량, 생산시간, 금화, 토큰 확률을 중복 계산했는가.
4. 특정 병종·건물·교리가 항상 최적이 되는가.
5. 보스와 일반 적에게 같은 제어·흡혈·파쇄가 무제한 적용되는가.
6. 최소·평균·최대 결과를 비교했는가.

### 아트·UX

1. 전략 줌에서 실루엣만으로 역할을 구분할 수 있는가.
2. 아군·적군, Tier, 등급, 지상·비행을 동시에 읽을 수 있는가.
3. 상시 VFX가 전장을 가리지 않는가.
4. 공격 전조와 실제 판정이 일치하는가.
5. 픽셀 크기·애니메이션·VFX 비용이 성능 예산 안에 있는가.
6. 색상만으로 정보를 구분하지 않는가.

### 구현 준비

1. 필요한 데이터 필드가 명시됐는가.
2. 상태 전이가 결정론적인가.
3. 저장·재현·시드 테스트가 가능한가.
4. 단위 테스트 또는 시뮬레이션 기준이 있는가.
5. 현재 단계에서 구현 금지 경계를 지키는가.

## 7. 수정과 승인 규칙

- P0가 하나라도 있으면 ChatGPT가 수정안을 만든 뒤 재검수한다.
- P1은 수정하거나, 유지할 이유와 위험 완화책을 문서에 적는다.
- P2는 같은 루프에서 처리하거나 후속 백로그로 보낼 수 있다.
- Codex가 `PASS` 또는 `PASS_WITH_NOTES`를 반환해도 방향 변경이 큰 항목은 사용자 승인 후 공식화한다.
- 사용자 승인 뒤 ChatGPT가 책임 문서를 `APPROVED_*.md`로 승격한다.

## 8. GitHub 운영 규칙

각 작업 패킷은 하나의 GitHub 이슈에서 관리한다.

이슈 본문:

```text
상태
목적
책임 문서
의존 문서
ChatGPT 제안 요약
Codex 검수 결과
사용자 결정
최종 승인 내용
후속 작업
구현 금지 문구
```

권장 라벨:

```text
design
balance
art
codex-review
changes-required
approved-design
ready-for-plan
```

현재 저장소에 라벨이 없더라도 제목 접두사와 본문 상태를 우선 사용한다.

## 9. 아트 패킷의 산출물 경계

아트 디자인 루프에서 먼저 확정할 것은 이미지 파일 자체가 아니라 제작 계약이다.

- 실루엣과 크기.
- 비율과 장비 형태.
- 진영별 형태 언어.
- 색상 역할.
- 등급별 추가 요소.
- 기본·공격·피격·사망 애니메이션 프레임 예산.
- 스킬 전조·판정·잔상 VFX.
- HUD 아이콘과 월드 아이콘.
- 금지 요소와 가독성 실패 조건.

시안 이미지가 필요할 때는 승인된 계약을 기반으로 별도 생성하고, Codex는 이미지의 미학보다 게임 카메라·크기·애니메이션·파일 구조·상태 수를 검수한다.

## 10. 밸런스 패킷의 최소 시뮬레이션

수치 패킷은 구현 전이라도 표 계산으로 다음을 검증한다.

- 단일 병종 1대1 기준.
- 명확한 상성전과 역상성전.
- 동일 금화·식량·생산시간 기준 전력 비교.
- 60초 안의 목표 처치시간.
- 15분 안의 생산량과 투자 회수.
- 최소 운·평균 운·높은 운의 룰렛 결과.
- 웨이브 중첩 시 최대 적 수.
- 보스 30~60초 목표 전투시간.

## 11. 사용자에게 보고하는 형식

한 루프가 끝날 때 다음만 요약한다.

1. 무엇을 확정했는가.
2. Codex가 무엇을 지적했는가.
3. 어떤 수정이 반영됐는가.
4. 사용자 결정이 필요한가.
5. 다음 패킷은 무엇인가.

검수 로그 전체는 GitHub 문서나 이슈에 남기고 대화에는 핵심만 표시한다.

## 12. 첫 운영 순서

1. 전체 경제 기준표.
2. 기본 병영 6종 능력 계보.
3. 특수병단 4종 능력 계보.
4. 아군·적군 10병종 대칭표.
5. 1~15웨이브 Threat Budget과 편성.
6. 16~20 초과·절멸 공세.
7. 룰렛 확률·토큰 풀·행운 시스템.
8. 농장·시장·포탑·전술 명령 수치.
9. 3시간 캠페인과 해금 순서.
10. 절차 생성·난이도·제약 검증기.
11. UI/UX 전체 흐름.
12. 아트 바이블과 실루엣.
13. 건물·전장·VFX·아이콘 제작 계약.
14. 오디오와 피드백 계약.
15. 전체 GDD 정합성 최종 검수.

각 단계는 Codex 검수를 통과한 뒤 다음 단계로 넘어가되, 의존성이 없는 아트 패킷은 밸런스 작업과 병렬로 진행할 수 있다.
