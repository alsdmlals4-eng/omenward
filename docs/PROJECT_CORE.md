# 오멘워드 프로젝트 코어

- 판정일: 2026-07-22
- 기준 커밋: `69c571c5a49502f9da57e1c8d8eba04455380c0f`
- 상태: `CORE_CONFIRMED`
- 잠금 상태: `CORE_LOCKED`
- 책임: 제품 정체성·핵심 선택·불변 조건·검증 게이트의 최상위 책임 원본

이 문서는 기존 승인 기획과 실제 구현을 대조해 오멘워드의 프로젝트 코어를 분리한 책임 원본이다. 세부 수치와 콘텐츠는 관련 `APPROVED_*.md`가 소유하지만, 기능의 우선순위와 제거 가능성은 이 문서를 기준으로 판단한다.

사용자는 2026-07-22 대화에서 `코어확정`을 명시했다. 따라서 정체성 한 문장, 세 가지 플레이어 책임, 프로젝트 코어 분류, 불변 조건과 제거·대체 스트레스 테스트를 `CORE_CONFIRMED`·`CORE_LOCKED`로 확정한다.

## 1. 정체성 한 문장

> **예고된 세 전선의 위협을 읽고, 제한된 건물 노드로 룰렛 확률을 설계한 뒤, 당첨된 증원을 어느 전선에 투입할지 결정해 전황을 뒤집는 실시간 전략 오토배틀 게임.**

## 2. 플레이어 판타지

플레이어는 직접 병사 한 명을 조종하는 영웅이 아니라, 불완전한 증원 체계를 설계하고 세 전선의 위험을 배분하는 지휘관이다.

플레이어가 책임지는 것은 다음 세 가지다.

1. **예측** — 베일의 징조로 다음 공세의 라인·병종·수량·특수 행동을 읽는다.
2. **확률 설계** — 제한된 건물 노드와 전문화로 룰렛 토큰·출처·확률을 바꾼다.
3. **전선 커밋** — 얻은 병력을 어느 라인에 배치할지 결정하고 다른 라인의 위험을 감수한다.

## 3. 핵심 루프

```text
베일의 징조 확인
→ 건설 후보와 룰렛 확률 변화 비교
→ 제한 노드에 건설·전문화
→ 3×3 룰렛 회전·허용된 조작·최종 확정
→ 생성된 보상 확인
→ 상·중·하 라인 중 하나에 배치
→ 자동 교전·접전지·중간거점·성문 공방
→ 라인별 성공·실패 원인 확인
→ 다음 공세에 맞춰 건설·확률·배치를 수정
```

루프의 시작은 정보이며 끝은 학습이다. 무작위 결과만 소비하거나 전투를 관전하는 것으로 끝나면 코어 루프가 닫힌 것으로 판정하지 않는다.

## 4. 프로젝트 코어

### 4.1 기획 코어

- 적 공세는 대응 가능한 시간 전에 공개된다.
- 건설은 경제·방어뿐 아니라 미래 룰렛 결과의 확률과 출처를 바꾼다.
- 룰렛은 결과를 직접 선택하는 장치가 아니라, 플레이어가 사전에 설계한 확률을 시험하는 장치다.
- 당첨 결과를 어느 라인에 투입할지가 최종 전술 선택이다.
- 자동전투 결과는 거점·성문·승패와 다음 경제에 실제 영향을 준다.
- 실패 원인이 다음 건설·확률·배치 판단으로 환류한다.

### 4.2 시스템 코어

- 좌우 대칭의 독립된 상·중·하 3라인.
- 제한된 후방·전방 건설 노드와 점령에 따른 건설권·생산권 이전.
- 3×3 룰렛의 중앙 가로줄 기본 판정과 동일 심벌 완성선 기반 등급.
- 룰렛 결과 보관·배치와 재회전 잠금.
- 공용 병종 데이터와 진영별 표현 분리.
- 접전지·중간거점·성문·같은 라인 암살자 우회.
- 결정론적 시드·입력 로그·재현 가능한 핵심 결과.

### 4.3 기술 코어

기술 코어는 제품 정체성이 아니라 제품 코어를 안전하게 보존하는 기반이다.

- Godot + GDScript.
- typed Resource 기반 공용 데이터.
- 전투 규칙과 진영 Visual 데이터 분리.
- 이름 기반 RNG stream과 입력 기록.
- 승인 계약을 직접 검증하는 headless·정적 테스트.

## 6. 불변 조건

1. 세 라인은 일반 유닛이 자유롭게 횡단하지 않는 독립 전선이다.
2. 기본·일반 난이도에서는 치명적 공세 정보를 숨겨 난이도를 만들지 않는다.
3. 건물 선택은 룰렛 토큰·확률·출처 중 하나 이상에 관찰 가능한 영향을 준다.
4. 기본 룰렛 보상은 중앙 판정 줄이 성립할 때만 생성된다.
5. 룰렛 등급은 승인된 동일 심벌 완성선 규칙으로 계산한다.
6. 자동전투는 거점·성문·승패 상태를 실제로 변화시킨다.
7. 플레이어가 얻은 보상을 어느 라인에 투입할지 결정한다.
8. 패배와 손실의 핵심 원인을 플레이어가 확인할 수 있다.
9. 아군과 일반 적군의 병종 전투 데이터를 별도 복제하지 않는다.
10. 새 콘텐츠가 위 인과를 우회해 단독 정답이 되지 않도록 한다.

## 8. 코어 검증 게이트

### C0 — 정본 일치

- 프로젝트 코어, GDD, 로드맵, 현재 상태와 Issue가 같은 구현 단계를 가리킨다.
- `구현 전`, `완료`, `검증됨`을 실제 증거 없이 사용하지 않는다.

### C1 — 룰렛 인과

- 건물 전후 확률 변화가 실제 판정 데이터와 일치한다.
- 중앙 판정 줄·완성선·등급·출처·보상이 승인 계약대로 동작한다.
- 같은 시드와 확정 보드는 같은 결과를 만든다.

### C2 — 전장 목적 루프

- 배치된 유닛이 전투를 통해 접전지·거점·성문·승패를 바꾼다.
- 경제가 실제 점령 상태를 반영한다.
- 승리·패배는 외부 디버그 명령이 아니라 전장 상태에서 발생한다.

### C3 — 코어 UX

- 건설 전 확률 미리보기.
- 룰렛 토큰 장부.
- T-30/T-15/T-5 공세 전조.
- 상성·사거리·타기팅 오버레이.
- 웨이브 종료 후 라인별 원인 보고.
- 건설 선택 비교 UI.

### C4 — 사람 플레이

- 10~15분 안에 코어 루프를 최소 두 번 경험한다.
- 플레이어가 위협·확률 변화·배치 이유·패배 원인을 설명할 수 있다.
- 1920×1080과 1280×720에서 세 전선과 핵심 경고를 읽을 수 있다.

### C5 — 안정성

- 승인 계약 자동 테스트.
- Godot editor import와 headless 테스트.
- runtime smoke.
- 결정론 회귀와 성능 기준.

## 9. 현재 제외

다음은 코어 검증 전에 확대하지 않는다.

- 신규 병종과 복합 친화도.
- 대규모 영구 성장 트리.
- 직접 조작 영웅 전투.
- PvP·랭크·시즌.
- 랜덤 개별 능력치·각인·흡수 진화.
- 전체 캠페인 대사와 최종 아트 대량 생산.

## 10. 변경·잠금 규칙

- 이 문서의 분류와 불변 조건을 변경하려면 제거 테스트와 대안을 먼저 기록한다.
- `PROJECT_CORE` 변경은 단순 구현 편의나 콘텐츠 추가를 이유로 자동 승인하지 않는다.
- `CORE_CONFIRMED`·`CORE_LOCKED`는 2026-07-22 사용자의 `코어확정` 지시로 적용됐다.
- 잠금된 코어의 변경은 사용자 명시적 승인, 제거 테스트, 대안과 영향 범위 기록을 모두 요구한다.
- 후속 구현은 이 문서의 우선순위와 C1~C5 검증 게이트를 따른다.
