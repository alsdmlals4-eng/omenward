## 1. 정체성 한 문장

> **예고된 세 전선의 공세를 읽고, 제한된 건물로 세 원형 릴의 토큰 구조를 설계·영구 편집한 뒤, 당첨 병력을 어느 전선에 커밋할지 결정해 전황을 뒤집는 실시간 전략 오토배틀 게임.**

시장 차별화 문장:

> **3×3 슬롯으로 병력을 뽑는 게임이 아니라, 건물과 가로 이동으로 미래 룰렛 자체를 다시 쓰는 3전선 지휘 게임.**

짧은 제품 문구:

> **건물로 룰렛을 만들고, 룰렛으로 전선을 지휘한다.**

## 2. 플레이어 판타지

플레이어는 개별 병사를 직접 조종하는 영웅이 아니라, 불완전한 증원 체계와 세 전선의 위험을 설계하는 지휘관이다.

플레이어가 책임지는 핵심 판단은 네 가지다.

1. **예측** — 다음 공세의 라인, 병종, 정확한 수량과 특수 행동을 읽는다.
2. **릴 설계** — `TokenSource` 건물과 영구 가로 이동으로 세 원형 릴의 토큰·출처·인접 순서를 바꾼다.
3. **결과 조작** — 멈춘 3×3 보드를 세로 이동과 가로 이동으로 조작하고 명시적으로 확정한다.
4. **전선 커밋** — 보관·판매·배치 중 하나를 선택하고 병력을 한 라인에 되돌릴 수 없이 투입한다.

## 3. 핵심 루프

```text
스테이지 준비 진입
→ 무료 회전권 획득·첫 공세 전체 확인
→ 건설·업그레이드로 릴 토큰 구조 조정
→ 룰렛 회전·비가역 이동·결과 확정
→ 병력 보관·판매·라인 배치
→ 스테이지 시작
→ 자동 교전·접전지·본진 방어
→ 다음 웨이브 예고에 맞춰 대응
→ 스테이지 정산과 다음 준비
```

루프의 시작은 정보이고 끝은 다음 설계를 위한 학습이다. 무작위 결과만 소비하거나 자동전투를 관전하는 것으로 끝나면 코어 루프가 닫힌 것으로 판정하지 않는다.

## 4. PROJECT_CORE

### 4.1 제품 코어

- 좌우 대칭의 독립된 상·중·하 3라인.
- 기본·일반 난이도에서는 치명적 공세 정보를 숨기지 않는다.
- `TokenSource` 건물은 세 릴에 동일 출처 토큰을 하나씩 제공한다.
- 세 개의 가변 길이 원형 릴이 순서와 인접성을 가진다.
- 가로 이동은 현재 보드와 미래 릴 배열을 동시에 영구 편집한다.
- 중앙 가로줄이 기본 보상 판정의 선행 조건이다.
- 보상은 멈춤, 조작, 예측, 명시적 확정, 결과 처리의 트랜잭션을 거친다.
- 병력은 보관하거나 판매할 수 있지만 배치 후 라인 변경·회수·판매가 불가능하다.
- 일반 스테이지의 전술계획 정지와 위험 스테이지의 실시간 실행이 대비된다.
- 자동전투는 접전지, 본진 체력, 스테이지 승패와 다음 준비에 실제 영향을 준다.
- 결과 원인은 다음 건설·릴 조작·배치 판단으로 환류한다.

### 4.2 시스템 코어

- 각 릴은 길이 3 이상의 원형 `TokenInstance` 배열이다.
- 초기 릴은 각 3개의 X로 구성한다.
- X 교체는 가장 낮은 안정 배열 인덱스를 사용한다.
- 가로 이동은 노출 인덱스 사이의 `TokenInstance` 순환 교환이며 배열 길이와 cursor를 변경하지 않는다.
- 멈춤 시 immutable `SpinSnapshot`을 생성한다.
- 건물 파괴는 live 릴에는 반영하되 이미 멈춘 snapshot을 변경하지 않는다.
- 럭키는 자연 중앙줄 꽝에만 판정하며 숨김 실패 보정 `15/25/35/45/55/100%`를 사용한다.
- 전설 결과는 횟수·스테이지 주기 제한 없이 항상 전설 `PendingReward`로 생성한다.
- 플레이어 전장에는 생존 중인 전설 유닛을 최대 1기만 허용하며, 충돌 배치는 경고 동의와 커밋 순간 재검증 뒤 같은 세부 병종 영웅 2기로 원자 변환·배치한다.
- 맵런 상태는 건물, 병력, 체력, 자원, 릴 배열, 보관함, 럭키, 전설 PendingReward와 생존 전설 배치 상태, 접전지 상태를 유지한다.
- 코어 PoC와 첫 수직 슬라이스는 mid-run save를 지원하지 않는다.

### 4.3 기술 코어

- Godot 4.7.1 Standard, GDScript, Compatibility renderer.
- typed Resource와 명시적인 도메인 상태 객체.
- 공용 `UnitArchetypeProfile`과 진영 Visual 데이터 분리.
- 이름 기반 RNG stream과 재현 가능한 입력 로그.
- resolver, 릴 상태, 스핀 트랜잭션, 결과 처리, 맵런 시간 상태의 책임 분리.
- 승인 계약을 직접 검증하는 headless·Python·문서 테스트.

## 6. 불변 조건

1. 일반 유닛은 세 라인 사이를 자유롭게 횡단하지 않는다.
2. 기본·일반 난이도에서는 라인, 병종, 정확한 수량과 치명적 특수 행동을 사전에 공개한다.
3. `TokenSource` 건물 선택은 릴 토큰·출처·인접 순서 중 하나 이상에 관찰 가능한 영향을 준다.
4. 중앙 가로줄이 동일한 비-X 심벌 세 개가 아니면 다른 완성선을 무시한다.
5. 등급은 판정 심벌의 동일 완성선 수로 계산한다.
6. 가로 이동은 토큰 인스턴스와 출처를 이동시키며 실행 즉시 확정되고 되돌릴 수 없다.
7. 멈춘 보드의 보상은 immutable snapshot에서만 계산한다.
8. 보상은 명시적 확정 한 번에만 생성·지급한다.
9. 보관 중인 병력은 식량을 사용하지 않고, 배치 후에는 라인 변경·회수·판매가 불가능하다.
10. 식량 수용량 감소는 기존 병력을 제거하거나 약화하지 않고 신규 배치만 차단한다.
11. 자동전투는 접전지·본진·승패 상태를 실제로 변화시킨다.
12. 위험 스테이지는 전술계획 정지를 허용하지 않지만 공세 정보를 숨기지 않는다.
13. 아군과 일반 적군의 전투 병종 데이터를 별도 복제하지 않는다.
14. 전술 아이템 룰렛 심벌은 별도 승인 전 코어 심벌로 추가하지 않는다.
15. 코어 PoC와 첫 수직 슬라이스는 mid-run save를 지원하지 않는다.
16. 새 콘텐츠가 위 인과를 우회해 단독 정답이 되지 않도록 한다.
17. 전설 결과는 항상 전설 PendingReward로 보존하며, 생존 전설 충돌 배치는 사용자의 경고 동의 없이 자동 강등하지 않고 실제 커밋 순간 재검증한다.

## 8. 기존 검증 자산의 지위

`main@95e5ae2`에서 검증된 C1·C2·C3는 삭제하지 않는다.

```text
LEGACY_C1_ROULETTE_CORE_REMOTE_PROVEN
LEGACY_C2_BATTLE_OBJECTIVE_REMOTE_PROVEN
LEGACY_C3_AUTOMATED_CONTRACTS_PROVEN
```

다만 다음 구현 계약은 V2와 직접 충돌하므로 `LEGACY_IMPLEMENTED / MIGRATION_REQUIRED`다.

- 독립 9칸 가중 추첨.
- 스테이지당 전설 1회.
- 12% 공개 럭키와 +8%p 증가.
- 이동 되돌리기·전체 초기화·확정 시 소비.
- 60초 단일 공세와 T-30/T-15/T-5 단계 공개.
- 유닛별 점령력 합산과 중간거점 상태기 재사용.
- 단일 `StageRun` 중심의 런 수명주기.
- 계열 고정 상위 등급 템플릿.
- 아군 주기적 3기 출격 묶음.

보존 대상은 중앙 판정, 완성선·등급, 금화 75/200/500%, 결정론, 공용 병종, 3라인, 전투 원인 보고와 UI snapshot 경계다.

## 9. 코어 검증 게이트

### C0V2 — 정본 일치

- PROJECT_CORE, 통합 명세, 룰렛, 맵런, GDD, 현재 상태, 로드맵과 Issue가 같은 V2 상태를 말한다.
- `V2_IMPLEMENTATION_NOT_STARTED`와 기존 `LEGACY_*_PROVEN`을 섞지 않는다.
- 구형 active 규칙은 현재 정본이 아니라 legacy evidence로만 남는다.

### C1V2 — 물리 룰렛 인과

- X 교체, append, source 제거, wrap 노출과 cursor가 승인 규칙대로 동작한다.
- 가로·세로 이동과 preview가 결정론적이다.
- snapshot은 건물 파괴 뒤에도 동일 보상을 생성한다.
- 중앙 판정·완성선·등급·금화 resolver가 보존된다.
- 럭키 truth table과 전설 결과의 항상-전설 PendingReward 생성이 정확하다.

### C2V2 — 보관·배치·전장 목적

- 결과 초과가 손실이나 softlock을 만들지 않는다.
- 병력 사망 시 식량이 반환된다.
- 배치가 접전지·본진·승패를 실제로 바꾼다.
- 고정 8초 접전지와 전투 반경 규칙이 재현된다.
- 플레이어 생존 전설 최대 1기, 경고 동의, 커밋 순간 재검증, 충돌 시 동일 병종 영웅 2기 원자 배치가 정확하다.
