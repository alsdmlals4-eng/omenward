## 1. 한 문장 소개

> **예고된 세 전선의 공세를 읽고, 제한된 건물로 세 원형 릴의 토큰 구조를 설계·영구 편집한 뒤, 당첨 병력을 어느 전선에 커밋할지 결정해 전황을 뒤집는다.**

핵심 감정:

- 설계한 릴이 실제 결과로 돌아오는 기대.
- 멈춘 보드에서 이동 자원을 쓸지 판단하는 긴장.
- 보관과 영구 배치 사이의 장기 선택.
- 점령·건설·수리로 전선을 유지하는 운영 압박.
- 실패 원인을 이해하고 다음 릴·건물·배치를 수정하는 학습.

## 2. 세계관과 역할

플레이어는 루메른 왕국 트리븐 전선의 지휘관이다. 베일런 황야에서 넘어오는 베일종 공세를 상·중·하 세 전선에서 막는다. 벨루는 세계관, 튜토리얼, 공세 보고, 상황 조언과 감정 반응을 담당한다.

공식 명칭:

- 루메른 왕국.
- 루미엔 영토.
- 트리븐 전선.
- 실베른 성채.
- 베일런 황야.
- 베일의 법칙.
- 베일의 징조.
- 벨루.
- 베일종.

## 3. 핵심 루프

```text
스테이지 준비
→ 공세 확인·미션 선택
→ 건설·업그레이드·수리
→ 물리 룰렛 회전·이동·확정
→ 보관·판매·라인 배치
→ 일반 또는 위험 전투
→ 중앙 경합 지역·중간 거점·본진 공방
→ 정산·checkpoint 저장
→ 다음 준비
```

코어 PoC는 사용자 결정으로 건너뛴다. 버티컬 슬라이스는 20스테이지와 주요 시스템 전체를 연결하되 콘텐츠 폭만 최소화한다.

## 4. 전장

각 라인:

```text
아군 본진
→ 아군 중간 거점
→ 중앙 경합 지역
→ 적 중간 거점
→ 적 본진
```

- 상·중·하 3라인.
- 일반 병력의 자유로운 라인 횡단 없음.
- 진영당 본진 건설 노드 6개.
- 전체 중간 거점 6개, 거점당 건설 노드 3개.
- 중앙 경합 지역 3개.
- 전체 건설 노드 30개.
- 후방 거점을 잃어도 전진 병력은 후퇴·약화·소멸하지 않는다.
- 신규 증원만 후방 경로를 재확보해야 한다.

### 4.1 중앙 경합 지역

- 수비 병력을 제거한 뒤 고정 8초 점령을 초기 기준으로 사용.
- 점령속도는 유닛 수·Tier·등급과 무관.
- 적 진입 시 점령 정지.
- 점령 부대 소멸 시 유예 뒤 진행도 회복.
- 완료 전까지 기존 소유권과 골드/초 유지.
- 완료 순간 소유권과 골드/초 원자 이전.
- 주둔 병력이 없어도 소유권과 수입 유지.
- 점령 완료 전에는 적 중간 거점으로 진격하지 않음.

### 4.2 중간 거점

- 중앙 경합 지역을 소유해야 적 중간 거점 점령 가능.
- 적 중간 거점을 점령해야 적 본진으로 진격 가능.
- 점령 완료 순간 건설 권리와 건물 상태를 함께 처리.
- 호환 건물은 HP·Tier·진행도를 보존해 이전.
- 병영과 비호환 건물은 `BLOCKED`.
- `BLOCKED` 건물은 노드를 점유하고 모든 효과를 중지.

---

## 5. 물리 룰렛

- 세 개의 가변 길이 원형 릴.
- 초기 각 릴 X 3개.
- 각 물리 건설 노드는 릴마다 하나의 `SOURCE_BOUND_X` 결속 슬롯을 가짐.
- 금고는 `[금화]`, 병영은 병종 토큰을 각 릴에 하나씩 공급.
- X 교체는 안정 인덱스를 사용하고 X가 없으면 append.
- 세로 이동은 cursor 회전.
- 가로 이동은 선택 행 TokenInstance의 릴 간 순환 교환.
- 가로 이동은 배열 길이·cursor를 바꾸지 않고 미래 회전에도 유지.
- 이동은 실행 즉시 소비하며 undo 없음.
- 멈춤 보상은 immutable SpinSnapshot 사용.
- 건물 파괴·점령·BLOCKED는 live 릴만 변경하고 기존 snapshot과 PendingReward는 변경하지 않음.

---

## 6. 당첨과 보상

- 중앙 가로줄이 동일 비-X 심벌 3개일 때만 판정.
- 중앙 실패 시 다른 줄 무시.
- 동일 심벌 완성선 수로 일반/엘리트/영웅/전설 등급 산정.
- 금화 1/2/3개 이상 완성선은 실제 회전 비용의 75/200/500% 지급.
- 무료 회전의 기준 회전 비용은 pending 데이터.
- 전설 결과는 항상 전설 PendingReward로 생성하며 배치 제한은 별도 계약을 따름.
- 럭키는 자연 중앙줄 꽝에만 판정하고 숨김 실패 보정 사용.

금고 Tier는 금화 토큰 보상액이나 선택 가중치를 올리지 않는다. 금고 Tier는 지속 골드/초만 강화한다.

---

## 7. 보관·판매·식량

- 보관과 판매는 별도 건물이 아니라 플레이어 공통 런 시스템.
- 기본 보관함 4칸.
- 보관 중 식량 0.
- 초과 결과는 Pending 상태로 안전하게 유지.
- 미해결 결과 또는 완전한 보관함은 새 회전을 차단.
- 배치 병력은 식량을 점유하고 라인 변경·회수·판매 불가.
- 병력 사망 시 식량 반환.
- 식량 최대 감소는 기존 병력을 제거·약화하지 않고 신규 배치만 차단.

## 8. 건물

기본 건물 5종:

| 건물 | 역할 | 성장 |
|---|---|---|
| 금고 | 골드/초 + 금화 토큰 | 선형 T1→T3 |
| 농장 | 식량 생산·한도 | 선형 T1→T3 |
| 타워 | 방어 공격 | T2 분기, T3 계열 강화 |
| 병영 | 병종 토큰 | T2 병종, T3 전문화 |
| 지휘소 | 범위형 전장 버프 | T2 분기, T3 계열 강화 |

### 8.1 타워 분기

- Tier 1: 공통 기본 타워.
- Tier 2 연사탑: 지상·비행 단일 대상, 빠른 공격과 표적 전환.
- Tier 2 포격탑: 지상 광역, 느린 고피해, 비행 공격 불가.
- Tier 3: 선택 계열의 수치와 범위만 선형 강화.

### 8.2 지휘소 분기

- Tier 1: 공통 기본 지휘소.
- Tier 2 돌격 지휘소: 범위 내 공격속도·이동속도 강화.
- Tier 2 수비 지휘소: 범위 내 방어력·강제 이동 저항 강화.
- Tier 3: 선택 계열 오라 강도·범위 선형 강화.
- 동일 계열 중첩 시 가장 높은 Tier만 적용.
- 돌격과 수비 계열은 함께 적용 가능.

### 8.3 건물 공격 가능성

- 타워는 건설 시작 순간부터 직접 공격 가능.
- 완공 전에는 공격 기능 비활성.
- 금고·농장·병영·지휘소는 직접 및 부수 피해 대상이 아님.
- 비전투 건물은 거점 점령으로 제어권을 바꿈.

### 8.4 파괴

- HP 0에서 건물 완전 제거.
- 잔해와 재건 없음.
- 노드 즉시 EMPTY.
- 새 건설 즉시 가능.
- 이미 소비된 비용 환불 없음.
- 미소비 프로젝트 에스크로만 원래 자금 제공자에게 반환.

---

## 9. 수리

- 별도 수리공방·작업자·임금 없음.
- 손상된 건물마다 수리 작업 하나 부착 가능.
- 여러 건물을 동시에 수리 가능.
- 같은 건물에 수리 중첩 불가.
- 실제 회복 HP만큼 골드를 실시간 차감.
- 골드 부족 시 가능한 만큼 회복 후 자동 일시정지.
- 최대 HP 도달 시 자동 종료.
- 처리 순서: 피해 → 파괴 확정 → 생존 건물 수리.

정확한 초당 회복량과 HP당 골드 비용은 경제 시뮬레이션 후 확정한다.

## 10. 병종 성장

Tier 1은 공통 보병이다.

Tier 2 10병종:

1. 방패병
2. 대검전사
3. 암살자
4. 창병
5. 궁병
6. 기병
7. 사제
8. 마법사
9. 비행병
10. 거인

Tier 3는 각 Tier 2에서 두 전문화, 총 20종이다.

- 방패병: 철벽수호병 / 호위병
- 대검전사: 파쇄검병 / 광폭전사
- 암살자: 그림자암살자 / 맹독암살자
- 창병: 장창병 / 미늘창병
- 궁병: 석궁병 / 연사궁병
- 기병: 중기병 / 충격기병
- 사제: 치유사제 / 전쟁사제
- 마법사: 원소술사 / 주술사
- 비행병: 천공창기병 / 폭풍익병
- 거인: 파성거인 / 고대거신

병종 업그레이드는 작업자 없이 여러 병영에서 병렬 진행할 수 있다. 확정 시 전체 비용을 지갑에서 차감하고 에스크로에서 소비·미소비를 분리한다. 취소 시 미소비 100%와 소비 비용 50%를 반환한다.

## 11. 방패병 계열

### 11.1 공통 표적 우선도

점수가 낮을수록 선호한다.

```text
방패병 1.0 < 기타 근거리 1.4 < 원거리 1.8
```

총점:

```text
병종 가중치
+ 예상 교전 도달시간 ÷ 2초
+ 가장 강한 전문 프로필 보정 하나
+ 전술 보정
```

- 공격 주기 완료 후 재평가.
- 새 표적이 20% 이상 우수해야 전환.
- 사망·무효·도달 불가는 즉시 전환.
- 암살·대공·공성·방패파괴·보스 전문 프로필 사용.

### 11.2 호위병

- 원형 반경 2.5D.
- 라인 제한 없음.
- 보호 대상의 방어 후 HP 손실 25%를 호위병이 대신 부담.
- 직접·광역 피해 포함.
- 지속·환경·이미 전달된 피해 제외.
- 가장 가까운 유효 호위병 하나만 선택.
- 호위병 계열은 보호 대상에서 제외.
- 완전 행동불능 상태에서 보호 중단.

### 11.3 철벽수호병

| 단계 | 정지시간 | 직접·광역 피해 감소 | 강제 이동 저항 |
|---:|---:|---:|---:|
| 0 | 0초 | 0% | 0% |
| 1 | 2초 | 10% | 25% |
| 2 | 5초 | 20% | 50% |
| 3 | 10초 | 40% | 100% |

- 이동 누적 1초마다 1단계 하락.
- 부분 이동시간은 정지 중 보존.
- 3단계는 일반 전투 강제 이동 면역.
- 예외 재배치 성공 시 즉시 0단계.
- 추적 반경: 0단계 무제한, 1단계 2.5D, 2단계 1.25D, 3단계 추적 없음.

## 12. 벨루

### 벨루의 조언

- 한 문장 자동 상황 조언.
- 비상호작용, 입력 차단·자동 일시정지 없음.
- 우선순위 큐, 중복 억제, 주제별 쿨다운.
- 기본 빈도 표준, 낮음, 끔.

### 벨루 팁

- 수동 비모달 패널.
- 추천 병종 최대 2개.
- 이유와 단점을 함께 표시.
- 자동 선택과 숨은 보너스 없음.
- 패널을 연 RecommendationSnapshot 유지.
- 상황 변경 시 오래됨 표시 후 수동 새로고침.

## 13. 맵런과 시간

표준 MapRun은 20스테이지다.

- 일반: 3웨이브.
- 위험: 4웨이브.
- 최종: 5웨이브.
- 매 5번째 스테이지 위험.
- 준비 화면은 무제한·안전.
- 일반 전투는 전술계획 정지와 예약 명령.
- 위험 전투는 전술계획 정지 없음.
- 전술계획 정지는 전투, 점령, 회복, 수리, 경제를 모두 정지.
- 건물, 병력, HP, 자원, 릴, 보관, 영토는 MapRun 안에서 스테이지 사이 유지.

### 13.1 저장

- 활성 전투 임의 프레임 저장은 제외.
- 준비 화면 진입과 스테이지 정산 완료 시 versioned checkpoint 자동 저장.
- 불완전 저장은 이전 정상본을 대체하지 않음.
- 저장 스키마와 migration 세부는 후속 결정.

## 14. 웨이브와 경제

- 기준 일반 웨이브 60초.
- 웨이브 사이 기본 10초.
- 본진 보장 수입 초기값 1.5골드/초.
- Tier 1 금고 지속 수입 초기값 1.0골드/초.
- 중앙 경합 지역 초기 보너스 지역당 0.25골드/초.

금화 토큰 기대수익이 추가되므로 건설비, 업그레이드비, 수리비, 판매가, 회전 비용은 100,000시드 시뮬레이션 전 잠정값이다.

## 15. 미션·메타 성장

버티컬 슬라이스에 포함하되 세부 수치는 pending이다.

- 스테이지 미션 카드 3개 중 1개 선택 또는 거부.
- 쉬움/보통/어려움 점수 1/2/3.
- 최종 등급 요소: 미션, 클리어 시간, 영토 장악률, 본진 HP.
- 영구 성장: 경제, 보급, 방어, 전술, 룰렛 준비, 병사.
- 룰렛 직접 당첨 확률과 등급 확률은 영구 성장으로 올리지 않음.
- 단일 메타 재화와 상한형 시작 강화 방향 유지.

---

## 16. 현재 구현 상태

현재 main의 C1·C2·C3는 legacy 설계 기준 실행 증거다. 최신 버티컬 슬라이스의 물리 릴, 금고·병영 TokenSource, 5구간 전장, 30노드 건설, 점령 이전, 직접 수리, Tier 분기, 20스테이지 checkpoint, 벨루 조언은 구현·검증되지 않았다.

```text
LATEST_USER_DESIGN_INTEGRATED
+ ADVERSARIAL_REVIEW_RECORDED
+ PRODUCT_CODE_NOT_CHANGED
+ VERTICAL_SLICE_NOT_IMPLEMENTED
+ AUTOMATED_CONTRACTS_NOT_RUN
+ HUMAN_QA_NOT_RUN
+ CORE_LOCK_NOT_ALLOWED
```

## 17. 완료 금지

자동 계약과 사람 플레이 전에는 다음 표현을 사용하지 않는다.

- `VERTICAL_SLICE_IMPLEMENTED`
- `VERTICAL_SLICE_PROVEN`
- `CORE_LOCK`
- `MVP_COMPLETE`
