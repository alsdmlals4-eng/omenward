# 개발 로드맵

모든 단계는 이전 단계의 관찰 가능한 완료 기준을 통과한 뒤 진행한다.

## Phase P — 프리프로덕션 디자인 프리즈

- `docs/design/DESIGN_FREEZE_CHECKLIST.md`의 핵심 계약 검토
- 한 판 구조, 시작 조건, 승패와 시간 흐름 확정
- 룰렛 보상, 대기칸, 럭키 찬스와 실패 처리 확정
- 건물 Tier, 파괴·폐허·철거와 경제 계약 확정
- 유닛 상태, 타기팅, 상성, 접전지와 웨이브 규칙 확정
- 필수 UI, 경고, 결과 원인 보고와 튜토리얼 범위 확정
- Godot 데이터 스키마, 상태 소유, 성능 예산과 검증 시나리오 제안

완료 기준:

- Codex가 주요 규칙과 상태 전이를 임의 해석할 필요가 없다.
- MVP 포함·제외 범위가 명시돼 있다.
- 경계·실패 상황의 기대 동작이 정리돼 있다.
- 수직 슬라이스 필수 UX와 공개 정보가 정리돼 있다.
- 밸런스 수치는 코드 상수가 아니라 데이터 조정 대상으로 분리돼 있다.
- 구현 전 검증 시나리오가 작성돼 있다.

## Phase 0 — Godot 기술 기반 구축

- Godot 정확한 stable 버전과 Windows PC 우선 여부 확정
- GDScript 기반 최소 프로젝트 생성
- `scenes/`, `scripts/`, `data/`, `resources/`, `tests/` 기본 구조 확정
- 2D/2.5D 카메라와 아트 파이프라인 결정
- 데이터 정의, 테스트, 빌드 명령 확정
- Godot headless 파싱·실행 검증 구성
- 기준 해상도와 stretch 정책 확정
- 맵 단위, 기본 이동속도·사거리와 최대 동시 유닛 목표 정의

완료 기준:

- 새 개발자가 README의 명령만으로 Godot 프로젝트를 열고 실행할 수 있다.
- 빈 메인 Scene이 오류 없이 실행된다.
- Godot headless 검증의 최소 루프가 동작한다.
- `.godot/`과 로컬 생성물이 Git에서 제외된다.
- 맵 단위와 사거리 기준이 수치로 정의된다.

## Phase 1 — 3라인 전장 시뮬레이션

- 본진, 전방 거점, 접전지, 이동 구간 배치
- 검사 더미 유닛의 자동 이동과 교전
- 라인별 전투 분리
- 기본 승패 판정
- 디버그 오버레이로 좌표, 라인, 사거리 확인
- 기본 포탑 위치에서 중앙 접전지까지의 거리를 테스트 데이터로 고정

## Phase 2 — 건설과 경제

- 후방 6개, 라인별 전방 3개 노드
- 농장, 시장, 훈련소, 포탑
- 금화·식량
- 건물 완공, 파괴, 폐허, 재건설
- 고정형 3티어 상승 및 생산 타이머
- 건설 선택 비교 UI
- 기본 포탑이 접전지에 닿지 않는 거리 검증

## Phase 3 — 룰렛과 배치

- 건물 기반 릴별 토큰 풀
- X 토큰 자동 충전·제거
- 3×3 회전과 선택 줄 판정
- 유닛 대기칸
- 원하는 라인으로 출전
- 토큰 장부와 건설 전 확률 변화 UI
- 럭키 찬스 실패 누적 보정의 데이터 구조

## Phase 4 — 상성과 접전지

- 검사, 기병, 창병, 궁병
- 상성 배율 데이터
- 라인별 접전지 점령
- 점령 수입과 접전 중 처리
- 상성·사거리·타기팅 오버레이
- 1대1 및 소규모 자동 밸런스 테스트

## Phase 5 — 적 웨이브

- 적 건물 기반 웨이브 생성
- T-30, T-15, T-5 전조 UI
- 일반 난이도 라인·병종·정확한 수량 공개
- 웨이브 확정 시점
- 적 건물 파괴가 현재/다음 웨이브에 미치는 영향
- 웨이브 종료 후 라인별 결과 원인 보고

## Phase 6 — 런 빌드와 특수 병종

- 상점
- 스킬북과 장비
- 럭키 찬스 실제 조작
- 사제, 마법사, 도적
- 영웅 스킬

## Phase 7 — 콘텐츠와 폴리시

- 맵 변형
- 특수 웨이브
- 난이도와 튜토리얼
- 선택형 건물 Tier 전문화 실험
- 아트·사운드 교체
- 성능 최적화
- 저장 및 설정
