# 개발 로드맵

모든 단계는 이전 단계의 관찰 가능한 완료 기준을 통과한 뒤 진행한다.

## Phase P — 프리프로덕션 디자인 프리즈

- `docs/design/DESIGN_FREEZE_CHECKLIST.md`의 핵심 계약 검토
- 승인된 한 판 구조와 시작 조건을 `docs/design/APPROVED_MATCH_STRUCTURE.md`에서 관리
- 첫 공개 프로토타입의 약 3시간 캠페인 구성 확정
- 수동 설계 튜토리얼 1개와 이후 절차적 정규 스테이지 구조 확정
- 튜토리얼의 전체 학습 순서, 단계별 해금, 체크포인트와 종합 시험 확정
- 절차적 스테이지 생성기의 시드, StageManifest, 난이도, Threat Budget, Validator 계약 확정
- 플레이어 선택형 제약의 점수, 카테고리, 충돌 규칙, 보상과 Validator 계약 확정
- 룰렛 보상, 대기칸, 럭키 찬스와 실패 처리 확정
- 건물 Tier, 파괴·폐허·철거와 경제 계약 확정
- 유닛 상태, 타기팅, 상성, 접전지와 웨이브 규칙 확정
- 특수 적의 역할, 전조, 공격 우선순위와 등장 순서 확정
- 필수 UI, 경고, 결과 원인 보고와 튜토리얼 범위 확정
- Godot 데이터 스키마, 상태 소유, 성능 예산과 검증 시나리오 제안

완료 기준:

- Codex가 주요 규칙과 상태 전이를 임의 해석할 필요가 없다.
- MVP와 첫 공개 프로토타입의 포함·제외 범위가 명시돼 있다.
- 경계·실패 상황의 기대 동작이 정리돼 있다.
- 수직 슬라이스 필수 UX와 공개 정보가 정리돼 있다.
- 밸런스 수치는 코드 상수가 아니라 데이터 조정 대상으로 분리돼 있다.
- 절차적 생성과 제약 적용 결과가 재현·검증 가능한 데이터 계약으로 정의돼 있다.
- 구현 전 검증 시나리오가 작성돼 있다.

## Phase 0 — Godot 기술 기반 구축

- Godot 정확한 stable 버전 확정
- GDScript 기반 최소 프로젝트 생성
- `scenes/`, `scripts/`, `data/`, `resources/`, `tests/` 기본 구조 확정
- 2D/2.5D 카메라와 아트 파이프라인 결정
- 데이터 정의, 테스트, 빌드 명령 확정
- Godot headless 파싱·실행 검증 구성
- 기준 해상도와 stretch 정책 확정
- 맵 단위, 기본 이동속도·사거리와 최대 동시 유닛 목표 정의
- 난수 시드와 결정론적 테스트를 지원할 시간·난수 서비스 계약 제안

완료 기준:

- 새 개발자가 README의 명령만으로 Godot 프로젝트를 열고 실행할 수 있다.
- 빈 메인 Scene이 오류 없이 실행된다.
- Godot headless 검증의 최소 루프가 동작한다.
- `.godot/`과 로컬 생성물이 Git에서 제외된다.
- 맵 단위와 사거리 기준이 수치로 정의된다.
- 같은 시드를 테스트에 전달할 수 있는 최소 seam이 존재한다.

## Phase 1 — 3라인 전장 시뮬레이션

- 본진, 전방 거점, 접전지, 이동 구간 배치
- 검사 더미 유닛의 자동 이동과 교전
- 라인별 전투 분리
- 기본 승패 판정
- 디버그 오버레이로 좌표, 라인, 사거리 확인
- 기본 포탑 위치에서 중앙 접전지까지의 거리를 테스트 데이터로 고정

## Phase 2 — 건설과 경제

- 후방 6개, 라인별 전방 3개 노드
- 농장, 시장, 훈련소, 포탑
- 금화·식량
- 건물 완공, 파괴, 폐허, 재건설
- 고정형 3티어 상승 및 생산 타이머
- 건설 선택 비교 UI
- 기본 포탑이 접전지에 닿지 않는 거리 검증

## Phase 3 — 룰렛과 배치

- 건물 기반 릴별 토큰 풀
- X 토큰 자동 충전·제거
- 3×3 회전과 선택 줄 판정
- 유닛 대기칸
- 원하는 라인으로 출전
- 토큰 장부와 건설 전 확률 변화 UI
- 럭키 찬스 실패 누적 보정의 데이터 구조

## Phase 4 — 상성과 접전지

- 검사, 기병, 창병, 궁병
- 상성 배율 데이터
- 라인별 접전지 점령
- 점령 수입과 접전 중 처리
- 상성·사거리·타기팅 오버레이
- 1대1 및 소규모 자동 밸런스 테스트

## Phase 5 — 적 웨이브

- 적 건물 기반 웨이브 생성
- T-30, T-15, T-5 전조 UI
- 일반 난이도 라인·병종·정확한 수량 공개
- 웨이브 확정 시점
- 적 건물 파괴가 현재/다음 웨이브에 미치는 영향
- 웨이브 종료 후 라인별 결과 원인 보고
- 첫 60초와 첫 웨이브 튜토리얼 계약 적용

## Phase 6 — 절차적 스테이지 생성기

- 튜토리얼을 생성기 대상에서 제외
- 결정론적 시드와 생성 규칙 버전
- `StageArchetype`, `MapTemplate`, `EnemyBuildArchetype`, `WavePatternCard`
- `DifficultyProfile`과 Threat Budget
- 생성 결과를 고정하는 `StageManifest`
- 맵 거리·포탑 사거리·해금·전조 일치 공정성 Validator
- 생성 실패 시 검증된 안전 스테이지 대체
- 같은 시드 및 새 시드 재도전
- 시드·난이도·예산·웨이브 타임라인을 확인하는 개발자 도구
- 다수 시드 headless 일괄 생성 검증

완료 기준:

- 같은 시드·난이도·생성기 버전은 같은 StageManifest를 만든다.
- 모든 생성 결과가 핵심 공정성 규칙을 통과한다.
- 전조 정보와 실제 출격이 일치한다.
- 기본 포탑은 모든 생성 맵에서 접전지에 닿지 않는다.
- 생성 실패가 게임 중단이 아니라 안전 스테이지 대체로 처리된다.

## Phase 7 — 특수 적과 런 빌드

- 상점
- 스킬북과 장비
- 럭키 찬스 실제 조작
- 사제, 마법사, 도적
- 영웅 스킬
- 공성병, 돌격형, 지원형, 침투형, 지휘관형 특수 적
- 특수 적의 아이콘, 역할, 목표와 대응 수단 전조
- 특수·공성·침투·결전 Wave Pattern Card

## Phase 8 — 튜토리얼 스테이지

- 절차적으로 생성하지 않는 고정 튜토리얼 맵과 웨이브
- 카메라·건설·룰렛·대기칸·배치·상성·전조·접전지·전방 시설·Tier 학습
- 단계별 기능 해금과 설명 중 일시정지
- 구간 체크포인트와 구간 재시작
- 마지막 세 라인 종합 시험
- 튜토리얼 완료 후 제약 시스템 해금

완료 기준:

- 첫 플레이어가 외부 설명 없이 핵심 시스템을 모두 한 번 이상 사용한다.
- 각 학습 단계의 성공 조건과 실패 복구가 명확하다.
- 튜토리얼 중 특수 적이나 제약이 핵심 학습을 방해하지 않는다.
- 종합 시험에서 도움말 없이 건설·룰렛·배치·웨이브 대응을 수행할 수 있다.

## Phase 9 — 플레이어 선택형 제약 시스템

- 제약 데이터 스키마와 1~3점 위험도
- 경제·보급·룰렛·전장·적 강화 카테고리
- 튜토리얼 완료 후 정규 스테이지 준비 화면에서 선택
- 난이도·시드·제약을 포함한 StageManifest 생성
- 제약 충돌 태그와 선택 차단 이유 표시
- 제약 적용 후 공정성 Validator 재실행
- 점수 배율, 메달, 최고 제약 점수 기록
- 영구 전투력 보상 제외
- 개발자용 제약 프리셋과 일괄 검증

완료 기준:

- 제약 없음과 제약 적용 결과의 차이가 UI와 StageManifest에 일치한다.
- 금지 조합은 시작 전에 차단되고 이유가 표시된다.
- 같은 시드·난이도·제약은 같은 결과를 만든다.
- 제약이 최소 시작 빌드와 필수 대응 수단을 제거하지 않는다.
- 결과 화면에 적용 제약과 점수 배율이 기록된다.

## Phase 10 — 약 3시간 프로토타입 캠페인

- 수동 설계 튜토리얼 1개
- 난이도·맵·특수 적이 단계적으로 증가하는 정규 스테이지 여러 개
- 맵 골격, 적 건물 성향, 웨이브 패턴과 수정자 콘텐츠 세트
- 쉬움·보통·어려움 Difficulty Profile
- 제약 선택, 결과 화면과 재도전 흐름
- 스테이지별 검증된 안전 시드
- 목표 총 플레이 분량 165~195분 조정
- 다수 시드와 제약 조합 플레이테스트 및 난이도 분포 확인
- 아트·사운드 교체
- 성능 최적화
- 설정 저장과 캠페인 진행·최고 제약 기록 저장

## 후속 확장

- 선택형 건물 Tier 전문화
- 분기 캠페인과 경로 선택
- 온라인 일일 시드와 순위표
- 무한 모드와 영구 메타 성장
- 추가 맵 테마와 진영
- 정보 제한, 철인 모드 같은 고급 제약
