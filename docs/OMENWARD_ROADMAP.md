# 오멘워드 개발 로드맵

- 갱신일: 2026-07-16
- 기준: `docs/design/APPROVED_PREPRODUCTION_POC_BASELINE_V1.md`
- 모든 구현 단계는 Codex Plan Mode 제안서와 사용자 승인 후 시작한다.

## Phase P — 프리프로덕션 디자인 프리즈

완료된 구조:

- 오멘워드 공식명과 루메른·실베른·트리븐·베일런 명칭.
- 베일의 법칙·베일의 징조·벨루 단일 안내자.
- 좌우 대칭 독립 3라인과 라인별 성문.
- 라인별 중간거점 점령, 전방 2·후방 1 건설 노드, 건설권·기본 생산권 이전.
- 다른 길과 연결되지 않는 중앙 접전지.
- 암살자를 적 후방에 직접 배치하지 않고 안개 속 같은 라인 우회로로 침투시키는 구조.
- 전장 전체 조망과 미니맵 미사용 원칙.
- 활성 전투 시간 60초 공세 시계.
- 5 엘리트·10 영웅·15 전설 보스·20 신화 최종보스.
- 기본 병영 6종과 특수병단 4종의 플레이어 10병종.
- 적군 대칭 10병종 구조.
- 특수병단 최대 50% 준비 할인과 장기 자동생산.
- 시작 경제·시장·농장·포탑·룰렛·환불 기준.
- 공통 전투·Tier·등급·상태이상 PoC 계산.
- 10병종 일반·엘리트·영웅·전설 능력 계보 초안.
- 룰렛 목표 확률·금화 기대값·이동권·결과 보관함 초안.
- 1~20웨이브 Threat·편성·보스 초안.
- 건물 Tier 3·전술 명령·용병 초안.
- 튜토리얼·10스테이지 약 3시간 캠페인·절차 생성 초안.
- UI·아트·오디오·성능·데이터·테스트 계약 초안.

남은 프리프로덕션 검증:

- 중간거점 점령 시간·생산량·기존 건물 처리.
- 성문 HP·방어·공성 배율·재건 규칙.
- 암살자 우회 이동 시간·도착 범위·탐지 규칙.
- 확률·경제 표 계산과 최소 100,000시드 시뮬레이션.
- 최종 고유명·아트 시안·아이콘·오디오.
- 정확한 Godot stable 버전과 구현 구조.
- 튜토리얼 수직 슬라이스 Plan Mode 제안서.

## Phase 0 — Godot 기술 기반

- 정확한 Godot stable 버전 고정.
- 프로젝트·Scene·Script·Resource·Test 폴더 구조.
- 2D 픽셀 카메라와 1920×1080/내부 해상도 정책.
- 결정론적 난수·Manifest·입력 로그.
- real_time / active_combat_time / ui_planning_time 분리.
- UnitProfile·BuildingProfile·RankProfile·StageManifest 골격.
- BattlefieldProfile 또는 동등 데이터에 라인·성문·중간거점·접전지·우회로 구조 정의.
- headless 테스트 러너와 데이터 검증기.

완료 기준:

- 빈 스테이지를 headless로 로드하고 동일 시드 결과를 재현.
- 일시정지 중 active_combat_time이 증가하지 않음.
- 잘못된 데이터 참조가 시작 전에 검출됨.
- 3라인 연결 금지와 우회로 전용 병종 제약이 데이터 검증에서 확인됨.

## Phase 1 — 트리븐 3라인 전장

- 양측 본진과 상·중·하 라인별 성문.
- 양측 라인별 중간거점과 중앙 접전지.
- 상·중·하 고정 라인과 일반 횡단 금지.
- 중앙 접전지가 다른 라인과 연결되지 않는 이동 그래프.
- 주 도로와 성문·거점 전방의 넓은 전투 공간.
- 검사·소형 베일종 더미 이동·교전.
- 지상·비행 레이어 인터페이스.
- 기본 승패·성문 독립 상태·접전지 점령·디버그 오버레이.
- 기본 전략 줌에서 전체 전장을 표시하고 미니맵은 구현하지 않음.

## Phase 2 — 거점·건설·경제·생산

- 중간거점 전방 2·후방 1 건설 노드.
- 노드와 최대 크기 건물이 도로를 침범하지 않는 배치 검증.
- 중간거점 점령 상태와 건설권·기본 생산권 이전.
- 점령 중 기존 건물의 임시 처리 규칙.
- 기본 병영·특수병단·농장·시장·포탑.
- Planned→Constructing→Active→Upgrading→Ruins.
- 시작 금화 160·식량 12·기본/시장/접전지/거점 수입.
- 취소·철거·파괴 환불.
- Producing→ReadyWaitingFood→Delivered.
- 특수병단 준비도·최대 50% 할인·자동생산.

## Phase 3 — 룰렛·등급·배치

- 3×3 릴과 건물 기반 토큰 가중치.
- X·금화·이동권.
- 중앙 가로줄 기본 판정.
- 일반·엘리트·영웅·전설과 전설 1회 제한.
- 럭키 찬스·이동권·결과 보관함 3칸.
- 출처 건물 Tier 가중치와 일반/상위 등급 생성 경계.
- 100,000시드 확률·금화 EV 검증.

## Phase 4 — 기본 병영 6종 전투

- 방패병·대검전사·암살자·창병·궁병·기병.
- T2 자동생산과 T3 세부 병종·운영 교리.
- 일반·엘리트·영웅·전설 스킬 구조.
- 방어·마법저항·치명타·후방·돌진·대형·대공.
- 타기팅·제어 감소·전투 계측.
- 암살자 선택 시에만 우회로를 표시하고 배치 뒤 같은 라인의 적 후열로 이동.
- 암살자 직접 후방 생성 금지와 우회 중 점령 불가 검증.

## Phase 5 — 특수병단 4종 전투

- 사제·마법사·비행병·거인.
- 치유·버프·광역·제어·비행·공성.
- 특수병단 T3 분기.
- 자동생산 일반형과 룰렛 상위 등급.
- 높은 식량·생산시간·Threat 예산 검증.
- 거인과 공성형의 성문 공격 역할 검증.

## Phase 6 — 베일의 징조·1~15웨이브

- T-30/T-15/T-5 정보 공개.
- W1~15 Threat·라인 편성.
- 적군 대칭 10병종과 생산시설.
- 시설 파괴가 현재·다음 공세를 감소.
- W5 엘리트, W10 영웅, W15 전설 보스.
- 보스 직선 돌파·대단절·진군.
- 라인별 성문과 중간거점이 웨이브 진행에 미치는 영향 검증.

## Phase 7 — 초과전·신화·절차 생성

- W16~19 초과 공세.
- W20 신화 보스와 2페이즈.
- StageManifest·WavePatternCard·DifficultyProfile.
- 베일의 축복·저주·선언.
- Validator와 안전 Manifest 대체.
- 절차 생성 맵도 3라인 비연결, 성문 3개, 중간거점 노드 3개, 우회로 전용 규칙 유지.
- 다수 시드 headless 검증.

## Phase 8 — 전술·용병·상위 건물

- 바리케이드·화살비·강화지대·역병.
- 바리케이드가 도로를 영구 완전 봉쇄하지 않는 이동 검증.
- 용병 재고·갱신·가격·전용 지원병.
- 농장·시장·포탑 Tier 2·3.
- 기본 병영·특수병단 Tier 3.
- 거점 점령 전후 건물 작동과 소유권 처리 검증.

## Phase 9 — 실베른 성채 튜토리얼

- 벨루 단일 안내.
- 첫 병영·룰렛·검사·배치.
- 포탑 또는 바리케이드 역전.
- 이동권으로 엘리트 생성.
- 방패병·대검전사·암살자 중 하나 선택.
- 첫 네 공세·경제·계측.
- 중간거점 점령과 건설권 상실·회복 체험 시점 설계.
- 암살자 선택 시 안개 속 우회로가 드러나고 적 후열에 도달하는 튜토리얼.
- 10~15분 수직 슬라이스 완주.

## Phase 10 — 약 3시간 캠페인

- 튜토리얼 1 + 정규 9스테이지.
- 창병→궁병→사제→기병→마법사→비행→거인→전체 T3 해금.
- 스테이지별 신규 개념 최대 2개.
- 보스·서사 비트·벨루 기억 파편.
- 저장·재도전·결과 화면.
- 성문·거점·우회로 변주가 생겨도 기본 토폴로지는 유지.

## Phase 11 — UI·아트·오디오·최적화

- 1920×1080 HUD·룰렛·징조·특수병단 UI.
- 미니맵 없이 실제 전장 위에 성문·중간거점·접전지 상태 표시.
- 암살자 선택·배치 중에만 우회로 안개 해제와 경로 표시.
- 아군·적군 10병종 실루엣과 등급 시각 언어.
- 건물 건설·활성·업그레이드·파손·폐허.
- 벨루 표정·상태 반응·종 모티프.
- 최대 동시 객체·투사체·오라·VFX 성능 검증.
- 접근성·가독성·오디오 반복 제한.

## Phase 12 — 플레이테스트와 디자인 프리즈

- 웨이브별 잔존 Threat·경제·식량·병종 효율 계측.
- 중간거점 점령률·생산권 가치·성문 생존시간 계측.
- 암살자 우회 성공률·후열 피해·대응 가능 시간 계측.
- 룰렛 확률·금화 EV·영웅/전설 등장 시점 검증.
- 보스 30~60초 목표 전투시간 검증.
- 특정 빌드의 상위호환·무한 지연·경제 폭주 제거.
- 구조 변경 없이 수치표 최종 조정.
