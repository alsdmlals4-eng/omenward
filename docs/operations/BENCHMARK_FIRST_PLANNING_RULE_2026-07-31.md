# 오멘워드 Benchmark-First 기획 원칙

- 적용 범위: 오멘워드의 기획, 검토, 문서화, 향후 실행 계획
- 제품 코드 권한: `NONE`
- Google Sheet 쓰기 권한: `NONE`

## 1. 핵심 원칙

오멘워드 작업에서 매번 대규모 조사를 반복하지 않는다. 다만 다음 항목을 새로 설계하거나 기존 구조를 실질적으로 변경할 때는 **설계안을 작성하기 전에 관련 벤치마킹을 먼저 수행한다.**

1. 새 시스템
2. 핵심 게임 규칙
3. 콘텐츠 구조와 콘텐츠 생산 체계
4. UX 흐름과 정보 구조
5. 플레이 세션·성장·난이도 구조의 중대한 변경

벤치마킹은 타 작품의 기능을 복제하기 위한 절차가 아니다. 검증된 설계 패턴, 실패 위험, 정보량, 선택 구조와 플레이어 경험을 비교해 오멘워드에 필요한 원칙을 추출하는 절차다.

## 2. 반복 조사를 생략할 수 있는 작업

다음 작업은 기존 조사와 승인 근거가 유효하면 새 대규모 조사를 요구하지 않는다.

- 오탈자·문장·표·링크 정리
- 이미 승인된 규칙의 수치 조정안 작성
- 승인된 데이터 스키마에 콘텐츠 항목 추가
- 기존 UI의 라벨·간격·정렬과 같은 국소 폴리싱
- 이미 조사된 동일 문제의 후속 보완
- 문서 간 충돌·누락·구형 참조 정리

단, 국소 수정처럼 보여도 플레이어 행동, 선택 구조, 정보 우선순위 또는 핵심 루프를 바꾸면 벤치마킹 대상이다.

## 3. 벤치마킹 강도

### 3.1 경량 벤치마킹 — 기본

새 설계마다 기본적으로 사용한다.

- 직접 관련성이 높은 작품·시스템 `3~5개`
- 공식 페이지, 공식 문서, 개발자 자료 또는 신뢰 가능한 1차 자료 우선
- 비교 범위는 현재 결정에 필요한 메커닉으로 제한
- 조사 결과는 `유지할 원칙 / 피할 위험 / 오멘워드 적용안`으로 요약

### 3.2 확장 벤치마킹 — 조건부

다음 경우에만 대규모 조사를 수행한다.

- 프로젝트 방향 또는 핵심 루프 변경
- 상업 출시 전략과 직결되는 경쟁력 판단
- 기존 조사 결과가 서로 충돌
- 새 장르·플랫폼·수익 모델 진입
- 사용자 또는 독립 검토자가 추가 근거를 요구

## 4. 설계 전 필수 산출물

벤치마킹 대상 작업은 설계안을 제시하기 전에 최소한 다음을 기록한다.

```text
Benchmark target
→ 비교 대상과 선택 이유
→ 검증된 패턴
→ 오멘워드에 맞지 않는 요소
→ 적용할 설계 원칙
→ 현재 제안에 미친 영향
```

비교 대상 이름만 나열하거나, 인기·평점만 근거로 기능을 채택하지 않는다.

## 5. 적용 규칙

- 벤치마킹 결과보다 오멘워드 최신 정본과 사용자 결정이 우선한다.
- 다른 게임의 고유 표현, 수치, 콘텐츠를 그대로 복사하지 않는다.
- 상충하는 사례가 있으면 장단점과 선택 이유를 함께 기록한다.
- 조사 당시 사실과 설계자의 추론을 구분한다.
- 이미 확보한 조사 근거가 현재 결정에 충분하면 재사용하고 조사 날짜와 범위를 표시한다.
- 새로운 핵심 차이가 생기면 필요한 범위만 보충 조사한다.
- 조사 완료는 설계 승인이나 구현 권한을 의미하지 않는다.

## 6. 기획 게이트

```text
CONTEXT REVIEW
→ BENCHMARK REQUIRED 여부 판정
→ 경량 또는 확장 벤치마킹
→ 비교 원칙 추출
→ 오멘워드 설계안 제시
→ 사용자 승인
→ 기획 정본 후보 기록
→ 자체 검토
→ 독립·적대적 검토
→ 사용자 최종 승인
→ 별도 Codex 실행 계획
```

벤치마킹이 필요한 작업에서 조사 근거 없이 바로 구현 계획이나 Codex Goal로 이동하는 것을 금지한다.

## 7. 현재 적용

이 원칙의 첫 적용 대상은 다음 기획이다.

- Vertical Slice 콘텐츠 Manifest
- 미션 카드 최소 풀과 보상 구조

현재 비교 대상은 직접 관련 메커닉을 기준으로 선별하며, 전수 시장조사는 수행하지 않는다.

## 8. 검수 체크

새 설계 문서에는 다음 질문에 대한 답이 있어야 한다.

- 기존 벤치마킹을 재사용했는가, 새 조사가 필요한가?
- 새 조사가 필요했다면 왜 필요한가?
- 비교 대상은 현재 결정과 직접 관련되는가?
- 단순 기능 모방이 아니라 설계 원칙을 추출했는가?
- 오멘워드 최신 정본과 충돌하지 않는가?
- 조사 결과가 설계 선택에 실제로 반영되었는가?
- 벤치마킹 완료와 구현 승인을 혼동하지 않았는가?
