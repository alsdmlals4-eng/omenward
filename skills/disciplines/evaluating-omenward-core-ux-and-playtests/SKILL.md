# Omenward Core UX and Playtests

Skill ID: `discipline.omenward-core-ux`

`skills/SHARED_EXECUTION_CONTRACT.md`를 따른다.

## 사용 조건

첫 10~15분 핵심 플레이테스트, HUD·가독성, 실패 원인 이해, 1920×1080·1280×720 화면 검증, 선택 피드백 또는 `CORE_LOOP_PROVEN` 판정이 필요할 때 사용한다.

## 사용하지 않는 조건

플레이어가 보지 않는 내부 코드 정리나 순수 에셋 제작에는 주 Skill로 사용하지 않는다. 자동 테스트만 존재하는 상태에서 인간 이해도를 판정하는 데 사용하지 않는다.

## 고유 책임

플레이어가 위협 예고를 읽고, 건설 선택이 미래 룰렛 구조에 미친 영향을 이해하고, 획득 유닛을 적절한 라인에 배치해 전황을 바꾼 뒤 그 결과를 다음 설계에 활용할 수 있는지 실제 관찰로 검증한다.

## 핵심 질문

첫 10분 안에 신규 플레이어가 다음 인과 사슬을 최소 두 번 스스로 연결하는가?

```text
전조·라인 위협 인식
→ 건물·토큰 또는 전술 선택
→ 룰렛 결과 이해
→ 유닛 보관·판매·라인 배치
→ 접전지·거점·성문 결과 확인
→ 다음 공세를 위한 설계 변경
```

한 세션에서는 한 가지 우선 가설만 검증한다. 예: 건물이 릴 구조를 바꾼다는 인식, 3라인 우선 대응 이유, 이동 아이템 사용 이유, Tier 패시브와 등급 액티브의 이해.

## Session contract

| Field | Define |
|---|---|
| Build and seed | 정확한 branch, commit, build, map/stage/wave, seed와 known issue |
| Participant | 장르 경험과 프로젝트 사전 노출 여부 |
| Task | 정답을 암시하지 않은 플레이어 목표 |
| Expected decision | 가설을 검증하는 관찰 가능한 선택 1개 |
| Evidence | 화면 녹화, 이벤트 로그, 행동 시간, think-aloud 또는 사후 설명 |
| Guardrail | 좌절, 접근 불가 입력, 읽기 불가능한 HUD, 버그와 진행자 유도 |
| Pass rule | 행동과 설명이 함께 충족해야 하는 기준 |
| Stop rule | 관찰을 무효화하는 버그 또는 누락 전제 |

스크립트 승리, 진행자의 정답 유도 또는 한 번의 운 좋은 룰렛 결과를 코어 루프 증거로 사용하지 않는다.

## 관찰 절차

1. 정상 전략 화면을 제공하고 개발자 위협 태그나 대체 미니맵을 노출하지 않는다.
2. 클릭 전에 가장 긴급한 라인과 다음 행동의 이유를 설명하게 한다.
3. 건물·토큰 변화와 이후 룰렛 결과의 인과를 연결하는지 관찰한다.
4. 획득 유닛의 라인 선택과 예상 효과를 말할 수 있는지 확인한다.
5. 접전지 결과가 바뀐 이유를 묻고 권위 있는 전투·소유권 이벤트와 대조한다.
6. 다음 예고에서 이전 결과를 이용해 계획을 바꾸는지 확인한다.
7. 세션 종료 후 핵심 루프 설명과 가장 큰 혼란 1개를 기록한다.
8. 1920×1080과 1280×720에서 잘림, 대비, 정보 우선순위와 상태 구분을 별도로 확인한다.

## 결과 분류

- `LOOP_PROVEN`: 행동과 설명이 필요한 인과를 모두 증명한다.
- `UX_GAP`: 규칙은 작동하지만 정보 계층, 피드백 또는 입력이 이해를 막는다.
- `RULE_GAP`: UI는 이해되지만 의미 있는 선택을 만들 규칙이 부족하다.
- `CONTENT_GAP`: 시나리오가 읽을 수 있는 대비나 결과를 만들지 못한다.
- `TECHNICAL_BLOCKED`: 빌드, 성능, 입력 또는 버그가 관찰을 무효화한다.
- `NOT_RUN`: 인간 플레이 증거가 없다.

## 출력

가설, 참가자 맥락, build/seed, 관찰 선택, 설명 증거, 실패, 결과 분류, 정확한 문서·상태 갱신과 가장 작은 후속 변경을 기록한다. 검증하지 않은 접근성·성능·해상도 주장은 `NOT_RUN`으로 유지한다.

## 고유 검수

자동화 통과를 인간 이해 증거로 대체하거나, 플레이 영상 없이 C4·`CORE_LOOP_PROVEN`을 완료 처리하거나, 진행자가 올바른 건물·룰렛 이동·라인을 유도하거나, 해상도별 증거 없이 가독성을 통과 처리하면 실패다.
