# OMENWARD 공통 실행 계약

개별 스킬은 고유 판단만 담당한다. 이 계약과 [AGENTS](../AGENTS.md)의 운영 규칙을 반복 복제하지 않는다.

## 권위와 범위

현재 사용자 지시 → 프로젝트 AGENTS의 읽기 순서와 현재 승인 owner → 실제 consumer·증거 → 채택한 Base 방법 → 외부 참고 순으로 적용한다. 승인된 Plan/Issue는 명시 범위의 실행 근거이며 AGENTS·현재 결정에 우선하는 별도 정본이 아니다. 코드의 존재만으로 승인을 추정하지 않는다.

- PLAN: 조사·설계·제안. 제품 수정 권한을 추정하지 않는다.
- BUILD: 승인된 변경·검증·교정·정본 갱신을 이어간다.
- REVIEW: 진단·근거·판정. 수정은 별도로 승인된 범위가 있을 때만 한다.
- CLI의 모드는 스킬 선택 힌트이지 승인 상태가 아니다. 유효한 같은 범위 승인을 다시 요청하지 않는다.

## 선택과 실행

1. 현재 요청의 owner와 실제 consumer를 확인하고 필요한 스킬만 읽는다.
2. 기본 경로는 skills/SKILL_REGISTRY.json과 PROJECT_BASE_ADAPTER.json, 생성된 PROJECT_SKILL_SNAPSHOT.json이다. docs/base/SKILL_REGISTRY.json은 명시한 과거 호환 검사에만 사용한다.
3. 스킬은 게임 규칙을 고정하지 않는다. 각 전문 owner의 현재 요구사항·승인 상태를 입력으로 받는다.
4. 변경된 동작의 실패 사례를 먼저 검증하고 최소 수정 후 관련 회귀를 실행한다. 문구만 바뀌는 작업에 게임 전체 실행을 완료 의무로 만들지 않는다.
5. 채택한 Base 원문과 프로젝트 특화 차이는 [채택 기록](../docs/BASE_RULES_VERSION.md)으로 연결한다.

## 검토 예산과 종료

현재 채택한 Base 작업 정책에 따라 **같은 승인 계약 전체에서 full-scope 적대적 검토 2회**를 공유한다. PLAN/BUILD/REVIEW·PR·재개마다 2회를 다시 시작하지 않는다. 검토 기록과 대상 revision을 기존 작업 기록에 남긴다. 그 이후 발견은 영향 범위 교정과 관련 회귀로 처리한다. 병합 전 독립 검토는 작성자 자가 검토와 구분한다.

횟수를 채워 결함을 무시하지 않는다. 데이터 손실·보안·정본/저장 파괴·주요 기능/병합 오판 등 미해결 결함은 해당 의존 작업을 완료 처리하지 않는다. 독립 승인 작업은 계속할 수 있다. 최신 사용자가 별도 범위를 승인하면 그 범위를 따른다.

## 검증과 근거

DOC / MACHINE / RUNTIME / HUMAN / USER_APPROVAL / MERGE / RELEASE를 각각 기록한다. PASS는 실행한 해당 검사에만 붙이고, 미실행은 NOT_RUN, 실패는 FAILED다. 과거 근거는 같은 요구사항·revision 영향·환경·consumer의 유효성을 확인한 경우만 REUSED_EVIDENCE로 연결한다.

재미·효과·UI 변경은 기존 기능 ID에서 경험 원본 → 상태·규칙·표현 → 실제 consumer → 관찰/검증으로 연결한다. 자세한 방법과 프로젝트 연결은 채택 기록의 재미 검증 절을 선택해 읽는다. 기술 검사·AI 검토는 사람 경험 증거가 아니다.

## 교정·복구·보고

계약 검사 실패를 무시하거나 protected baseline을 옮겨 통과시키지 않는다. 실패 경로·영향을 읽기 전용으로 분류하고 승인된 운영 교정은 진행할 수 있다. 제품 경로 변경은 해당 승인 owner/범위 검사를 별도로 통과해야 한다.

완료 시 변경·이유·실제 검사·미검증·다음 행동만 간결하게 보고한다. 범위 밖 작업·다른 PR·실사용 저장·전역 설정은 보호한다.
